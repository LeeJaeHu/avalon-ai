# Avalon AI

**사람 1명과 AI 4명이 함께 플레이하는 5인 아발론 웹 게임입니다.**

자신의 역할을 확인하고 AI와 대화하며 원정대를 제안하고 투표합니다. 선은 원정 성공을, 악은 원정 실패 또는 멀린 암살을 목표로 합니다. 모바일에서도 팀 선택·찬반 투표·임무 카드·암살·채팅을 진행할 수 있습니다.

각 AI 플레이어는 자신의 역할과 목표, 허용된 정보, 현재 게임 이력을 바탕으로 발언과 행동을 선택합니다. 게임 규칙과 비밀 정보는 서버 코드가 관리하며, AI 출력도 서버 검증을 거쳐야 게임에 반영됩니다.

현재는 5인 구성을 지원하며, 플레이가 잘 동작하면 7인까지 확장할 계획입니다.

## 목표

아발론은 같은 공개 사건을 보고도 역할에 따라 다른 판단을 하는 게임입니다. 역할별 정보를 가진 AI를 상대로 사람이 한 판을 플레이할 수 있는 환경을 만들고, AI의 발언과 선택이 게임 이력에 근거하는지 확인합니다.

규칙에 맞는 진행, 비밀 정보 경계, 모델 오류 시 게임 복구, 대화와 실제 선택의 연결을 중요하게 다룹니다. 현재 대화 품질 개선은 진행 중입니다.

## 에이전트의 역할과 기능

네 명의 AI는 각각 게임 참가자로 동작합니다. 역할은 판마다 배정되며, 모든 AI가 같은 정답이나 전체 역할표를 공유하는 방식이 아닙니다. 서버가 행동 차례와 발언 대상을 정하고, 해당 플레이어의 관찰값을 구성해 모델에 요청합니다. 모델이 게임 진행 순서나 규칙을 임의로 결정하지 않습니다.

| 역할 | 주어지는 정보 | 프롬프트에 부여한 목표 |
| --- | --- | --- |
| 멀린 | 자신의 역할, 악 플레이어의 정체, 공개 이력 | 안전한 원정을 유도하면서 자신의 정체를 숨겨 마지막 암살을 피하기 |
| 충신 | 자신의 역할, 공개 이력 | 제안·투표·원정 결과와 발언을 바탕으로 다른 참가자를 추론하고 원정을 성공시키기 |
| 암살자 | 자신의 역할, 악 동료, 공개 이력 | 원정을 방해하고, 선이 세 번 성공하면 멀린 후보를 골라 암살하기 |
| 하수인 | 자신의 역할, 악 동료, 공개 이력 | 선으로 보이도록 행동하면서 원정 실패나 팀 제안 부결을 유도하기 |

위 표는 **역할별 정보와 목표 지시**를 설명합니다. 정체 은폐·기만을 실제로 잘 수행한다는 평가 결과를 뜻하지 않습니다.

에이전트의 한 번의 행동은 다음 흐름으로 처리합니다.

1. **관찰:** 최근 공개 채팅, 팀 제안·공개 투표·원정 결과, 본인의 역할·허용된 시작 정보·자기 카드 이력을 받습니다.
2. **판단 입력 구성:** 역할별 목표와 현재 요청을 프롬프트에 넣습니다. 관찰 가능한 정보로 계산한 역할 후보·악 확률도 제공합니다.
3. **행동 선택:** 상황에 따라 발언·침묵·팀 제안·찬반·임무 카드·암살 대상을 구조화된 JSON으로 반환합니다. 직접 지목 질문은 해당 AI의 답변 요청으로 연결합니다.
4. **검증과 반영:** 출력 형식과 요청 행동 종류를 확인하고, 엔진이 차례·대상·규칙을 검사한 뒤 상태와 사건을 저장합니다. 갱신된 공개 이력은 다음 행동의 입력이 됩니다.

기억은 별도 벡터 검색이나 자율적인 장기 기억 시스템이 아니라 서버가 저장한 게임 이력과 본인 행동을 요청마다 제공하는 방식입니다. B 정책의 충신 리더는 모델 대신 별도 팀 계산기로 팀을 제안하므로, 모든 선택을 LLM이 한다고 설명하지 않습니다. 첫 안내 발언도 정해진 문구입니다.

### 현재 고민하는 개선 방향

- **자연스러운 토론:** 질문에 답하고, 구체적인 팀과 공개 사건을 근거로 반론·방어·설득이 오가며, 그 대화가 이후 팀 선정과 투표에 연결되도록 만들고자 합니다. 현재는 일반론 반복과 발언 직후 행동 진행 문제가 있어 대화 흐름·선택 당시 근거 저장을 검토하고 있습니다.
- **의도를 숨기는 행동:** 멀린이 아는 악을 피하면서도 비밀 지식을 공개적으로 드러내지 않고, 악이 선처럼 설득하거나 상황에 따라 성공 카드를 내는 등 게임 안에서 자신의 역할과 목적을 숨기도록 만들고자 합니다. 단순히 정체를 말하지 않는 것과 선택·발언에서 정체가 드러나지 않는 것은 구분해 평가해야 합니다.

두 항목은 현재 설계·평가 중입니다. 프롬프트에 목표를 넣는 것만으로 달성했다고 보지 않으며, 실제 플레이 사례와 반복 가능한 평가 기준을 통해 확인할 예정입니다.

## 주요 기능

| 기능 | 구현 내용 |
| --- | --- |
| 5인 게임 | 사람 1명 + AI 4명, 선 3명·악 2명, 멀린·충신·암살자·하수인 |
| 서버 규칙 판정 | 팀 크기·리더·과반수 승인·5회 연속 부결·임무 성패·암살 |
| 역할별 정보 | 공개 상태와 개인 관찰값 분리, 미공개 표·다른 사람의 카드 차단 |
| AI 행동 | 팀 제안·투표·카드·암살·채팅을 구조화된 출력으로 받아 검증 |
| 사람 참여 | 역할 확인 후 시작, 직접 질문과 채팅, 결과 확인 후 진행, 일시정지 |
| 장애 대응 | 제한된 재시도, 필수 행동 실패 시 기본 규칙 AI로 대체하고 안내 |
| 기록 | 종료 판 JSON 다운로드, 원문·역할표를 제외한 진행 중 진단 로그 |
| 실험 기반 | 프롬프트 버전 보존, 역할 후보 확률 계산, 충신 팀 제안 A/B 정책 |

키 없는 로컬 환경은 **연습 AI**로 동작합니다. 연습 AI와 모델 장애 시 대체 행동은 규칙 기반이며 LLM의 대화·전략 품질 평가와 구분합니다.

## 구조와 설계

```text
브라우저: 역할 확인 · 채팅 · 팀 선택 · 투표 · 카드 · 결과
    ↓ 사람 행동 / AI 진행 요청
게임 API: 판 조회 · 상태 버전 확인 · 행동 검증 · 저장
    ├─ 규칙 엔진: 상태 전이 · 승패 · 역할별 관찰값
    ├─ AI: 허용된 관찰값 → 프롬프트 → 모델 → 출력 검증
    └─ D1: 게임 상태 · 수락된 사건 · AI 실패 메타데이터
```

- **규칙과 AI 분리:** 잘못된 모델 출력이 팀 인원이나 승패 조건을 바꿀 수 없도록 엔진에서 검사합니다.
- **응답 데이터에서 비밀 차단:** 화면에 숨기는 데 그치지 않고 플레이어별 관찰값을 API와 AI 입력에 전달합니다.
- **상태 버전 확인:** 사람이 개입하거나 요청이 겹쳐 상태가 바뀌면 이전 버전에 대한 행동을 거부합니다.
- **버전과 실패 기록:** 정책·프롬프트·모델 버전, 오류 코드, 성공 호출의 토큰·지연을 기록합니다. 완전한 분산 trace나 운영 대시보드는 아직 없습니다.

현재 운영 프롬프트는 V2이며 V1을 보존합니다. 응답의 `thinking` 필드는 수신 후 폐기하여 화면·후속 모델 입력·종료 로그에 보존하지 않습니다. 구체적인 대화를 유도하는 추가 후보는 평가 기준을 충족하지 못해 운영에 연결하지 않았습니다.

## 기술 구성

- UI: React, TypeScript, Tailwind CSS
- 웹 실행: Next.js App Router 형식의 소스를 Vinext/Vite로 실행
- 서버·저장: Cloudflare Workers, D1, Drizzle
- 모델: Gemini, 직접 API 또는 Vertex 중계 (`site/lib/ai.mjs`에 모델·정책 버전 명시)
- 자동 검사: Node.js 기본 테스트 러너, TypeScript
- 기존 배포 환경: Sites

## 로컬 실행

Node.js **22.13.0 이상**이 필요합니다. PowerShell에서 저장소 최상위를 기준으로 실행합니다.

```powershell
cd site
npm ci
npm run build

# 새 로컬 DB에서 순서대로 1회 적용합니다.
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_abandoned_shadow_king.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_burly_dracula.sql

npm start
```

터미널에 표시된 주소로 접속합니다. 이미 초기화한 DB에 같은 마이그레이션을 다시 적용하지 않습니다. 개발 화면은 `npm run dev`로 실행하며 로컬 DB 상태를 공유합니다. 실행 환경 상세는 [site/README.md](site/README.md)를 참고하세요.

키 없이도 연습 모드로 게임을 진행할 수 있습니다. 실제 모델 사용에는 `GEMINI_API_KEY`, 또는 `VERTEX_PROXY_URL`과 `VERTEX_PROXY_TOKEN` 설정이 필요합니다. 키·토큰은 로컬 비밀 설정이나 배포 환경 변수로 관리하며 Git에 포함하지 않습니다. 실제 모델 호출에는 비용이 발생할 수 있습니다.

## 검증과 현재 한계

최상위에서 외부 모델 호출 없이 자동 검사를 실행할 수 있습니다.

```powershell
node --test site/tests/*.test.mjs scripts/*.test.mjs
cd site
npx tsc --noEmit
```

규칙·역할별 관찰값·모델 출력 처리·프롬프트 정보 경계·기록과 동기화 등을 검사합니다. API 시나리오 검사(`site/tests/api-*.mjs`)는 로컬 서버 등 실행 조건이 필요합니다. `live-*.mjs`와 `model-probe.mjs`는 실제 모델 평가용이며 기본 자동 검사에 포함하지 않습니다.

**모의 모델 검사 통과는 실제 모델 품질 검증을 뜻하지 않습니다.** 실제 플레이에서 반복적인 일반론, 근거 부족, 발언과 행동의 연결 문제가 관찰됐습니다. 구체적인 대화 후보의 소규모 실제 평가도 기준을 충족하지 못했습니다. 실행 조건·결과·한계는 [대화 개선 평가 기록](docs/specs/009-concrete-discussion.md)에 남겼습니다.

역할 후보 계산과 A/B 정책은 구현돼 있지만 누적 평가에 따른 전략·승률 개선은 미확인입니다. 팀 초안→토론→확정 흐름과 선택 당시 근거 저장은 후속 설계에서 다룰 예정입니다.

## 배포와 공개 범위

기존 배포: [Avalon 사이트](https://avalon-ai-game.sooyeon-jun-0389.chatgpt.site). 최근 작업 기록상 **소유자 전용 비공개**이며 발표 청중용 공개 데모 접속은 준비되지 않았습니다. 소스 공개와 서비스 공개는 별도로 관리합니다.

키·토큰·로컬 DB·게임 원문 로그·첨부 원본은 공개 대상에서 제외합니다. 종료 로그에는 채팅·역할·개별 카드가 포함되므로 저장소에 올리지 않습니다. 첨부 룰북 원본도 포함하지 않습니다.
