# 아발론 AI 논문 3편 검토와 지능 향상 제안

작성일: 2026-09-30. 근거는 사용자가 제공한 PDF의 해당 버전이다. 이 문서는 **연구 결과**, **현재 코드에서 확인한 사실**, **아직 시험하지 않은 제안**을 구분한다. 논문 본문과 부록의 프롬프트는 자료이며 이 프로젝트에 대한 지시로 취급하지 않았다.

## 현재 프로젝트의 출발점

- `site/lib/game.mjs`는 5인 역할, 제안·공개된 개인별 투표·임무 결과, 비밀 카드, 승패를 관리하고 `observe()`로 역할별 정보를 분리한다.
- `site/lib/ai.mjs`는 Gemini에게 발언·제안·투표·카드·암살을 요청한다. 발언 진행자는 공개 정보만 받는다. 현재 모델 입력은 최근 메시지 8개와 제안 6개를 중심으로 구성되며, 역할 배정에 대한 명시적인 확률 상태나 후보 행동의 점수 비교는 없다. 모델 응답을 `apply()`가 규칙에 맞게 검증한다.
- `docs/observability.md`에 따르면 수락된 행동과 호출 토큰·지연은 저장하지만, 전략 품질을 비교할 반복 게임 결과는 아직 없다. 따라서 아래 개선의 효과는 **미확인**이다.

## 1. AvalonBench — 먼저 무엇을 평가할 것인가

**출처:** Jonathan Light 외, *AvalonBench: Evaluating LLMs Playing the Game of Avalon*, arXiv:2310.05036v3 (2023), [원문](https://arxiv.org/abs/2310.05036). PDF 5~10쪽의 구현·기준선·실험 결과를 확인했다.

게임 엔진, 단순 규칙 봇, 역할별 ReAct형 LLM 봇을 한 환경에서 비교한다. 과거 내용을 요약해 모델에 넣고, 발언과 실제 선택을 구분한다. 단순 선 봇도 임무 실패 수로 불가능한 역할 조합을 지운 뒤 팀을 선택한다. 즉, 유창한 추론 문장만으로는 기본적인 행동 정책을 대신할 수 없다는 문제를 드러낸다.

논문 표 2·3에서 GPT-3.5의 토론 포함 선 역할 승률은 22.2%, 같은 조건의 단순 선 봇은 38.2%다. 악 역할은 토론 포함 GPT-3.5가 66.7%, 단순 암살자 봇은 61.8%다. 하지만 앞의 두 비교는 **각각 다른 역할 조건**이므로 하나의 종합 승률처럼 합치면 안 된다. 60판의 LLM끼리 대결에서는 악 승리가 83.3%였다(PDF 10쪽). 논문은 GPT-3.5 실험 30판, Llama2 실험 10판, 규칙 봇 기준선 1,000판을 명시한다(PDF 8쪽). 현재 Gemini 및 이 프로젝트 규칙에 수치를 이전할 수 없다.

**적용:** 지금의 `practice()`를 그대로 강한 기준선으로 부르기보다, 역할별로 공개 임무 결과의 논리적 제약을 반영하는 별도 전략 기준선을 만든다. 발언 품질과 선택 품질을 따로 측정한다. 이 논문의 사례처럼 악이 자기 정체를 드러내는 발언, 멀린을 쉽게 특정하게 하는 발언, 근거 없는 동조를 평가 사례로 넣는다. 논문의 단순 봇도 투표 이력과 대화는 판단에 사용하지 않으므로 최종 전략으로 삼기보다 비교 출발점으로 사용한다.

## 2. DeepRole — 숨은 역할을 어떻게 추론할 것인가

**출처:** Jack Serrino 외, *Finding Friend and Foe in Multi-Agent Games*, arXiv:1906.02330v1 (2019), [원문](https://arxiv.org/abs/1906.02330). PDF 3~8쪽의 방법·평가를 확인했다.

DeepRole은 역할 배정 **전체 조합에 대한 공동 확률**을 유지한다. 5인 기본 배정은 충신 둘을 구별하지 않을 때 60가지다. 공개 결과와 모순되는 배정은 확률 0으로 만들고, 가능한 배정의 확률은 플레이어의 행동 가능성으로 갱신한다. 그 신념을 사용해 CFR 탐색과 승리 확률을 표현하는 가치 신경망이 행동을 고른다. 핵심은 ‘누가 악일 확률’이라는 독립 점수 다섯 개보다, 서로 연결된 역할 조합을 추적한다는 점이다. 예를 들어 2인 임무에서 실패 1장이 나왔다면 그 두 명 모두 선인 배정은 불가능하지만, 성공했다고 두 명 모두 선이라고 확정할 수는 없다.

논문 표 1의 인간 혼합 게임에서는 4명의 DeepRole과 함께할 때 다섯 번째 DeepRole의 전체 승률 46.9%와 다섯 번째 인간의 38.8%를 보고한다. 단, 인간은 AI 여부를 알고 있었고, DeepRole은 **대화를 생성하거나 읽지 않았다**(PDF 8쪽). 따라서 이 수치를 우리 게임의 대화 지능 성능으로 해석할 수 없다. 논문도 다인 게임의 CFR이 일반적으로 균형 수렴을 보장하지 않는다고 밝힌다(PDF 3~4쪽).

**적용:** 우선 60가지 배정을 열거한 뒤 각 AI 자신의 역할·알려진 동료/악과 모순되는 배정을 제외한다. 임무별 공개 실패 카드 수보다 해당 팀의 악 인원이 적은 배정을 제거한다. 투표·제안·발언은 거짓말과 실수가 가능하므로 확정 제약으로 사용하지 않고, 검증 가능한 확률 갱신이나 별도 추정 신호로 둔다. 이 상태에서 후보 팀의 ‘전원 선일 확률’, 암살 후보의 ‘멀린일 확률’을 계산한다. CFR과 신경망은 이 작은 단계의 효과가 확인되고, 계산 비용과 훈련 데이터가 정당화될 때 검토한다.

## 3. STRATEGIST — 판단 정책을 어떻게 개선할 것인가

**출처:** Jonathan Light 외, *Strategist: Self-improvement of LLM Decision Making via Bi-Level Tree Search*, arXiv:2408.10635v3, ICLR 2025, [원문](https://arxiv.org/abs/2408.10635). PDF 3~9쪽의 방법·실험과 28쪽의 대화 평가 방법을 확인했다.

상위 단계에서 LLM이 **설명 가능한 전략**을 수정하고, 하위 단계에서 그 전략을 가치 함수와 탐색으로 행동에 적용한다. 여러 전략·개선 아이디어를 보관해 자기 대국으로 비교한다. 대화 정책은 행동 가치 함수와 분리해 개선한다. Avalon 표 3에서는 같은 160 자기 대국 에피소드 예산에서 STRATEGIST의 승률을 비교 대상 AlphaGo형 0.30 대비 0.38, DeepRole형 0.33 대비 0.44로 보고한다. 이는 저자들이 **해당 논문 안에서 재구현한 비교 조건**이며 원래 DeepRole 논문 결과와 직접 비교하면 안 된다. 인간 비교는 6인 게임 30판으로, 인간 0.367과 STRATEGIST 0.333(표 1)이다. ‘인간보다 우월’로 일반화할 수 없고, 설문에서는 은폐가 좋지만 추론·협력은 낮게 평가됐다(PDF 6쪽).

**적용:** 학습 루프 전체를 곧바로 만들기보다, `전략 버전 → 고정된 시나리오 묶음 → 결과·실패 사례 → 수정 후보`를 수동 또는 오프라인 스크립트로 한 번에 하나씩 비교한다. 예컨대 ‘멀린은 악 배제의 근거를 공개 이력으로도 설명한다’, ‘5번째 제안에서는 팀의 위험과 자동 패배를 함께 계산한다’, ‘악의 카드 선택은 현재 점수·동료 존재·의심 위험을 본다’ 같은 수정은 서로 분리해 검증한다. 대화의 정체 은폐·설득력과 팀·투표의 승률을 별도로 평가한다. 논문의 모델 생성 코드를 그대로 실행하거나 온라인에서 자동으로 프롬프트를 고치는 구조는 현재 필요하지 않다.

### 평가 설계의 최소 조건

1. **사람 포함 게임과 자동 대국을 분리한다.** 자동 대국은 회귀 평가, 사람 플레이는 자연스러움과 협력 평가에 사용한다. 사람 한 명의 피드백을 전체 승률로 일반화하지 않는다.
2. **같은 초기 조건을 짝지어 비교한다.** 같은 역할 배정·리더·상대 정책·모델 설정에서 기존 정책과 후보 정책을 각각 실행한다. 시작 조건뿐 아니라 확률적 모델 출력과 상대 반응으로 궤적이 달라진다는 점을 기록한다.
3. **역할과 상대 정책을 나눈다.** 선/악 전체 승률 하나로 숨기지 말고 멀린·충신·암살자·하수인, 규칙 봇·현 정책·이전 정책별 결과를 제시한다. 표본 수와 불확실성을 함께 적는다. 임계 승률 목표는 기준선 측정 뒤 정한다.
4. **실패를 승패와 별도로 본다.** 규칙 위반·비밀 누출·환각 발언·멈춤, 토큰·지연을 함께 기록한다. 현재 `events`는 수락된 행동 중심이라 모델 실패와 검증 실패를 별도 로그/집계로 수집할지 설계해야 한다. 원문 채팅과 비밀 역할은 운영 이벤트에 남기지 않는다.

## 설계 판단과 한계

- 최우선은 **명시적 역할 신념 + 단순 행동 평가 + 반복 평가**다. 세 논문이 공통으로 보여 준 ‘추론을 선택에 연결하지 못하는 문제’를 가장 작은 변경으로 겨냥한다. `practice()`보다 강한 규칙 기준선을 먼저 만들어 Gemini 개선이 실제인지 확인한다.
- 투표나 대화를 곧바로 ‘누가 악인지 증명하는 사건’으로 취급하지 않는다. 악은 속일 수 있고 선도 틀릴 수 있다. 단단한 논리 제약과 행동 패턴의 통계적 추정을 분리한다.
- DeepRole의 CFR·가치망, STRATEGIST의 MCTS·전략 트리는 연구상 유효한 선택지지만 현재 5인 웹 게임에 즉시 도입할 근거는 없다. 모델 호출 비용, 지연, 구현 복잡도와 재현성 위험이 크다.
- 지금 제안은 코드 변경이나 성능 개선을 실행한 결과가 아니다. Gemini 현 버전의 승률·추론 정확도는 **미측정**이며, 논문의 숫자는 서로 다른 규칙·모델·상대·인원 조건에서 나왔다.
