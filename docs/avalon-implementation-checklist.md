# AI 아발론 구현 체크리스트

상태: 2026-09-29 구현 중. 완료 표시에는 코드·검사 근거를 함께 적는다. 설계 근거는 `avalon-PRD.md`, `specs/003-avalon-agent-prompts.md`, 탐색 결과는 `../playtests/avalon-quest-card-probe-2026-09-29.md`에 있다.

## 2026-09-30 후속 작업 순서와 완료 기준

이 절은 앞으로의 우선순위다. 아래 기존 체크 항목은 작성 당시 상태가 섞여 있어, 완료 여부를 코드·검사·실제 플레이 근거로 다시 대조하기 전까지 일괄 완료로 해석하지 않는다.

1. **게임 기능 작동 확인:** 규칙·비밀 정보·API 자동 검사 후, 배포 화면에서 사람과 실제 AI가 한 판을 끝까지 진행한다. 팀 제안→다섯 명 투표→원정 카드→결과→종료/암살과 오류·재시도를 기록하고, 역할별 필수 경로와 정보 공개 시점을 확인한다. 배포 실제 모델 판 1건의 `ENDED` 저장과 사건 기록은 확인했다(`../작업일지.md` 2026-09-30 종료 판 항목). 사용자가 악 승리를 확인했으며, 전체 화면 경로·비밀 공개 시점과 다른 역할 경로는 추가 확인이 필요하다.
2. **악 추정 모델 개선:** 현재 고정 계수와 규칙만 적용한 기준을 보존한다. 종료 판에서 계수를 학습하고, 판 ID로 분리한 보류 판의 동일 공개 시점에서 Brier 점수·로그 손실·확률 보정을 비교한다. 실제 역할표는 학습 정답과 평가 채점에만 쓰고 진행 중 추론 입력에는 넣지 않는다. 설계는 `specs/005-belief-learning-experiment.md`에 있으며 학습·점수 측정은 미실시다.
3. **AI 성능 개선:** 확률모형 버전을 고정한 뒤 발언·제안·투표·카드 선택 정책을 한 가지씩 변경한다. 같은 초기 역할·리더·사람 입력 시나리오에서 정책 전후를 반복 비교하고, 역할별 승률 외에 무효 행동, 질문 응답·근거 오류, 승리 기회 누락, 호출 실패·토큰·지연을 본다. 변경 효과가 재현되기 전에는 전략 개선으로 쓰지 않는다.

각 단계는 `문제와 기준선 → 선택한 변경과 대안 → 정책/모형 버전·코드 → 동일 조건 검사 → 실제 관찰 결과와 한계` 순서로 `../작업일지.md`에 근거 경로를 남긴다. `events`·`ai_failures`는 실행 기록이며 일지는 그 기록의 해석과 의사결정 근거다. 현재 사건 연결은 `game_id → version` 수준이므로 모델 호출·검증·상태 전이를 단계별로 재구성하는 trace와 반복 평가 결과 저장은 후속 보강 대상이다.

## 사용 방법

- 완료한 항목만 `[x]`로 바꾸고, 같은 줄이나 바로 아래에 **코드 경로·검사 명령·결과**를 적는다. 설계만 끝난 항목은 구현 완료로 표시하지 않는다.
- 단계 끝에서는 자동 검사와 실제 화면 확인을 구분해 `../작업일지.md`에 기록한다. 실패나 미확인 사항도 남긴다.
- 범위는 사람 1명·AI 4명의 5인 기본판이다. 추가 역할, 다인 접속, 새 프레임워크는 이 체크리스트의 완료 조건이 아니다.

## 2. 비밀 정보와 공개 이력

- [ ] `observePlayer(id)`와 진행자·브라우저용 공개 관찰값을 나눈다. 일반 충신·진행자에는 악/멀린의 정체가 없고, 멀린·악에게만 룰북상 허용된 시작 정보를 준다.
- [ ] 제안마다 `proposal_id`, 임무/시도 번호, 리더, 팀원 ID를 구조화된 사건으로 보존한다.
- [ ] 개인별 팀 찬반은 전원 제출 전 비공개로 두고, 제출 뒤 찬반·합계·결과를 공개 이력과 화면에 함께 반영한다.
- [ ] 임무 결과는 팀·실패 카드 수·성패로 공개한다. 카드별 제출자는 다른 플레이어와 공개 응답에서 숨긴다.
- [ ] AI에게 자기의 과거 비공개 행동만 제공하고, 다른 사람의 미공개 표·임무 카드가 입력/응답/로그에 섞이지 않도록 검사한다.
- [ ] 제안 여러 번, 임무 여러 번이 지나도 공개 사건 ID가 유지되고 AI의 근거 ID가 실제 사건에 연결되는지 확인한다.

**단계 확인:** 역할별 관찰값 및 API 응답 자동 검사에서 비밀 누출이 없고, 화면에서는 제안·공개 투표·임무 결과를 순서대로 다시 볼 수 있다.

## 3. AI 행동 계약과 필수 행동

- [ ] 공통 지침 + 자기 역할 + 독립된 성격 + 현재 관찰 + 요청 행동을 조합한다. 다른 역할의 지침/비밀은 넣지 않는다.
- [ ] 네 AI 성격을 역할 배정과 독립적으로 부여한다. 같은 말투가 특정 역할을 드러내는 고정 대사가 되지 않게 한다.
- [ ] `PROPOSE_TEAM`, `TEAM_VOTE`, `QUEST_CARD`, `ASSASSINATE`의 JSON 출력과 허용 대상·단계·중복을 검증한다.
- [ ] 모델 오류/시간 초과/무효 JSON은 제한적으로 재시도하고 사용자에게 대기·재시도 상태를 보여준다. 임의 표나 임무 카드를 조용히 대신 제출하지 않는다.
- [ ] 사람의 팀 제안·표·임무 카드·암살 선택을 AI가 대신하지 않는다.
- [ ] 악 임무 카드 입력에 점수, 즉시 승패 가능성, 공개 의심 이력, 아는 악 동료의 팀 포함 여부를 주고, 다른 사람의 미공개 카드는 주지 않는다.
- [ ] 악 AI 두 명이 같은 팀인 상황에서 공동 실패 담당 원칙을 쓸지 반복 실험으로 결정한다. 실패 카드 2장·모두 성공·즉시 승리 누락을 측정하고 사람 악 팀원의 선택권을 유지한다.

**단계 확인:** 가짜 모델로 모든 필수 행동이 유효하게 적용되며, 실제 모델의 고정 시나리오에서 오류 처리와 악의 카드 선택을 재현할 수 있다.

## 4. 채팅과 사람 참여

- [ ] 현재 마피아의 사건→진행자→플레이어 발언→서버 저장→화면 갱신 흐름을 아발론의 토론 단계에 맞춘다.
- [ ] 진행자는 공개 정보만 보고 `SPEAK|WAIT`를 고른다. 지목 질문에는 해당 AI의 직접 답변 기회를 먼저 준다.
- [ ] 최근 채팅 원문과 관련된 과거 발언, 제안·공개 투표·임무 결과를 AI 문맥에 넣는다. 서버 사건을 모델이 생성한 요약으로 대체하지 않는다.
- [ ] 악 AI가 자기 비공개 카드와 공개 결과를 구분해 이후 대화·제안·찬반에 반영한다. 없는 발언·투표를 근거로 만들지 않는다.
- [ ] 사람이 새로 입력하면 이전 상태에서 생성된 AI 발언은 게시하지 않는다. 같은 침묵 상태의 `WAIT`를 반복 호출하지 않는다.
- [ ] AI 연속 발언·응답 간격은 실제 채팅을 보고 조정한다. 기존 마피아의 5회·1초를 검증 없이 고정하지 않는다.
- [ ] 모바일 화면에서 역할 확인, 팀 선택, 찬반, 임무 카드, 암살, 채팅, 이력 열람을 직접 조작해 본다.

**단계 확인:** 사람이 한 판의 모든 필수 행동을 할 수 있고, AI가 질문·원정 이력에 근거해 답하며 토론이 막히거나 끝없이 반복되지 않는다.

## 5. 끝까지 플레이하고 기록하기

- [ ] 사람 역할이 멀린·충신·암살자·하수인인 경로를 가짜 모델로 각각 확인한다.
- [ ] 실제 모델과 사람이 함께 적어도 한 판을 끝까지 플레이하고, 승패·비밀 공개 시점·화면 동작을 기록한다. 한 판만으로 자연스러움이나 전략 품질을 확정하지 않는다.
- [ ] 같은 역할·공개 사건·사람 입력을 고정한 반복 시나리오에서 직접 질문 응답, 근거 ID 유효성, 같은 주장 반복, 악의 중복 실패, 승리 기회 누락을 비교한다.
- [ ] 호출·토큰·지연·실패·재시도·판 완주를 집계하고, `game_id → event_id → model_call → validation → state_transition` 흐름을 추적할 수 있게 한다. 로그에는 API 키, 비밀 역할표, 개인 대화 원문을 기본으로 넣지 않는다.
- [ ] 구현·검사·사용자 확인·남은 위험을 `../작업일지.md`에 근거 경로와 함께 적는다. 배포한다면 실제 배포 상태와 접속·플레이 확인 범위를 따로 기록한다.

**최종 확인:** 규칙과 정보 경계 자동 검사, 모델 있는 실제 완주 기록, AI 품질의 재현 가능한 비교가 각각 구분되어 있다. 미확인 품질을 성공으로 표시하지 않는다.
