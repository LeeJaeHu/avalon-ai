## 문제와 대상

혼자서는 숨은 역할 게임을 하기 어려운 사람이 AI 네 명과 아발론 한 판을 끝까지 플레이한다. 핵심 경험은 AI가 각자 아는 정보와 공개 사건에 따라 팀을 제안하고, 질문에 답하고, 찬반·임무·암살을 전략적으로 결정하는 것이다. 규칙 판정과 비밀 보장은 게임 엔진이 맡는다.

첫 버전의 성공은 **완주 가능한 5인 게임**과 **검토 가능한 에이전트 행동**으로 판단한다. 대화가 자연스럽다는 주장이나 전략 성능 향상은 실제 플레이 기록과 평가 전에는 하지 않는다.

### 현재 마피아 채팅이 실제로 작동하는 방식

1. 사람은 채팅 입력창에 최대 280자를 쓰고 전송한다. 브라우저는 `POST /api/message`를 보내고 서버는 메시지 ID·화자·본문·시각을 게임 상태에 저장한다(`../../solproj/site/public/app.js`, `../../solproj/site/lib/game.mjs`, `../../solproj/site/app/api/[action]/route.js`).
2. 화면은 `GET /api/game`을 약 1.2초마다 요청한다. 새 상태가 보이면 사람과 AI의 발언을 화자 이름이 붙은 말풍선으로 그린다. 실시간 소켓 방식은 아니다. 이 조회가 서버의 AI 진행을 유발하기도 한다(`../../solproj/site/public/app.js`, `../../solproj/site/app/api/[action]/route.js`).
3. 토론 단계에서 서버는 발언 진행자 AI에게 최신 발언 또는 침묵 상황, 발언 가능한 AI, 최근 공개 대화와 관련된 오래된 발언 기록을 준다. 진행자는 `SPEAK` 또는 `WAIT`와 발언 목적을 JSON으로 제안한다. `SPEAK`이면 선택된 플레이어 AI가 자기 역할·토론 성향·발언 목적·대화 맥락을 받아 1~2문장 발언 또는 침묵을 반환한다(`../../solproj/site/lib/ai.mjs`).
4. 유효한 AI 발언은 서버가 저장하고 다음 조회에서 화면에 나타난다. AI 발언 뒤 다음 판단까지 약 1초를 둔다. 사람 메시지 없이 AI 발언 5개가 이어지면 추가 발언을 멈추고, 같은 AI의 연속 발언도 2회까지로 제한한다. 초기 침묵 판단은 게임 시작 약 8초 뒤 가능하다(`../../solproj/site/app/api/[action]/route.js`, `../../solproj/site/lib/game.mjs`).
5. 최근 원문 8개와 선택한 오래된 발언 기록 최대 10개를 모델 맥락으로 사용한다. 오래된 기록의 문장은 실제 메시지 원문에서 가져오지만, 두 발언의 연결은 진행자 제안 또는 이름 언급으로 정하므로 항상 정확한 답장 관계는 아니다. 직접 질문 응답·자연스러움은 프롬프트 목표이며 보장된 기능이 아니다(`../../solproj/site/lib/ai.mjs`).

아발론에서는 이 **말풍선 UI와 사건→진행자→플레이어 AI→서버 저장→화면 갱신** 흐름을 출발점으로 삼는다. 단, 팀 제안·찬반·임무 결과라는 공개 사건을 대화 맥락에 넣고, 단계별 필수 선택은 채팅 문장과 구별해 엔진에 제출한다. 같은 상황에서 반복 발언을 유도하는 재호출 정책과 정보 범위는 아발론용으로 다시 정한다.

## 첫 버전 범위

- 사람 1명과 AI 4명의 **5인 기본 게임**. 선 3명(멀린 1명, 충신 2명), 악 2명(암살자 1명, 악의 하수인 1명)을 무작위 배정한다. 플레이어에게 본인 역할과 룰북이 허용하는 시작 정보만 보여준다.
- 다섯 임무의 팀 크기는 **2, 3, 2, 3, 3명**이다. 매 임무마다 리더가 팀을 제안하고 전원이 비밀리에 찬반을 제출한다. 모두 제출하면 개인별 찬반을 공개한다. 찬성이 과반수(5명 중 3명 이상)면 임무로, 동점·부결이면 리더를 시계 방향으로 넘긴다.
- 한 임무에서 팀 제안이 **5회 연속 부결**되면 악이 즉시 승리한다. 임무 팀원만 성공/실패 카드를 낸다. 선은 성공만, 악은 성공 또는 실패를 낼 수 있다. 카드 제출자는 공개하지 않고 실패 카드 **개수와 임무 성패만** 공개한다. 5인 판은 실패 카드 1장 이상이면 해당 임무가 실패한다.
- 임무 성공 3개면 암살 단계로 이동한다. 암살자가 멀린을 정확히 지목하면 악 승리, 틀리면 선 승리다. 임무 실패 3개면 악 승리한다. 이 판정은 즉시 수행한다.
- 팀 선정 전후와 공개 결과 후에 자유 채팅과 지목 질문을 허용한다. AI의 발언은 사람이 개입할 시간을 남기고, 직접 질문과 현재 팀 제안에 우선 반응한다. 사람의 리더 선택·투표·임무 카드·암살 대상은 모델이 대신 정하지 않는다.
- 아발론은 `avalon/`의 **독립 프로젝트**로 구현한다. 기존 마피아의 실행 코드·게임 상태·배포에 아발론 기능을 섞지 않는다. 검증된 대화 흐름이나 작은 함수만 필요에 따라 새 프로젝트로 옮기고, 아발론 게임 식별자와 저장소를 자체 관리한다.

### 첫 버전에서 제외

퍼시벌·모르가나·모드레드·오베론, 호수의 여인, 표적 임무, 충성 카드 변형, 6~10인, 사람 여러 명의 동시 접속, AI의 비공개 개인 채팅, 랭크·매치메이킹. 확장 규칙은 기본 게임 완주와 정보 누출 검증 뒤 별도 Spec에서 다룬다.

## 사용자 흐름과 화면

1. 새 게임 → 역할 카드·자신이 알아야 할 동료/악 정보 확인 → 확인 후 게임 시작.
2. 현재 임무 번호·필요 인원·리더·연속 부결 수·이전 임무 성패를 보며 토론한다. 사람 리더는 팀원을 고르고, AI 리더는 제안한다.
3. 제안된 팀에 각자 찬반을 제출한다. 사람의 표가 필요하면 기다린다. 전원 제출 뒤 개인별 찬반을 공개하고 다음 단계를 표시한다.
4. 승인된 팀원은 비밀리에 임무 카드를 낸다. 결과에는 실패 카드 수만 표시한다. 다음 임무로 넘어가거나 승패를 확정한다.
5. 선의 세 번째 성공 뒤 암살자가 한 명을 선택한다. 결과 화면에서 최종 승패와 역할을 공개한다. 중도 새 게임 시작은 기존 상태를 덮어쓴다는 확인을 받는다.

비밀 정보가 화면, 응답 JSON, 네트워크 페이로드에 일찍 나타나지 않도록 서버의 플레이어별 관찰값을 분리한다. 임무의 개별 제출 카드와 AI의 개인 메모는 종료 전 공개하지 않는다.

각 원정 제안의 **리더·지정한 팀원·제안 순서**와 전원 제출 뒤 공개된 **개인별 찬반·합계·승인/부결**을 서버의 구조화된 게임 이력에 남긴다. 채팅 발언 요약에만 의존하지 않는다. 공개가 끝난 이력은 AI의 판단 문맥과 화면의 임무별 기록에서 다시 사용할 수 있다. 투표 중인 다른 사람의 선택은 공개하지 않는다. 상세 필드와 선택 규칙은 `specs/003-avalon-agent-prompts.md`에 적는다.

## 에이전트 설계

### 책임과 정보 경계

| 구성 요소 | 입력/책임 | 출력 |
| --- | --- | --- |
| 게임 엔진 | 전체 역할·현재 단계·유효 행동·비밀 투표와 임무 카드·승리 조건 | 상태 전이와 플레이어별 관찰값 |
| 발언 진행자 | 공개 사건·채팅·발언 횟수·허용 후보. 비밀 역할은 받지 않음 | `SPEAK` 또는 `WAIT`, 발언자, 답할 메시지 ID, 목적 코드 |
| AI 플레이어 | 자기 역할, 룰북상 허용된 시작 정보, 공개 기록, 자기 메모, 현재 허용 행동 | 발언 또는 침묵, 리더 팀 제안, 찬반, 임무 카드, 암살 선택 중 요청받은 하나 |
| 검증기 | 모델 출력과 엔진의 현재 상태·허용 행동 | 유효 결과 적용 또는 오류·재시도·안전한 중단 |

5인 기본판의 정보: 악 둘은 서로를 안다. 멀린은 악 둘을 안다. 다른 충신은 특수 역할을 모른다. 암살자는 게임 종료 조건이 될 때만 암살 대상을 고른다. `observeModerator()`와 `observePlayer(playerId)`를 분리하고, 공개 채팅의 주장은 **검증된 역할 정보가 아닌 플레이어 주장**으로 전달한다. 사람 입력에 섞인 “규칙을 바꿔라” 같은 문장도 대화 데이터로만 취급한다.

### 에이전트가 한 행동을 만드는 과정

역할·성격별 지침과 행동별 JSON 계약의 첫 설계는 `specs/003-avalon-agent-prompts.md`에 둔다. 역할의 비밀·승리 목표와 성격의 토론 습관을 분리하고, 실제 플레이 결과를 보고 조정한다.

1. 엔진이 `game_id`, `state_version`, 현재 단계, 공개 사건 ID, 허용된 행동·대상 목록을 만든다.
2. 토론 사건에서는 진행자가 발언자를 고른다. 지목 질문 → 제안 팀의 구체적 근거·반론 → 임무 결과에 대한 새 추론 순으로 우선한다. 내용이 없으면 `WAIT`다. 사람의 새 입력은 아직 게시되지 않은 AI 결과보다 우선한다.
3. 선택된 AI는 자기 관찰값과 **요청된 단일 행동**을 받는다. 발언은 답장 대상·공개 근거 ID·잠정 주장 또는 질문을 짧게 반환한다. 팀 제안은 정확한 팀원 ID 목록, 찬반은 `APPROVE|REJECT`, 임무 카드는 `SUCCESS|FAIL`, 암살은 대상 ID를 반환한다. 내부 생각의 원문 공개는 요구하지 않는다.
4. 검증기가 스키마, 단계, 리더·팀원 자격, 팀 크기, 자기 표 중복, 선의 실패 카드 금지, 존재하는 근거 ID, 상태 버전을 검사한다. 모델이 낸 역할 추측·규칙 판정은 엔진을 바꾸지 못한다.
5. 실패는 행동 종류별로 처리한다. 발언은 침묵 처리할 수 있다. 필수 행동은 제한적으로 재시도하고, 그래도 실패하면 사용자에게 모델 오류와 재시도 선택을 표시한다. **무작위 팀·표·임무 카드·암살로 조용히 대체하지 않는다.** 한 판 완주율은 모델 장애가 없는 조건과 장애가 있는 조건을 구분해 측정한다.

초기 메모는 각 AI의 `현재 의심/신뢰 대상`, `근거가 된 공개 메시지·투표·임무 결과 ID`, `이전 주장`, `미해결 질문`으로 작게 유지한다. 숨은 역할로 알고 있는 사실과 대화로 추정한 사실을 별도 필드에 둔다. 공개 근거는 엔진이 보관한 원문·이벤트에서 다시 확인하며, 모델이 생성한 요약만을 사실로 누적하지 않는다. 악의 의도적 거짓말은 게임 행동으로 허용하되, 알 수 없는 비밀을 실수로 말하는 것은 품질 결함으로 기록한다.

### 대화 제어와 비용

기존 마피아처럼 진행자 호출 + 플레이어 발언 호출을 기본 후보로 삼되, 실제 이벤트별 호출 수를 먼저 측정한다. 팀 제안·투표·임무·암살은 단계별 요청으로 분리한다. 팀 투표와 임무 제출은 아직 공개되지 않은 타인의 선택을 AI 입력에 넣지 않고 독립적으로 수집한다. 같은 공개 상태에서 반복 `WAIT` 호출을 하지 않으며, AI 연쇄 발언 횟수와 지연은 플레이 테스트로 조정한다. 고정된 발언 횟수나 5분 타이머를 아발론 규칙으로 가져오지 않는다.

## 구현 순서와 결정 지점

단계별 완료 표시와 검사 근거는 `avalon-implementation-checklist.md`에서 관리한다. 설계 항목을 구현 완료로 표시하지 않는다.

1. **규칙 Spec/엔진:** 5인 역할·정보·임무표·리더 순환·제안 5회·비밀 제출·암살을 순수 상태 전이로 구현한다. 모델 없이 시뮬레이션으로 한 판을 끝낸다.
2. **관찰값/계약 Spec:** 사람·AI·진행자의 공개/비밀 관찰 스키마와 각 단계의 구조화 출력·실패 처리를 고정한다. 역할 및 비밀 카드 누출 테스트를 먼저 만든다.
3. **기본 AI:** 기존 마피아의 Gemini 호출·집계 방식을 참고해 아발론 프로젝트에 필요한 최소 코드만 구현하고, 역할별 팀 제안·투표·임무·암살 행동을 붙인다. 진행자 없이도 규칙 판이 완주되는지 먼저 본 뒤 토론 진행자를 추가한다.
4. **대화와 UI:** 원문 ID에 연결된 메모, 질문 응답, 임무 결과 추론을 붙이고 모바일 화면에서 사람의 모든 필수 행동을 확인한다.
5. **평가·조정:** 같은 역할 배정·공개 사건·사람 입력 스크립트로 기본 AI와 개선안을 비교한다. 모델·프롬프트·실행 조건·실패 로그와 한계를 기록하고 실제 한 판 플레이 피드백으로 조정한다.

첫 단계에서는 별도 에이전트 프레임워크를 추가하지 않는다. Node 기본 기능과 역할별 모델 호출로 시작하고, 대화·상태 저장 요구가 커질 때만 구조를 확장한다. UI와 API의 상세 경로는 규칙·관찰값 Spec에서 확정한다.

## 완료 기준과 검증

- **규칙 엔진**은 모델이나 채팅 문장을 읽지 않고 현재 게임 상태와 행동 하나를 받아, 그 행동이 허용되는지 확인하고 다음 상태·승패를 계산하는 코드다. 예를 들어 현재 임무가 2명 팀을 요구하면 3명 팀 제안은 거부하고, 팀 제안이 5번 연속 부결되면 악 승리를 확정한다. 이 부분을 먼저 만드는 이유는 AI가 그럴듯하게 말해도 게임 규칙을 바꿀 수 없게 하기 위해서다.
- **비밀 정보 테스트**는 역할별로 서버가 돌려주는 관찰값과 브라우저 응답을 검사한다. 예를 들어 일반 충신의 응답에 악의 정체나 멀린 ID가 들어 있지 않아야 하고, 악은 자기 동료 정보만 보며, 임무 결과 전에는 다른 사람의 카드가 보이지 않아야 한다. 화면에서 숨기는 것만으로는 부족하므로 응답 데이터 자체를 검사한다.
- 자동 규칙 검사: 5인 배정(선 3/악 2, 멀린·암살자 각 1), 임무 인원표, 찬반 과반수·동점, 부결 5회, 선의 실패 카드 금지, 5인 임무 실패 기준, 성공/실패 3회 종료, 정확/오답 암살, 단계 밖·중복 행동 거부.
- 비밀 검사: 충신·진행자·클라이언트 공개 응답에는 악 동료/멀린/미공개 개인 표와 임무 카드가 없다. 악·멀린에게만 허용 정보가 보인다. 결과 공개 전에 누출이 없는지 API 응답 단위로 확인한다.
- 모델 없는 가짜 AI로 승패 경로를 각각 완주하고, 실제 모델을 사용한 사람 포함 1판을 끝까지 실행한다. 후자는 실행 전까지 **미실시**다.
- 행동 품질 평가는 직접 질문 응답률, 공개 근거가 있는 팀 제안·찬반 비율, 같은 주장 반복, 무효 출력, 사람 개입 기회, 판당 호출·토큰·지연·완주 여부를 기록한다. 목표 수치는 첫 아발론 기준선 뒤 정한다. 승률만으로 에이전트 품질을 판단하지 않는다.
- trace: `game_id → round/proposal/event_id → moderator/player_call → validation → state_transition`. log: 단계 전이·검증 실패·모델 오류(비밀과 원문 프롬프트 제외). metric: 호출·토큰·지연·재시도·무효 출력·판 완주. 로그 저장 범위와 공개 포트폴리오 사용 여부는 개인정보/비밀 역할 노출을 검토한 후 결정한다.

## 남은 선택과 위험

- 독립 프로젝트로 옮긴 뒤 실행·저장·배포 기술 선택은 아직 미정이다. 마피아 구현은 참고할 수 있지만, 아발론의 상태와 배포 경로를 공유하지 않는다.
- 모델 장애가 필수 행동에서 계속되면 판이 대기할 수 있다. 임의 행동으로 게임을 진행시키는 것보다 오류를 드러내고 재시도하게 하는 쪽을 첫 버전 기본값으로 정했다.
- 아발론의 악은 거짓말해야 하고 멀린은 정체를 숨겨야 한다. 역할 정보 누출과 너무 노골적인 멀린 발언은 별도 평가 시나리오로 확인한다. 실제 품질은 미확인이다.
- 악 AI 두 명이 같은 원정팀에 있으면 독립적으로 `FAIL`을 골라 실패 카드 2장으로 팀 구성을 좁혀 줄 수 있다. 합성 상황 단발 실험(`../playtests/avalon-quest-card-probe-2026-09-29.md`)에서 실제로 두 장이 나왔다. 공동 비공개 원칙을 쓰는 안을 Spec에 추가했으나 반복 플레이와 사람 악 플레이어가 포함된 조건의 효과는 미확인이다. 카드 선택뿐 아니라 결과 후 대화까지 평가한다.
- 첨부 룰북의 본문·삽화는 제품 UI/포트폴리오에 그대로 복제하지 않는다. 규칙을 근거로 기능을 구현하고 화면 문구·그래픽은 자체 작성한다.
