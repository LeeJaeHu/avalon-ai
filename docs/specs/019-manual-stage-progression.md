# 수동 단계 이동 (2026-10-06)

사용자 요청: 수정한 v3.txt를 반영하고 JEV 자동 이동을 항상 보이는 사용자 버튼으로 교체한다. AI 발언자·발언 목적은 JEV가 정한다. 대화 및 준비 중, 투표·임무 카드·암살 선택 중에는 이동할 수 없다.

구현 기준:
- 기존/신규 판과 기존 방식/JEV 모두 수동 이동. 과거 자동 정책은 테스트/비교용 코드에서만 보존.
- 채팅 입력 위 결과/행동 영역 오른쪽에 고정된 버튼, 단계별 이름과 비활성 이유. 자동 예고·카운트다운·읽기 자동정지 제거. 수동 전체 일시정지는 유지.
- 토론 묶음은 최대 3발언에서 종료, 새 사람 발언으로 재개. 결과가 공개되면 토론을 즉시 한 묶음 시작하고 완료 후 사용자 이동 대기. AI가 기다리는 중 시간 기반 재호출 없음.
- 입력 중/미공유 팀 수정/미답변·예약된 AI 응답/리더 재검토 중 이동 차단. 서버에도 합법 전이와 미완료 응답 경계 적용. 상태 버전 충돌 시 이동 재시도하지 않는다.
- 기존 저장 예고는 새 정책에서 무시하고 읽기 자동정지 상태는 풀어준다. 일반 수동 일시정지는 유지.
- 사용자 v3.txt 원문을 보존하고 빌드 동기화한다. V3 최근 채팅20·본인 생각 입력·종료 로그 경계 유지. 실제 모델 품질 평가는 이번 작업에서 미실시.

자동 검증/통과 기준(구현 전):
1. 시간이 아무리 지나도 START_VOTE/CONTINUE/예고 생성 없음; JEV payload에 progress 질문 없음.
2. 준비된 토론/결과에서 버튼 이동 성공. pending 응답/재검토/중복/잘못된 행위자/투표·카드 도중 실패.
3. 3발언 상한, WAIT·모델 장애 뒤 묶음 종료; 새 사람 질문은 반드시 답변 경로. 결과 공개→즉시 토론→대기 검증.
4. 모의 공급자로 사용자 단계 버튼 및 선택만 받아 전체 판 완료. 숨은 표/카드/생각 공개 경계 유지.
5. 기존 회귀, 사용자 V3 원문·thinking 경계 검사, TypeScript, Worker 빌드 모두 통과. 키 없는 로컬 화면에서 버튼 위치·비활성 사유·클릭 이동 확인.

실행: 배포 소스에서 `node scripts/sync-player-prompt.mjs`, `node --test tests/*.test.mjs`, `node node_modules/typescript/bin/tsc --noEmit`, `npm run build`. 실패한 검사는 수정 후 관련 경로 재검증; 유료 모델 품질 평가는 별도 예산/기준 합의 후 수행.
