# 플레이어별 발언 의사 판단

- 목표: 기존 DISCUSS 시점(공개 사건/새 대화)에 각 AI가 자신의 역할·허용된 정보·개인 판단으로 TALK/WAIT를 결정한다.
- 새 판 `discussionPolicy`: `player` 기본, `moderator` 기존 중립 JEV 화자 선택. routingMode=jev일 때 적용한다. 기존 미기록 판은 moderator로 유지한다. 기존 Gemini 단독/규칙 라우팅에는 적용하지 않으며 UI에 설명한다. 다음 새 게임부터 고정 적용하고 로그/비교 조건에 기록한다.
- 입력: 기존 개인 actionPayload 관찰 경계를 재사용하고 행동 후보는 제거한다. 현재 DISCUSS 트리거와 본인 공개 발언을 함께 제공한다. 다른 AI의 비밀 역할/생각/미공개 표·카드는 전달하지 않는다. 사적 계획을 중립 진행자에게 모으지 않는다.
- 실행: 별도 JEV TALK/WAIT4회, 동시성 최대2, 호출별3초 제한, 자동 재시도 없음. 발언 의사만 판단하고 Gemini 발언은 선택된 AI1명만 생성한다. 기존 THINK를 추가하지 않는다.
- 선택: 공개 직접 질문 수신자가 있으면 답변 기회를 보존한다. 그 외 TALK 희망자 중 마지막 발언자는 후순위로 두고 공개 쟁점의 제안자/오래 기다린 참가자를 고려해 결정적으로 선택한다. 서로 다른 개인 판단 확률을 우선순위 점수로 비교하지 않는다. 전원 WAIT이면 SILENCE. 실패 일부는 성공 판단을 사용하고 전부 실패/키 없음은 기존 규칙으로 대체한다. 사용자 질문 응답·비활성·기존 임대/오래된 응답 폐기 규칙을 유지한다.
- 관측: 호출마다 actor/requestType=DISCUSSION_INTENT/inputHash/비용·지연·상태를 기록한다. 라우팅 결과에 설정/개별 의사/선택을 기록하고 실제 생성·채택과 연결한다. 원문 입력/개인 생각은 추가 로그에 복사하지 않는다. 폴링마다 호출하는 타이머를 추가하지 않는다.

## 구현 전 자동 검증 기준

후속 소유권/유의미성 보완: 도윤 제안·하린 단독 반대·서아 찬성 사례에서 팀 선정 의도와 반대표의 주체를 명시한다. 개인 JEV는 구체적인 한 문장을 먼저 구상하고 본인의 정당한 새 기여가 없으면 WAIT를 선택하도록 강화한다. Gemini도 동일 주체/인용 관계를 받아 남의 해명을 대신하거나 같은 취지를 반복하면 SILENCE를 선택한다. 추가 생성/검수 호출은 없다. 자동 검사는 주체·공개 투표·인용 관계와 미공개 표 비노출, 두 생성 입력의 동일 지침 연결 및 기존 호출 수를 확인한다. 자연어 의미의 적절성은 실제 모델 평가 없이 통과로 주장하지 않는다.

기본/허용값/오류 설정, 개인 비밀 경계, 이벤트/새 발언 트리거, TALK 희망자 선택/공정 순서/전원 WAIT, 직접 질문 응답, 부분/전체 실패·무키·정지, 동시성2·호출4·재시도 없음, 호출별 사용량, Gemini 한 명 또는 미호출, 기존 moderator/규칙 동작을 모의 모델 테스트로 확인한다. API NEW/GET 저장 및 잘못된 설정400도 로컬 Worker로 검증한다. 전체 Node/TypeScript/빌드를 거쳐 배포한다. 실제 발언 전략 품질·지연/비용은 모의 검사로 입증하지 않으며 유료 평가는 이번에 실행하지 않는다.
