# 발언 필요성과 발언자 선택 분리

2026-10-06. 사용자는 매 결과마다 한 명의 발언을 강제하는 방식이 인위적이라고 판단했다. 필요성/발언자 분리와 Gemini의 자율 침묵을 적용하고, 대화 종료 안내는 “다음 단계로 진행할 수 있어요.”만 표시하도록 승인했다.

## 동작과 경계

- 수동 진행의 JEV 모드: 같은 공개 맥락으로 discussion(TALK/WAIT)와 responder(AI4명)를 한 요청에서 판단한다. TALK이면 responder의 Gemini를 호출하고 WAIT이면 생성 없이 토론을 종료한다. 발언자 선택의 불확실성이 필요성 선택과 경쟁하지 않는다. shadow에서는 판단만 기록하며 baseline은 기존 선택을 유지한다. 과거 자동 진행 프로토콜은 보존한다.
- 판단 기준은 미답변 질문, 구체적인 반박/설명 필요, 공개 투표의 차이, 새 원정 결과가 주는 추리 단서, 반복 여부다. 새 사건이라는 이유만으로 발언을 강제하지 않는다. 공개 사건과 사건 이후의 발언을 구분해서 제공한다. 진행자는 비밀 역할/개인 생각/미공개 카드/미공개 표를 받지 않는다.
- 매 사건 첫 응답을 강제하는 규칙과 Gemini CHAT 전용 계약을 제거한다. 사용자 질문의 기존 응답 보장은 유지하며, 선택받은 AI의 자발적 발언에서는 SILENCE를 허용한다. SILENCE를 수신하면 다른 사람을 다시 호출하거나 같은 사건을 재촉하지 않는다. 새 사용자 발언/새 사건이 생기면 다시 판단한다.
- 자동 단계 전환을 추가하지 않으며 연속 세 발언 상한을 유지한다. AI 대화/준비/사용자 선택/역할 추측 중에는 다음 버튼을 비활성화한다. 활성 상태의 안내는 “다음 단계로 진행할 수 있어요.”이다.
- 로그에는 필요성의 선택·확신도·분포와 발언자 후보의 선택·분포, 최종 적용 발언자를 구분해 저장한다. 사용량은 기존 JEV 한 요청/기존 ledger를 사용한다. 비용 차이·자연스러움은 실측 전까지 미확인이다.

## 구현 전 자동 검증 기준

새 팀/투표/원정 결과에서도 WAIT가 유효하고 Gemini 호출0이어야 한다. TALK이면 지정된 AI 생성1회, Gemini SILENCE이면 재시도 없이 종료해야 한다. 질문에는 WAIT 뒤 응답 보장을 유지한다. 누락/잘못된 필요성·발언자·확률·모델·사용량/HTTP/시간초과는 기존 bounded fallback과 오류 기록을 지켜야 한다. 새 사건/새 질문이 다음 판단을 재개하고 상태 버전 충돌·정지·3회 상한·비밀 경계를 유지해야 한다. PC/모바일에서 TALK/WAIT/SILENCE와 문구·버튼 활성/준비 중 비활성을 확인한다.

실행: 운영 `node --test tests/*.test.mjs`, TypeScript 및 Worker 빌드, 별도 로컬 D1/합성 proxy API 검사, 합성 API로 실제 UI 검사. 모의 판별의 TALK/WAIT 판단 품질은 검증하지 않는다. 실제 모델 평가 예산·기준은 지정되지 않아 유료 호출하지 않는다.
