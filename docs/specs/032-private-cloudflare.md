# 개인 Cloudflare 배포

## 목표와 범위
사용자 소유 Workers와 새 D1으로 Codex 구독 및 PC 실행과 독립적으로 게임을 운영한다. GitHub 공개 여부는 변경하지 않는다. 과거 DB는 가져오지 않고 기존 자료는 보존한다. UI/규칙/모델 프롬프트 변경은 범위 밖이다.

## 설계
- 기존 Sites 빌드와 분리된 Vite 설정·Worker 진입점으로 같은 소스를 빌드한다.
- Cloudflare Access를 Worker 전체에 적용하고 사용자 이메일 한 개만 허용한다.
- Worker에서도 Access JWT의 서명·발급자·대상·만료·이메일을 검사한다. 설정 누락은 503, 인증 실패는 403으로 닫는다. 이메일 헤더만 신뢰하지 않는다.
- 정적 파일도 Worker를 먼저 실행한다. Preview URL은 비활성화한다.
- 기존 D1 테이블·잠금·버전 검사를 유지한다. 새 D1에 기존 마이그레이션 3개를 적용한다.
- AI 자격 증명은 기존 연결을 재사용하여 Worker secrets로 전달하며 출력·Git에 저장하지 않는다. 원본 비밀 파일과 기존 Sites는 수정하지 않는다.

## 구현 전 검증 계약
- 생성한 RSA 테스트 키로 정상 소유자 JWT는 허용, 다른 이메일·만료·잘못된 발급자/대상·위조 서명·토큰 누락은 거부한다.
- `/`, `/api/game`, `/api/logs`, 정적 파일 요청 모두 인증 전에 게임 처리기를 호출하지 않는지 확인한다.
- 기존 Node 규칙/정보 경계 테스트와 TypeScript, 독립 Worker 빌드가 통과해야 한다.
- 배포 후 미인증 GET/POST 및 위조 헤더가 로그인으로 이동하거나 403이어야 한다. DB/AI 호출이 허용되면 배포 완료로 처리하지 않는다.
- 인증된 브라우저에서 화면·새 게임·AI 응답·로그 다운로드를 확인한다. 실제 모델 확인은 호출 범위/비용을 정한 후 실행하며 전략 품질 평가와 구분한다.

## 운영
게임 로그 원본은 D1의 games/events/model_usage/ai_failures, 실행 오류는 Workers 운영 로그다. JSON 다운로드를 유지한다. PC 자동 동기화는 Access 인증에 맞춘 추가 연결 전까지 이전 완료 항목에 포함하지 않는다.

## 상태
계정 연결과 구현 진행 중. 실제 배포·검증 결과는 최상위 작업일지에 기록한다.
