# 원정팀 선택의 예상 결과 비교와 A/B 실험 설계

작성일: 2026-10-01. 아래 B1의 제한된 반복 반응 계산과 새 판의 A/B 배정은 구현·비공개 Sites 배포했다. Sites 소스 커밋은 `ca4e824164f7ed96fdb9042f5a6705c946a445f2`, 배포 버전은 `appgprj_6abb90e254808191991a28a385292e4a~appgver_412cb0bb56808191a2906da2442004b6`이다. 자동 대국기와 실제 모델 평가는 아직 실행하지 않았다.

## 문제와 현재 상태

사용자는 과거 기록을 보고 가능한 원정팀과 결과를 비교한 뒤 선택하는 사고 과정을 AI에 적용할 수 있는지 제안했다. 죄수의 딜레마처럼 행동의 결과와 상대 반응을 고려하고 반복적으로 전략을 고치는 게임이론적 접근도 제기했다. 이어 도입 전후 A/B 비교를 요청했고, 첫 버전에 후보별 비교와 상대 전략 반복 계산을 모두 시도하자고 선택했다. 사용자가 말한 `스테이셔너리`의 수학적 의미는 아직 미확인이다.

도입 전의 A에서 `site/lib/belief.mjs`는 5인 역할 배정 60개를 열거하고 공개 제안·완료된 투표·원정 결과로 역할별 사후확률을 만들었다. `site/lib/ai.mjs`는 이를 개인 관찰값과 함께 Gemini에 전달해 `PROPOSE` 팀을 한 번 생성하게 했다. B는 충신 AI 리더에 후보 비교 단계를 추가했다. 사후확률의 행동 계수는 실측·보정된 값이 아니라 가정값이다. `docs/specs/004-evil-probability-model.md`와 `005-belief-learning-experiment.md`가 이 한계와 확률 검증 계획을 설명한다.

## 정책 후보와 결정 경계

| 정책 | 팀 선택 | 비교 목적 |
| --- | --- | --- |
| A: 현재 정책 | 같은 버전의 Gemini가 현재 관찰값·역할 단서를 받아 팀을 직접 반환한다. | 현 동작의 기준선. |
| B1: 예상 결과·제한된 반복 반응 | 각 AI 관찰값에서 합법적 팀 조합(2인 10개, 3인 10개)을 열거하고, 역할 배정의 **공동 분포**와 원정 실패·투표 수락 가정을 이용해 후보별 기대 결과를 계산한다. 각 후보에서 다른 참가자의 찬반 반응을 3차례 갱신한 뒤 고정된 동점 규칙으로 팀을 고르고 Gemini는 대화를 담당한다. | 사용자 요청의 첫 구현. 반복 결과는 균형으로 해석하지 않는다. |
| B2: 균형·탐색 정책 | 상대의 제안·투표·카드 전략을 반복 추정하고 더 긴 결과를 탐색한다. | B1이 실패하는 구체적 상황과 평가 예산이 확인된 뒤 별도 실험. |

B1은 변경 원인을 분리하기 위해 **충신 AI 리더**의 제안에만 적용했다. 악 리더와 멀린은 목표나 정체 노출 비용이 달라 같은 점수를 쓰지 않는다. `P(팀 전원 선)`을 `P(원정 성공)`과 동일시하지 않는다. 악이 성공 카드를 낼 수 있고, 제안 승인도 확률적이다.

예상 결과 계산은 개념적으로 `후보 팀 T의 가치 = Σ_역할배정 P(배정 | 그 AI의 관찰) × Σ_상대 반응 P(반응 | 배정,T,기록) × 이후 승리 가치`다. 실제 `site/lib/team-planner.mjs`는 한 번의 팀 투표와 원정만 근사한다. 악 한 명당 실패 카드 확률 `0.65`, 기존 투표 행동 가정, 찬반 3회 동시 갱신과 절반 폭 완화, 다섯 번째 부결의 즉시 패배값을 사용한다. 나머지 부결은 임시 비용 `-0.15`로 놓고 장기 정보 가치·멀린 피암살 위험은 점수에 넣지 않았다. `weightedRoleAssignments()`의 **공동 배정 분포**를 사용하며 개인별 악 확률을 독립으로 곱하지 않는다. 역할표·중간 점수는 비공개 판단에만 둔다. 모두 가정값이므로 높은 점수가 실측 최선이라는 뜻은 아니다.

DeepRole 연구는 5인 아발론에 공동 역할 신념과 CFR 탐색을 적용했다([Serrino 외, 2019](https://arxiv.org/abs/1906.02330)). 다인 숨은 역할 게임에서 단순 죄수의 딜레마식 2인 균형을 그대로 계산할 수 없으며, 논문도 다인 CFR의 일반적인 균형 수렴을 보장하지 않는다. 따라서 이 설계는 B1의 실증 결과 없이 B2의 균형 계산을 성능 향상으로 가정하지 않는다.

## 오프라인 A/B: 선택 품질과 게임 결과

1. **사전 고정:** 게임 규칙, A의 코드·프롬프트·모델 설정, B의 코드·점수식·동점 규칙, 상대 정책, 테스트 시나리오의 역할·시작 리더·무작위 시드를 버전으로 고정한다. 개발용 시나리오와 최종 평가 시나리오를 판 단위로 분리한다. 같은 판의 여러 결정 시점이 양쪽 자료에 섞이지 않게 한다.
2. **비교 단위:** 우선 대상 AI 한 자리의 역할을 `LOYAL`로 고정하고 그 자리의 제안 정책만 A 또는 B1로 바꾼다. 다른 세 AI와 사람 자리의 스크립트 정책은 동일하게 둔다. 역할 배정, 리더, 상대 유형, 난수 시드가 같은 조건에서 A와 B를 각각 실행한다. 순서는 무작위로 바꾸고 A/B 실행 중에 프롬프트나 상대 정책을 고치지 않는다. 사람 자리의 대화·선택은 고정 스크립트로 제공하므로 이 결과를 실제 사람 게임의 효과로 일반화하지 않는다.
3. **단일 결정 검사:** 저장한 공개 기록 시점에서 A와 B가 고른 팀, 합법성, 팀에 실제 악이 포함되는지, 예측한 원정 성공·승인 가능성, 평가 시점의 실제 결과를 비교한다. 실제 역할표는 평가에서만 정답으로 쓴다. B의 점수가 A보다 높다는 사실만을 성공으로 판정하지 않는다.
4. **반복 대국의 주 지표:** 대상 충신 AI가 속한 선 진영의 **최종 승률 차이**를 쌍으로 계산한다. 각 정책의 승/패, 짝 차이, 역할·상대 정책별 표본 수와 불확실성 구간을 보고한다. 원정팀의 악 포함률, 승인률, 원정 성공률, 멀린 피암살률은 보조 지표다. 멀린·악 적용은 이후 별도 층으로 평가하며 전체 AI 승률 하나로 합치지 않는다.
5. **비용·안정성:** 판당 Gemini 호출 수·토큰·비용 추정, 행동 결정 지연, 게임 완료 시간, 모델 오류·무효 팀·대체 행동 횟수를 정책별로 측정한다. B가 규칙 위반이나 정보 누출을 늘리면 승률과 별개로 실패로 처리한다.
6. **반복 수와 판정:** 평가 전에 파일럿에서 승패의 판 간 변동과 비용을 측정해 목표 효과 크기·반복 판 수·실제 모델 호출 예산을 사용자와 정한다. 현재 자료에는 이를 확정할 근거가 없다. 최종 평가는 고정한 판에서 한 번 실행하고, 미리 정한 효과 기준과 불확실성 구간을 함께 본다. 소수 판 승률 차이나 낮은 B 점수만으로 개선을 선언하지 않는다.

새 판 생성 시 `proposalPolicy`를 A 또는 B로 50:50 무작위 배정하고 `aiConfig`와 `GAME_CREATED` 사건에 보관한다. B 판에서는 충신 AI 리더만 B1을 쓰고 나머지 행동은 A와 같다. 동일 판 중간에 재배정하지 않는다. 사람 게임에서 네 AI 모두를 바꾸면 양 진영에 변경이 들어가므로 `AI 승률`은 좋은 주 지표가 아니다. 실제 서비스 자료에서는 사람의 재방문·중단, 오류, 지연, 만족도와 역할별 승패를 별도 지표로 둔다. 서비스 코드는 배포됐으나 실제 판 자료의 A/B 집계는 미실시다. 사용자 채팅 원문과 비공개 역할은 A/B 운영 메타데이터에 복제하지 않는다.

## 자동 검증과 평가 실행 조건

- **결정적 검사:** 가능한 팀 조합 수와 인원, 같은 관찰값의 같은 점수·선택, 동점 처리, 다섯 번째 부결 비용, 확률 합·유한값, 실패 카드 수와 모순되는 배정 제거, 성공 원정 뒤 악 가능성 유지, 공개 전 투표·개인 카드·실제 역할표의 입력 차단을 `node --test`로 확인한다. 예를 들어 충신 본인과 다른 1명의 2인 원정에서 실패 1장이 공개되면 그 다른 사람의 악 확률은 1이어야 한다. 무효 점수나 관찰 모순은 명시적 오류·기존 유효 정책 대체로 처리하고 사건 코드로 남긴다.
- **모의 모델 회귀:** 고정 응답 모델에서 A/B 정책 라우팅, 재시도·대체, 동시에 들어온 사람 행동으로 이전 결정을 폐기하는 경로를 확인한다. 이 검사는 실제 Gemini의 대화·전략 품질을 증명하지 않는다.
- **실제 모델 평가:** 모델명, 정책·프롬프트 버전, 입력 시나리오 묶음, 상대 정책, 반복 수, 실행 날짜·비용, 위 지표와 실패 사례를 보관한다. 발언 품질은 직접 질문 응답·존재하지 않는 사건 인용·비밀 누출을 별도로 표본 평가한다. 실제 모델 호출의 판 수·비용 한도와 최종 통과 기준은 파일럿 후 확정한다. 미실시 평가는 결과로 기록하지 않는다.

## 구현 전 확인 사항

1. 현재 B1의 3회 반응 갱신·고정된 행동 가정이 실제 상대와 맞는지 검증한다. B2의 본격 균형 탐색은 별도 범위로 남긴다.
2. `005-belief-learning-experiment.md`의 예측 확률 보정 결과가 없는 상태에서 B1의 행동 가정을 어떻게 제한할지 정한다. 확률 가정값의 소수점 차이로 팀을 고른 결과를 실측 최적 전략으로 표시하지 않는다.
3. 평가 파일럿의 대상 상대, 허용 Gemini 호출 비용, 원하는 개선폭을 확인한 뒤 최종 반복 수와 통과 기준을 고정한다.

## 2026-10-01 보완 — 동일 조건과 악 리더에 대한 평가

사용자는 A/B 차이와 동일 조건을 맞추는 방법을 설명해 달라고 요청했고, 충신 리더보다 악 리더일 때 더 주의해야 하지 않느냐고 지적했다. 이는 악 리더에 대한 위험 평가를 우선 검토하자는 사용자 판단이며, 악의 제안 정책까지 즉시 변경하라는 승인으로 해석하지 않는다.

현재 배포된 판 단위 50:50 배정은 **무작위 서비스 비교**다. A와 B의 역할 배정·공개 기록·사람 행동이 동일하다는 보장은 없고 표본이 작으면 역할과 리더의 구성 차이가 크다. 역할·시작 리더·실제 B 적용 횟수로 나눠 보고, 모든 배정 판을 포함한 결과와 충신 AI 리더가 등장할 수 있는 초기 조건의 결과를 구분한다. 실제 B가 실행된 판만 사후 선택해 주 결과를 만들면 선택 편향이 생길 수 있다.

아직 구현하지 않은 **짝지은 오프라인 비교**는 다음 두 범위로 나눈다.

- 한 번의 선택 비교: 동일 저장 상태를 복제하고 동일 대상 AI·역할·공개 기록·팀 인원·원정 점수·제안 횟수에서 A/B의 선택만 비교한다. 실제 역할표는 채점에만 사용한다. A의 Gemini 응답은 같은 설정에서도 달라질 수 있으므로 같은 상태에서 반복 호출하고 변동을 보고한다. B도 동일 상태에서 결정이 재현되는지 검사한다.
- 게임 전체 비교: 같은 역할 배정·시작 리더·규칙·모델 설정·상대 정책에서 A/B를 실행한다. 선택 이후의 상대 반응과 게임 이력은 달라지는 것이 정상이다. 상대의 **정책**을 고정하며 서로 다른 상태에 똑같은 행동 원문을 강제하지 않는다. 게임 난수 시드는 모델 출력의 완전 재현을 보장하지 않는다. 반복과 실행 순서 무작위화로 변동을 측정한다.

악 리더에 대한 평가는 두 가지 질문을 분리한다.

| 평가 질문 | 변경할 정책 | 필요한 상황과 관측 |
| --- | --- | --- |
| 악 리더의 위험한 팀 제안을 선 AI가 걸러내는가? | 선 AI의 찬반 판단 후보 정책. 현재 A/B에는 미포함. | 악이 섞인 팀/전원 선 팀, 악의 이전 성공 카드로 신뢰가 생긴 상태, 5번째 제안. 위험 팀 승인율만 낮추는 것으로 성공을 판정하지 않고 안전 팀 부결·5회 부결 패배·선 최종 승률을 함께 본다. |
| 악 AI가 전략적으로 팀을 구성하는가? | 악 리더의 별도 제안 후보 정책. 현재 A/B에는 미포함. | 실패 유도, 성공으로 신뢰 쌓기, 동료 악을 포함하는 선택, 정체 노출과 멀린 암살. 악 최종 승률·승인률·실패 카드 선택·정체 노출을 평가한다. 선의 점수를 단순히 반대로 뒤집지 않는다. |
| 충신 리더의 새 팀 선택이 악의 기만에도 유효한가? | 현재 B의 충신 제안 정책. | 항상 실패하는 악, 초기에 성공하는 악, 악 둘이 같은 팀일 때 실패를 분담하는 상대 정책을 고정해 각각 A/B 비교한다. 상대 유형별 효과를 보고한다. |

첫 번째와 세 번째를 우선 평가하는 것이 선 AI의 방어 능력 검증에 맞다. 현재 B의 3회 갱신은 고정 가정 아래의 찬반 확률 계산이며, 실제 상대 행동을 통한 온라인 학습·악 카드 전략의 반복 최적화·장기 균형 계산은 아니다. 악의 실패 카드 확률 `0.65`를 고정해 둔 한계 때문에, 이 가정을 다르게 놓는 민감도 검사와 실제 상대 정책별 대국을 함께 설계해야 한다. 이번 보완은 평가 설계 변경이고 배포된 행동 정책 변경이나 대국 실행 결과는 없다.

### 자료 이해와 목표

`site/db/schema.ts`의 `games` 한 행은 한 판의 최신 상태이며 `state` 안에 실제 역할표, `proposals`의 팀·리더·공개 완료 표, `quests`의 실패 카드 수와 최종 승자가 있다. `events`는 수락된 상태 전이 한 건, `ai_failures`는 실패 시도 한 건이다. 판과 사건은 `game_id`로 연결하고 사건의 상태 버전은 판 안에서 고유하다. 제안·투표·원정은 판 상태 배열에서 분석하며 사건 전체와 단순 조인해 투표가 중복 증식하지 않게 한다. 정책 배정은 새 버전의 `aiConfig.proposalPolicy`, 정책·모델 버전과 모드는 생성·행동 사건에서 확인한다.

사용자는 악 포함 팀에 반대한 선 AI 수와 선 AI 리더의 악 배제 여부를 지표로 제안했다. 동시에 사람의 정보 수집 전략에서 일부러 악이 섞인 팀을 고를 수 있음을 지적했다. 채택 여부의 결과 지표와 선택·투표의 진단 지표를 함께 보고, 위험 팀 선택을 무조건 잘못된 행동으로 판정하지 않는 방향을 제안한다. 사용자는 최소 목표 개선폭을 파일럿을 보고 결정하기로 선택했다. 이는 실제 모델 호출 비용 집행 승인이 아니다.

### 같은 상황과 전략적 예외

선/악 배정과 두 번째 원정·3인 팀이라는 조건만으로 동일한 판단 상황이 되지는 않는다. 같은 충신이라도 자기 역할·이미 공개된 투표·원정 실패·대화·점수·제안 횟수·리더·본인 참가가 다를 수 있다. 실제 서비스에서는 몇 개의 사전 지정 조건으로 층화해 기술 비교하며, 전체 역할 배정×대화 이력의 정확 일치를 기다리지 않는다. 현재 정책의 이전 선택으로 생긴 이력을 사후 매칭한 결과도 직접적인 인과 효과로 주장하지 않는다. 투표 능력 자체는 같은 공개 상태·같은 제안 팀을 A/B 판단에 입력하는 별도 평가에서 비교하는 것이 적절하다.

사람이 일부러 악을 팀에 넣어 정보를 얻는 전략은 사람 제안을 제외하는 충신 AI 리더 지표를 직접 오염시키지 않지만, 이후 투표·승패·AI 관찰에는 영향을 준다. 또 AI도 같은 전략을 사용할 수 있으므로 악 포함 여부는 진단이지 정답 행동 라벨이 아니다. 원정 실패 카드 수는 실제 악 수의 하한일 뿐이다. 성공해도 악이 포함될 수 있다. 전략적 예외를 결과를 본 뒤 골라 제외해 수치를 높이지 않는다. 필요하면 제안 전에 의도를 표시하는 별도 평가 사례를 만들고, 정보 획득과 다음 선택·최종 승패를 확인한다. 자기 보고 의도만으로 좋은 전략으로 인정하지 않는다. 현재 배포판에는 이 의도 기록이나 정보 가치 정책이 없다.

### 수집량의 예시와 단계

아래는 **실측 성능·확정 목표가 아닌 계산 예시**다. 독립적인 두 집단의 판별 이진 승패, A/B 동일 수, A 승률 50%, 양측 유의수준 5%, 검정력 80%의 정규 근사를 가정한다. 식은 `n = ceil((1.95996398454*sqrt(2*pbar*(1-pbar)) + 0.84162123357*sqrt(pA*(1-pA)+pB*(1-pB)))^2/(pB-pA)^2)`이며 `pbar=(pA+pB)/2`다. 근거는 [statsmodels의 두 독립 비율 검정력·표본 수 구현](https://www.statsmodels.org/stable/_modules/statsmodels/stats/proportion.html)이다. 이번 대화의 JavaScript 계산에서 아래 값을 얻었다.

| 가정한 차이 | 집단별 독립 판 수 | 총 판 수 |
| --- | ---: | ---: |
| 50% → 70%, +20%p | 93 | 186 |
| 50% → 60%, +10%p | 388 | 776 |
| 50% → 55%, +5%p | 1,565 | 3,130 |

이 표는 반복된 투표·특정 역할 조합의 하위 집단·중단 판·동일 사용자 세션의 상관·짝지은 대국에 그대로 적용할 수 없다. 파일럿에서 판별 분산과 상관, 역할별 사례 확보율을 측정해 주 지표에 맞춰 다시 계산한다. 투표 진단 지표가 몇백 건 쌓여도 승률 검증에 필요한 판 수를 충족했다고 보지 않는다.

제안 순서는 A/B 각각 30~50판을 **수집·계측·분산 점검용 파일럿**으로 삼는 것이다. 이 수는 통계적 우위 판정의 근거가 아니라 실행 규모 제안이다. 같은 모델·규칙을 유지하고 중단·실패·역할별 지표의 분모가 잡히는지 확인한다. 그다음 의미 있는 최소 개선폭과 실제 모델 호출 비용 한도를 사용자와 정하고 최종 평가 판 수·종료 시점을 고정한다. 파일럿 결과를 보고 정책을 수정했다면 파일럿은 최종 확증 자료에 섞지 않는다. 유의한 결과가 처음 보였다는 이유로 수집을 중단하지 않는다. 수동 사람 플레이만으로 표본을 채우기 어려우면 자동 대국과 고정 상태 평가를 병행하되 실제 사람 플레이 자료와 분리한다. 현재 자동 대국·지표 집계기는 미구현이며 실제 모델 호출 비용 집행은 이번 설계에 포함하지 않는다.

검토 상태: 기록 구조·지표의 분자/분모·예외·현재 정책 범위는 확인했다. 실제 자료 품질·기간별 판 수·기준값·목표 개선폭·상관·예산은 미확인이다. 소유자가 채택 판단을 맡고, 다음 최소 작업은 종료 판의 정책·기록 완전성 검사와 위 지표의 판별 집계기를 만드는 것이다. 서비스 행동 정책 변경은 이번 문서 보완에 포함하지 않는다.

### 승률의 주체와 적용 범위

사용자는 한 진영이 이기면 상대가 지는데 승률을 어떻게 계산하려는지 확인했다. 여기서 현재 정책의 결과 지표는 **A 배정 판의 선 승리 수 / A 정상 종료 판 수**와 **B 배정 판의 선 승리 수 / B 정상 종료 판 수**를 비교하는 것이다. 예시 A 100판의 선 승리 40판과 B 100판의 선 승리 55판은 선 승률 40%와 55%, 차이 +15%p다. 악 승률 60%와 45%는 같은 결과의 보완값이므로 두 지표를 독립적인 개선으로 주장하지 않는다. 수치는 설명 예시이며 실측 결과가 아니다.

현재 B는 충신 AI의 제안만 바꾸므로 선 진영을 지원하는 변경의 효과를 평가할 수 있다. 선과 악의 AI를 동시에 바꾼 뒤 같은 리그 전체의 승률을 평균하면 양쪽의 상대적 강약만 드러나거나 항상 평균 50%가 되는 정의가 생겨 AI 전체 지능 개선을 측정할 수 없다. 해당 단계에서는 대상 AI 한 자리의 정책만 A/B로 바꾸고 상대 정책을 고정해, 대상 AI가 속한 진영의 최종 승률을 충신·멀린·암살자·하수인별로 계산한다. 목표 AI가 선이면 선 승리, 악이면 악 승리가 그 AI의 승리다. 사람 승률·AI 인원수로 가중한 전체 승률은 이 지표와 섞지 않는다.

### 플레이 중 배정 숨김과 사후 분석

사용자는 현재 실험 범위로 진행하는 데 동의하고 플레이 중 A/B를 모르는 상태로 참여하되 이후 로그에서 분석할 수 있기를 요청했다. 일반 게임 응답에는 배정이 없고, 진단 파일의 `proposalPolicy`도 종료 전에는 제외하도록 수정했다. 종료 후 진단·전체 로그와 서버 상태·사건에는 A/B를 보존한다. 로컬 API 연습 판 완주로 숨김과 종료 후 보존을 확인했으며 Sites 버전 17을 비공개 배포했다. 정책별 행동이나 지연에서 추측하는 것까지 막는 완전한 블라인드를 보장하지는 않는다.
