# 게임 로그 자동 저장

작성일: 2026-10-01. 사용자 요청: 종료 시와 새 게임 시작 시 로그를 자동 저장하고 기존 다운로드 버튼을 유지한다. `logs` 폴더에 게임별 파일을 두며 같은 게임 코드면 최신 기록으로 갱신한다.

## 확인된 구조와 연결 선택

- 판의 UUID를 게임 코드로 사용해 `logs/avalon-{UUID}.json` 한 파일을 유지한다. 새 코드 체계나 최근 파일 검색은 필요하지 않다.
- 배포 게임 기록은 Sites의 D1에 자동 저장되며 브라우저 다운로드는 현재 판 쿠키를 사용한다. 클라우드 Worker와 모바일 브라우저는 이 PC 폴더에 직접 쓸 수 없다.
- 모바일 판까지 PC 폴더에 모으려면 PC 동기화 프로그램이 서버에서 기록을 가져와야 한다. PC가 꺼지면 서버에서 보존하고 다음 실행에 가져온다. PC 브라우저 폴더 연결은 사용자의 디렉터리 권한 설정이 필요하며 모바일에서 PC 폴더로 쓰는 기능을 제공하지 않는다.
- 사용자가 PC 자동 동기화 제안대로 구현·배포하도록 승인했다. Windows 로그인 시 `AvalonLogSync` 작업이 창 없이 실행된다. 정상 수집 후 15초, 오류 후 60초 간격으로 다시 확인한다.

## 저장 규칙과 검증

- 전체 로그의 기존 `avalon-game-log-v1` 형식을 유지한다. 종료 전 게임의 비밀 역할과 A/B 배정은 플레이 화면에 노출하지 않는다.
- 새 게임 때문에 중단된 판은 정상 승패 판과 구분하고 평가 승률 분모에서 별도로 처리한다.
- 같은 UUID는 같은 파일에 쓰고, 새 버전보다 낮은 버전이 도착하면 기존 파일을 유지한다. 임시 파일 작성 후 교체해 중간 쓰기 파일이 정식 로그로 읽히지 않게 한다.
- 역할표·채팅이 들어 있는 `logs/`와 로컬 인증 설정은 Git에서 제외한다. 파일 이름은 검증된 UUID에서만 만든다.
- `node --test scripts/save-game-log.test.mjs`로 동일 코드 갱신·오래된 버전 거부·UUID 경로 입력 검증을 확인한다. 자동 연결을 구현하면 종료 후·새 게임 전 기록, PC 오프라인 뒤 복구, 반복 동기화의 중복 방지, 인증 실패와 커서 전진 조건도 검사한다.

## 구현과 운영

- 정상 종료 시 서버가 종료 시각을 저장한다. 새 게임 시작 시 진행 중인 이전 판은 `ENDED`, `winner: null`, `endReason: RESTARTED`로 보관한 뒤 새 판을 만든다. 중단 판은 정상 승률 분모에 넣지 않는다.
- `/api/logs`는 전용 비밀 토큰을 확인하고 종료된 판만 반환한다. 기존 사이트의 소유자 전용 접근도 유지한다. 목록의 버전·갱신 시각·마지막 오류 번호로 변경을 감지해 같은 게임 파일을 갱신한다.
- `scripts/sync-game-logs.mjs`가 기록을 가져오고 `scripts/save-game-log.mjs`가 파일을 저장한다. 인증값은 현재 Windows 계정의 DPAPI로 암호화해 `.log-sync/credentials.dpapi`에 보관하고 해당 계정과 SYSTEM만 폴더에 접근하게 한다. 평문 인증은 실행 메모리에만 전달한다.
- `.log-sync/manifest.json`은 수집한 기록의 버전 목록, `status.json`은 마지막 실행 시각·성공 여부·저장 개수다. 이 상태 파일에는 대화·역할표·인증값을 남기지 않는다. 전체 게임 파일에는 역할표·대화·A/B 설정·사건·오류가 들어가므로 개인 분석 자료로 보관한다.
- PC가 꺼져 있거나 통신이 실패하면 서버 기록을 다음 실행에서 가져온다. 이는 종료 즉시 PC에 파일을 쓰는 보장이 아니라 주기적 동기화다. PC 폴더 이동 또는 인증값 변경 시 실행 경로·인증 설정을 다시 구성해야 한다.
- 기존 로그 다운로드 버튼은 유지한다. 자동 수집은 현재 브라우저 쿠키와 독립적이므로 모바일에서 끝난 판도 대상이다.

### 관리

프로젝트 폴더에서 `powershell.exe -NoProfile -File scripts/run-log-sync.ps1 -Once`로 한 번 수집할 수 있다. Windows 예약 작업 `AvalonLogSync`를 중지/시작하면 자동 수집을 끄거나 다시 켤 수 있다. `scripts/install-log-sync.ps1`은 보호된 인증 입력을 받아 로그인 작업을 등록하는 설치용 스크립트다. 인증값을 저장소나 작업일지에 복사하지 않는다.

## 2026-10-07 새 플레이 수집 폴더와 thinking 확인

사용자 요청에 따라 이후 종료·새 게임으로 중단된 판은 `logs/playtests-2026-10-07/avalon-{UUID}.json`으로 수집한다. `.log-sync/collection.json`에 폴더 이름과 시작 전 보관된 34개 판 ID를 기록해 과거 자료가 새 수집 폴더로 섞이지 않게 한다. 기존 logs 최상위 파일은 유지한다. 진행 중이던 판이 이후 종료/재시작되면 수집 대상이다. 폴더별 manifest를 별도로 사용한다.

새 게임의 이전 판 보관과 정상 종료 저장은 기존 서버 동작을 사용한다. 종료 화면 다운로드는 서버 기록의 최신 JSON을 브라우저로 받으며 브라우저 다운로드 위치는 브라우저 설정을 따른다. PC의 위 폴더에는 예약 작업 AvalonLogSync가 보통 15초 주기로 별도 저장한다. 따라서 클릭과 PC 저장이 같은 순간에 일어나는 보장은 없으며 PC 오프라인/인증 오류 시 다음 성공 수집까지 늦어진다. 새 게임은 진행 중 판을 RESTARTED로 보관하며 정상 승패 판과 구분한다. 다운로드 버튼을 누르지 않아도 정상 종료 판은 수집한다. 과거 제외 판을 다시 다운로드한 경우에는 브라우저 다운로드만 남는다.

서버가 usage_revision을 제공하면 기존 변경 검출을 사용한다. 제공하지 않는 과거 배포는 대상 로그를 재조회하여 exportedAt을 제외한 내용이 바뀐 경우에만 파일을 갱신한다. 늦게 기록된 thinking/사용량의 누락을 막기 위한 호환 처리이며 수집 판이 많아지면 서버의 usage_revision 지원이 효율적이다. 다른 작업에서 추가 중인 usage_revision 처리도 보존했다.

검증: `node --test scripts/sync-game-logs.test.mjs scripts/save-game-log.test.mjs site/tests/player-v3-memory.test.mjs site/tests/action-selection.test.mjs site/tests/game-log.test.mjs` 13/13. 새 폴더 격리, 과거 판 제외, 중단판 저장, 같은 판의 늦은 생각/비용 반영, 중복 갱신 방지, 경로 이탈 거부, 개인 기억 경계를 검사했다. 실제 일회 수집은 total34/saved0으로 새 경로를 반환했고 예약 작업 Running과 후속 status 갱신을 확인한다. 신규 실제 판 완주/클릭 후 자동 수신 및 재부팅 검증은 아직 미실시다.

### thinking 저장과 입력 범위

- 의미: 응답 JSON의 thinking 문자열이며 모델의 자기보고다. Gemini native thought 파트는 필터링한다. thoughtsTokenCount는 사용량 숫자로만 남는다.
- 로그: 파싱 가능한 각 응답의 생각을 modelUsage[].thinking에 보존한다. 채택된 행동은 events[].detail.thinking/thinkingOwner에도 남고, game.privateThinking[AI ID]에는 해당 AI의 최근 채택된 생각 한 개가 들어간다. 전체 종료/중단 JSON은 이 필드를 포함한다. JSON 자체가 깨지거나 요청 실패로 thinking을 파싱하지 못하면 생각 텍스트는 없다.
- 다음 Gemini 요청: personalInfo.previousThinking으로 본인의 최근 기억 한 개(text/stateVersion/requestType/at)를 입력한다. 코드상 별도 문자열 절단 없이 전달하며 전체 응답 생성 상한은 768토큰이다. 모든 과거 생각을 다시 입력하지 않는다. 재시도·낡은 상태의 폐기 응답·기본 대체는 채택된 기억을 덮어쓰지 않는다. 유효하게 채택된 자율 SILENCE는 해당 AI 기억을 갱신할 수 있다.
- 함께 제공하는 정보: 공개 채팅 최근20개, 그 이전 replyTo가 있는 발언 최대4개(earlierResponses), 공개 사건 최근12개, 제안 최근6개, 원정 이력, 본인 역할/허용 시작 정보/본인 표·카드, 본인 행동 최근16개, 역할 단서와 악 확률. 대화20개 제한이 전체 게임 정보를20개로 자른다는 뜻은 아니다.
- 다른 입력 경로: JEV 개인 행동에는 본인의 같은 최신 생각(text/stateVersion/requestType)이 들어간다. 공개 진행자 JEV와 다른 AI 관점에는 전달하지 않는다. JEV 자체는 thinking을 생성하지 않는다. evidence는 별도 짧은 판단 설명이며 다음 요청의 기억으로 넣지 않는다.
- 실제 로컬 수집 로그34개 확인: thinking이 있는 판6개, 호출 기록215개, 사건 기록193개. 가장 최근 해당 판(2026-10-06 18:49 KST 생성)은 호출4개/사건4개, AI3명의 최신 기억이 해당 사건 문자열과 모두 일치했다. 이는 저장 확인이며 모델의 기억 활용 품질이나 모든 호출의 성공을 증명하지 않는다. 원문 텍스트는 문서에 복사하지 않았다.
