# 악 확률모형 학습 전후 비교 실험 설계

작성일: 2026-09-30. **설계안**이며 학습·평가 실행 결과는 없다. 비교 대상은 `site/lib/belief.mjs`의 현재 가정 계수와, 종료된 여러 판으로 추정한 계수다. 목표는 악 확률의 **예측 품질**을 높이는지 확인하는 것이다. 게임 승률이나 Gemini의 추론 능력 개선은 이 실험의 결론으로 주장하지 않는다.

## 1. 비교할 모형과 판 수집

| 이름 | 계수 | 목적 |
| --- | --- | --- |
| 규칙만 적용 | `roleClues()`의 가능한 역할 배정 균등 비율 | 행동 우도를 넣는 것 자체의 참고 기준선 |
| 학습 전 A | 현재 `BEHAVIOR_MODEL`: 제안 선호 `1.2`, 투표 절편 `-0.4`, 본인 참가 `1`, 5번째 제안 `1.2`, 정보 보유자의 악 팀 반응 `1`, 악의 실패 카드 확률 `0.65` | **주 비교 기준선** |
| 학습 후 B | 같은 수식·특징을 유지하고 종료 판에서 계수만 추정 | 가정값을 자료로 바꾼 효과 |

수집 기간에는 게임 규칙, AI 행동 정책·프롬프트, 역할 추론에 공급하는 **A의 계수**를 고정한다. B는 우선 오프라인에서만 계산한다. 학습 결과를 게임 중 AI에 공급하면 AI의 제안·표·카드 행동 자체가 바뀌므로, 그때부터는 다른 행동 정책의 새 자료로 분리한다. 사람 플레이와 연습 AI/Vertex AI 판, AI 정책 버전은 섞지 않고 각각 표시한다. 주 평가 모집단은 실제 제공하려는 게임 모드로 사전에 하나를 지정한다. 다른 모드는 별도 탐색 결과로 보고한다.

현재 `games.state`에는 판의 역할표, `proposals`의 팀·리더·완료 투표, `quests`의 팀·실패 카드 수, `privateCards`의 개인별 카드, 종료 상태가 있다. `events`와 `ai_failures`에는 상태 버전·정책 버전·오류 단서가 있다. 추가 게임 중 비밀 기록은 필요하지 않다. 다만 평가 파이프라인은 아직 구현되지 않았고, 과거 판은 정책 버전이나 완전한 기록이 없을 수 있다. 원문 채팅은 이번 학습에 사용하지 않는다.

## 2. 학습 자료와 정보 경계

1. `phase=ENDED`인 판만 가져오고 역할 수, 제안 순서·팀 크기, 다섯 명의 완료 투표, 원정과 승인 제안 연결, 카드 수 일치를 검사한다. 중단 판과 모순·누락 기록은 제외하고 제외 건수와 이유를 남긴다. 종료 판을 골랐다는 선택 편향도 보고한다.
2. **학습할 때만** 실제 역할표를 정답으로 사용한다. 제안은 실제 리더·팀에 대한 softmax 로그 우도, 공개 투표는 각 플레이어의 찬반 로그 우도, 악의 실패 카드 선택은 종료 후 `privateCards`의 개인별 이진 결과로 추정한다. 선의 실패 금지 같은 규칙은 학습하지 않는다. 계수가 식별되지 않는 조건(예: 학습 구간에 5번째 제안이 없음)은 기존 값으로 고정한다.
3. 작은 자료에 한두 행동이 계수를 크게 바꾸지 않도록 A의 계수 쪽으로 수축하는 벌점과 악 카드 확률의 경계 제약을 둔다. 벌점 강도 등 선택은 **학습·검증 판에서만** 한다. 우선 `sabotageChance`만 학습하고, 카드·제안·투표의 역할별 사례가 쌓이면 나머지 다섯 계수를 함께 학습한다. 새 특징이나 복잡한 정책은 이 비교에 넣지 않는다.
4. 예측 시에는 실제 역할표나 개인별 카드가 입력에 나타나면 안 된다. 종료 상태에서 `observe()`를 그대로 호출하면 역할표가 공개되므로, 제안 투표 공개 직후와 원정 결과 공개 직후의 **과거 시점 관찰값**을 사건 순서대로 재구성한다. 해당 시점까지의 제안·공개된 표·원정 결과와 관찰자의 자기 역할·시작 정보만 `evilPosterior()`에 전달한다. 재생기의 정보 경계는 별도 검사로 확인한다.

## 3. 분리와 평가 시점

- 같은 판의 여러 시점·플레이어를 학습과 평가에 나누어 넣지 않는다. **판 ID 단위**로 시간순 분리한다. 초기 자료는 학습과 계수 선택용 검증에 사용하고, 이후 새로 종료되는 판을 한 번만 여는 최종 평가 구간으로 예약한다. 분리 시점·포함 조건·모형 버전과 해시를 최종 평가 전에 고정한다. 현재 판 수와 분산을 확인하지 않았으므로 최종 판 수와 검출 가능한 개선폭을 임의로 확정하지 않는다. 먼저 파일럿으로 판당 점수의 판 간 변동을 측정해 필요한 판 수를 정한다.
- 각 종료 판에서 **모든 충신 관찰자**의 예측을 재생한다. 멀린과 악은 시작부터 악을 알기 때문에 주 점수에 섞으면 쉬운 정답이 성능을 부풀린다. 충신 본인을 제외한 네 플레이어의 정답 `y_i∈{0,1}`과 확률 `p_i`를 비교한다.
- 각 공개 완료 제안 직후와 각 원정 결과 직후를 체크포인트로 삼는다. 종료 화면의 역할 공개 직후는 평가하지 않는다. 한 판에서 `4명 × 2충신 × 체크포인트 수`의 오차를 평균해 **판당 점수 하나**를 만든다. 따라서 제안이 많은 판이 총점에서 자동으로 더 큰 비중을 얻지 않는다. 원정 이전에 5회 부결로 끝난 판도 완료 제안 체크포인트로 평가한다.
- A·B·규칙 기준선에 **동일한 판·동일 시점·동일 관찰값**을 입력한다. 주 지표는 판당 Brier 점수 `평균[(p_i-y_i)^2]`로, 낮을수록 좋다. 주 비교값은 `Δ = Brier_B - Brier_A`다. 참고로 로그 손실과 확률 구간별 실제 악 비율을 보고, 첫 원정 전/후·제안 횟수별 점수와 학습 모드별 점수도 분리한다. 승률은 이번 오프라인 실험의 주 지표가 아니다.

## 4. 판정과 보고

최종 평가 판을 단위로 A와 B의 **짝지은 점수 차이**를 계산한다. 판 단위 재표본추출로 `Δ`의 95% 신뢰구간을 구하고, 점추정·구간·판 수·체크포인트 수를 함께 보고한다. `Δ<0`이고 신뢰구간 전체가 0보다 작으면 해당 평가 자료에서 Brier 개선의 근거로 본다. 그렇지 않으면 개선을 확인하지 못한 것으로 보고 A를 유지한다. 개선이 보이더라도 로그 손실 악화, 확률 보정 불량, 특정 역할·단계에서의 큰 악화가 있으면 원인을 검토한 뒤 적용 여부를 결정한다. 미리 정한 평가 판을 반복해서 열어 계수를 고르면 그 판은 더 이상 독립 시험 자료가 아니다.

평가 결과가 좋으면 학습 계수·자료 범위·게임/AI 정책 버전·검사 결과를 버전으로 남기고 다음 새 판부터 적용한다. 이후 같은 기간의 승률 전후 차이만으로 확률모형 효과를 주장하지 않는다. 확률이 AI 행동에 영향을 주는 **게임 성능**까지 평가하려면 다음 단계에서 같은 시작 조건의 반복 대국 또는 정책별 무작위 배정 실험을 별도로 설계한다. 그때 모델 호출 실패·지연·비용도 함께 본다.

## 5. 구현 순서와 미확인 사항

1. 종료 판을 소유자 전용으로 읽어 구조·정책 버전·게임 모드를 점검하고, 공개 사건 재생기를 만든다. 실제 DB의 적격 판 수와 누락률을 확인한다.
2. A를 재생해 현재 서버에서 보던 시점의 확률과 같은지 확인한다. 비밀 표·개인 카드·미래 사건을 제거한 입력 검사를 만든다.
3. 학습·검증 구간에서 계수를 추정하고 모델 버전별로 고정한다. 파일럿의 판당 점수 분산으로 최종 평가 판 수를 정한다.
4. 예약한 새 판에서 A와 B를 오프라인으로 동시에 채점하고 위 기준으로 판정한다. 점수·계수·제외 판·실행 명령을 남긴다.

현재 실제 학습 가능한 종료 판 수, 모드별 구성, 모델의 학습 전 Brier 점수, 필요 판 수, 비용은 **미확인**이다. 이 문서는 설계와 판정 기준이며 학습 결과나 성능 향상 기록이 아니다.
