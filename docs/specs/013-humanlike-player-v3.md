## 목표와 완료 기준

말투를 꾸미기보다, 자기 역할의 승리를 원하는 참가자가 현재 대화와 선택에 반응하도록 한다. 새 프롬프트, 관찰 범위를 지키는 입력 구성, 재현 가능한 검사, 실제 품질 평가 사례를 만든다. 사람과 구분 불가능하다는 주장은 하지 않는다. 화면의 AI 표시는 그대로 둔다.

## 구현 전에 정한 자동 검사

- 새 파일의 읽기용 본문과 실행 템플릿 일치. V2 기본 연결·원문 유지.
- 새 판은 과거 기록 없음. 요청한 AI 자신의 역할·알려진 악·자기 표/카드만 포함.
- 공개 전 타인 투표/카드, 전체 역할표, thinking, 종료용 evidence가 입력에 섞이지 않음. 종료 판의 입력 생성 거부.
- 최근 8개 밖의 직접 질문·답장 원문과 본인 과거 발언을 회수. 제안·전원 공개 표·원정 결과의 구조화 이력은 보존. 없는 과거 이유를 생성하지 않음.
- 본인 페르소나만 전달. 5개 요청 행동별 JSON 스키마·팀 인원·선 카드 제한을 기존 스키마와 일치시킴.
- 요청 스냅샷 버전을 함께 반환. 두 입력 생성 간 전역 기억을 공유하거나 게임 상태를 변경하지 않음.
- 기존 오류·재시도·동시 요청·오래된 응답 폐기 검사는 전체 회귀 검사에서 유지. 후보는 네트워크/저장/재시도 경로를 새로 만들지 않음.

## 프롬프트만으로 부족한 부분

이번 구현은 **관찰값 구성과 공개 사실 기억 회수**까지다. `buildHumanlikeTurn(game, request)`가 새 프롬프트·기존 응답 스키마·스냅샷을 만든다. 서버 전체 상태를 문자열로 복사하지 않는다. 마지막 몇 문장만 보느라 과거 표나 자신의 발언을 놓치는 문제를 줄이는 목적이다. 선택 당시의 사적 이유를 새로 저장/회상시키지는 않는다. 종료용 evidence를 다음 입력으로 쓰는 기존 경계도 바꾸지 않는다.

문맥은 최근 8개, 본인 발언 최근 4개, 본인 이름 언급 최근 2개, 직접 답장과 최대 4단계 원문 연결 및 관련 답변을 합쳐 원래 시간순으로 전달한다. 임의의 오래된 대화 전체를 회상하는 기능은 아니며 누락 수를 표시한다. 특정 팀·찬반·암살 대상을 복사하게 만들 수 있는 고정 선택 예시는 제외하고, 기존 구조화 출력 스키마로 형식을 전달한다.

실행 연결 시 기존 `decide()`의 모델 요청 부분에서 반환한 prompt/schema를 사용하고 기존 행동 검사·thinking 폐기·evidence 정규화·상태 버전 검사를 유지한다. 기본 연결 변경은 이 후보의 결과물을 작성하는 것과 분리한다. 별도의 실제 API 클라이언트를 추가하지 않는다.

### 자유 토론을 위한 후속 구조 (설계, 미구현)

1. 사람/AI의 새 공개 메시지 모두를 응답 기회 사건으로 취급한다. replyTo 또는 명확한 지목 당사자를 우선하고, 이후 관련 리더·팀원·오래 말하지 않은 후보 순으로 한 명씩 기회를 준다. 인물 언급만으로 질문이라고 확정하지 않는다.
2. 후보 한 명의 한 호출에서 CHAT/SILENCE를 받는다. 진행자에게는 비밀 역할·개인 의도·evidence를 전달하지 않는다. 후보가 선택되지 않아도 다음 입력에 공개 사건은 누락하지 않는다.
3. 같은 공개 상태에서 이미 확인한 후보에게 다시 묻지 않는다. 모두 침묵하면 호출 없이 대기한다. 새 AI 질문에는 답할 기회를 다시 열되, 장시간의 AI 연쇄는 호출 예산/사람 끼어들기 경계로 중단한다. 과거 사용자가 거부한 ‘사건당 두 발언’ 제한을 몰래 되살리지 않는다. 연쇄 예산의 값과 UX는 결정 필요다.
4. 사람 입력이 저장되면 진행 중인 이전 버전의 AI 답변은 게시하지 않는다. 중복 ADVANCE도 한 번만 저장한다. 토론 중 자동 투표하지 않고 START_VOTE에서 최종 명단을 고정한다.
5. 기본 8초 idle·단계당 최대 2회 기회는 기존 합의다. 무한 재시도·전원 동시 모델 호출·추가 LLM 진행자 호출은 이번 후보에 넣지 않는다.

현재 앱은 AI CHAT 뒤 토론 대기를 해제한다. 따라서 **새 프롬프트만 붙여도 자유로운 AI 간 연쇄 토론이 완성된다는 뜻이 아니다.** 위 큐/예산을 구현하려면 UI/API/game의 별도 변경과 회귀 검사가 필요하다. B 충신 초기 팀 계산·연습 모드·scripted 시작 안내에도 프롬프트는 영향을 주지 않는다.

## 실제 품질 평가안 (실행 전 범위 합의 필요)

평가 단위는 단문이 아니라 질문→답변→후속 선택의 짧은 구간이다. 사례 파일에 상황·요청·기대 관찰·금지 실패를 둔다. 기대 대사나 유일한 정답을 강제하지 않는다.

`site/tests/humanlike-v3-cases.mjs`의 `humanlikeCases()`는 실제 엔진으로 합성 상황 6개를 만든다: 오래된 반대표 질문, 반복할 내용밖에 없는 순간, 실패 팀의 범인 단정 반박, 첫 멀린 팀 선정, 선 2승에서 악 둘의 비밀 카드 선택, 조용한 참가자들 사이의 암살. 실제 사용자 로그가 아니며 호출·저장을 수행하지 않는다. 이 사례는 단일 결정의 출발점이고, 대화→후속 선택 연결을 평가할 때는 동일한 후속 공개 발언을 두 버전에 이어서 제공해야 한다.

원하는 대화 모습의 창작 예시(프롬프트에 삽입하지 않음): 사람의 “하린 대신 서아를 넣으면 찬성할게”에 하린이 “나를 빼는 이유가 지난 실패 팀에 있었다는 것뿐이야?”라고 반응하고, 사람이 다른 근거를 답하면 리더가 그 근거를 받아들이거나 반박한 뒤 초안을 유지/수정한다. 모든 참가자가 이름·근거·대안을 한꺼번에 말할 필요는 없고, 최종 명단을 본 뒤 실제 표를 판단한다. 이 예시는 모델이 생성한 결과나 검증된 품질 증거가 아니다.

동일 모델/온도/출력 상한/공개 상황/역할/페르소나/대화 기회에서 V2와 V3를 비교한다. 현재 모델 식별자는 ai.mjs를 기준으로 기록한다. 비교는 (a) 같은 입력으로 문구만 변경, (b) V3 문맥 회수까지 포함한 전체 후보로 나눠 원인을 구별한다. 전체 대국 A/B는 별도 실험이다.

제안하는 첫 실행은 대표 6사례 × 두 버전 × 2회 = 최대 24회 생성, 자동 재시도 없음이다. 비용 상한과 반복 수는 아직 사용자 승인/확정이 아니므로 실제 호출하지 않는다. 긴 대국·품질 검토용 추가 모델 호출도 포함하지 않는다.

사람 평가 후보: 질문 관련성·앞말 반영·상황에 맞는 짧고 긴 반응·역할 목표 관련성·공개 발언/후속 선택 연결을 각각 0(실패)/1(부분)/2(충족)로 판정한다. 악의 전략적 입장 변경은 곧 오류가 아니며, 무조건 정직하게 행동하도록 채점하지 않는다. 침묵은 맥락에 맞으면 통과다. 다섯 항목 합계 8/10 이상, 정보 경계/규칙/없는 사건 조작 0건을 사례 통과 후보 기준으로 제안한다. V2 대비 개선/악화 사례를 함께 보고하고, 표본이 작으므로 승률·사람 구별 불가능성의 통계적 증거로 쓰지 않는다. 실제 채택 기준은 실행 전 합의한다.

trace 후보는 gameId/stateVersion/actor/요청→검사→게시·폐기 단계이며 상세 사고 원문이 아니다. log는 오류 코드·대체 방식·허용 출처 검증 상태, metric은 입력/출력 토큰·호출 수·지연·반복/질문 회피율이다. 새 수집 기능이나 측정 성과가 구현됐다는 의미가 아니다. evidence는 모델의 사후 설명이고 진짜 의도·정답의 증거가 아니다.
