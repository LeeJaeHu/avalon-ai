# V3 로컬 게임 프로토타입

## 목표와 범위

사용자는 V3를 매 AI 행동에 맞춰 조립해 보내는 게임을 간단한 로컬 프로토타입으로 요청했다. 별도 Node HTTP 서버와 작은 HTML 화면을 만들고 기존 게임 엔진·Gemini 호출·V3 빌더를 재사용한다. 새 프레임워크/패키지/배포는 추가하지 않는다. 기본 사이트와 V1/V2 파일을 보존한다.

- 접속은 `127.0.0.1:5174`, 서버는 loopback에만 바인딩한다. 기존 5173 미리보기와 분리한다.
- 플레이어는 사람 1명·AI 4명. 역할 확인, 팀 초안/토론/재검토, 투표, 결과 확인, 원정, 암살, 종료까지 기존 규칙을 쓴다.
- 모델의 모든 행동에는 V3를 적용한다. 기존 scripted 시작 안내와 B 충신 계산기 우회를 로컬 V3 경로에서 제외한다. 키가 없을 때에는 명시적인 연습 모드다.
- 상태는 로컬 한 세션을 파일로 저장해 새로고침·서버 재실행 때 이어간다. 종료/새 판 때 게임 ID별 로그를 자동 저장한다. 비밀 역할·카드·evidence는 플레이 중 브라우저 응답에 넣지 않는다.
- 사람은 AI 생성 중에도 입력 가능하다. 버전이 바뀌면 이전 AI 응답을 폐기하고, 같은 상태의 중복 AI 요청은 한 호출로 제한한다. 지목 답장은 제삼자 이름보다 명시 replyTo를 우선한다.
- 자동 AI 연쇄 토론/추가 진행자 호출은 이번 간단한 범위에 포함하지 않는다. 원탁 토론 중 사용자가 추가 AI 의견을 요청할 수 있고, 투표 시작은 사람만 선택한다. 필수 행동은 자동으로 진행한다.

## 구현 전 검증 기준

1. 모의 Gemini가 받은 모든 생성 입력에 V3 버전의 실제 조립문이 있고 미치환 변수가 없음. CHAT/PROPOSE/VOTE/CARD/ASSASSINATE를 모의 판에서 검증한다.
2. 기존 V2 기본 동작과 검사 보존. 명시 답장 우선·비밀 경계·thinking 폐기·evidence 로그 분리 검증.
3. 로컬 API로 게임 완주·새로고침/재시작 복구·종료 로그·새 판 기록 보존 검사. 게시 전에 상태 버전을 재확인하며 사람 입력 중 낡은 AI 결과/중복 요청을 검증한다.
4. Host/Origin·콘텐츠 타입 확인과 요청 크기 제한, 서버용 비밀/프롬프트를 브라우저에 반환하지 않는지 검사한다.
5. 실제 브라우저에서 첫 화면·역할 확인·토론/선택 흐름을 확인한다. 자동 실제 모델 대국은 수행하지 않는다. 실제 연결 생성 검사는 별도로 요청한 최대 2회 범위의 사용자 응답에 따른다.

실행: `node prototype/server.mjs`, 단위/모의 통합 검사: `node --test prototype/*.test.mjs site/tests/*.test.mjs scripts/*.test.mjs`.

## 단순화와 한계

한 컴퓨터의 한 게임을 위한 프로토타입이며 여러 사용자/탭이 독립 게임을 만드는 서비스가 아니다. 파일 저장은 동기적 원자 교체로 처리한다. 악의 카드 선택은 모델에 맡기며 키 없음/장애의 기본 규칙은 실제 V3 품질과 구분한다. 실제 자연스러움·승률은 모의 판 완주로 검증하지 않는다.

## 구현·검증 결과 (2026-10-03)

- `prototype/server.mjs`와 `prototype/index.html`로 별도 서버/화면을 만들었다. 새 패키지나 Sites 배포 없음. 실제 AI 생성 때에만 옵션으로 `buildHumanlikeTurn`을 기존 `decide`에 전달한다. 기본 사이트 호출은 V2를 유지한다.
- `prototype/prototype.test.mjs`: 실제 전송 함수를 가로채 V3의 다섯 행동 입력/응답을 검사했다. 별도 로컬 API 연습 판은 완주·로그·새 판 보존·재시작 복구를 확인했다. 동시에 AI 요청을 두 번 보내도 한 호출만 하고, 그 사이 사람 채팅이 저장되면 이전 AI 결과를 폐기하는 테스트를 통과했다.
- 기존 답장 선택에서 플레이어 ID순으로 이름을 찾던 문제를 본문 등장순으로 보정했고, 명시적 replyTo 대상은 제삼자 언급보다 우선한다. 기존 V2/V3 모두에 적용되는 작은 라우팅 수정이며 배포는 하지 않았다.
- 최초 검사는 64/65였다. Node fetch가 사용자 지정 Host를 실제 요청에 반영하지 않아 Host 거부 검사가 200을 받았다. 낮은 수준의 `node:http`로 실제 Host를 보내도록 검사 수정 후 65/65 통과. 거부 응답에 게임 관찰값도 포함하지 않도록 보완했다.
- TypeScript --noEmit 통과. HTML 스크립트 구문 검사 통과. 최종 `git diff --check` 통과(기존 줄바꿈 경고).
- 브라우저 연습 모드에서 역할 확인→자동 AI 초안→질문→투표 시작→내 표 저장→전원 공개 결과를 확인했다. 역할 카드가 시작 직후 다시 열리는 문제를 화면 전환 처리로 수정했다. `docs/review-assets/local-v3-prototype-2026-10-03.jpg`는 검사 중 연습 화면이며, 수정 전 이름 선택 문제의 응답도 포함하므로 V3 모델 품질 예시가 아니다. 사용자용 시작 화면은 `local-v3-prototype-start-2026-10-03.jpg`다.
- 일반 실행에서는 5174/5180 바인딩이 EACCES로 거부됐다. 승인된 실행으로 127.0.0.1:5174 서버 시작을 확인했다. 외부 호스트에는 바인딩하지 않았다.

## 실제 모델 연결 상태

기존 Cloud Run 중계 서비스 주소 조회는 성공했다. 실제 생성 최대 2회 검사는 사용자가 승인했다. 그러나 자동 승인 검토가 Cloud Run 토큰 조회 및 `prototype/.env.local` 저장을 별개 자격 증명 작업으로 판단해 거절했다. 이 작업에 대한 별도 승인을 요청했으며, 승인 전 비밀값 조회/저장 및 실제 생성은 미실시 상태다. `prototype/live-check.mjs`는 명시적 2회 상한 설정에서만 실행하며 재시도하지 않는다.
