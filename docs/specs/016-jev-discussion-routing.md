# JEV 발언 라우팅과 기존 방식 비교

## 2026-10-04 운영 선택 기능 확장 — 구현 전 기준

사용자는 배포판에서도 JEV 사용/미사용을 선택해 경험하도록 요청했다. 두 방식 모두 기존 운영 Gemini 및 V2 프롬프트를 사용한다. 새 게임 생성 요청의 routingMode를 검증하고 판별 방식을 판마다 고정한다. 기존 판은 baseline으로 복구한다. 화면의 선택은 다음 새 게임에만 적용하고 현재 판의 방식도 표시한다. JEV를 선택할 수 있는 조건은 JEV 키 및 대화 모델이 모두 설정된 경우다. 연결 실패는 기존 규칙으로 대체하고 화면 안내와 기존 사건 로그에 남긴다.

자동 통과 기준: 잘못된 선택 거부(이전 판 보관 전에 검사), baseline에서 JEV 0회와 Gemini 생성 유지, jev에서 선택 주체의 Gemini 생성, WAIT 생성 생략, 키/응답 오류 대체, 공개 입력 경계 유지. 기존 규칙/로그 테스트와 타입 검사 및 운영 소스 빌드를 실행한다. 실제 모델은 합성 공개 질문으로 두 방식 각각 1회 이내 생성하는 연결 smoke만 진행하며 대화 품질/승률 평가로 표현하지 않는다. 중복/폐기 호출은 서버 로그에 남고 종료 JSON에는 게시된 사건만 포함되는 기존 제한을 유지한다.

## 목표와 범위

사용자는 JEV 발언자·응답 필요 판단을 적용하고 이전 방식과 비교할 수 있도록 요청했다. 공유 decide 경로에 선택 가능한 라우터를 연결하고 로컬 V3 화면에서 새 판의 baseline/shadow/jev 모드를 선택한다. Sites 경로는 서버 환경 설정으로 연결하되 배포는 이번 범위 밖이다. 역할 전략·대사·필수 게임 행동과 V2/V3 프롬프트는 보존한다. 자동 AI 연쇄 토론은 추가하지 않는다.

## 구현 전 동작과 검증 기준

- baseline: 현재 답장/이름/암묵 상대/순번 선택을 그대로 사용, JEV 호출 0회.
- shadow: 같은 공개 상태에서 기존 선택과 JEV 선택을 기록하되 실제 발언은 기존 선택만 실행. Gemini를 두 번 생성하지 않는다.
- jev: 명시 replyTo는 코드로 확정. 그 외에 JEV가 ai1~ai4/WAIT 중 선택한다. WAIT이면 Gemini 호출 없이 SILENCE. 없거나 잘못된 키, HTTP/네트워크/시간 초과/잘못된 응답은 기존 선택으로 대체. JEV는 요청당 1회, 3초 상한, 자동 재시도 없음.
- 모델은 jev-1.13.0, 질문 버전은 jev-discussion-v1로 고정한다. 공개 입력만 사용한다. 최근 8개 대화와 답장 연결, 최근 제안·원정 사실을 필드 허용목록으로 복사한다. 비밀 역할·known·미공개 표/카드·evidence·thinking을 복사하지 않는다.
- 같은 state의 독립 Choice 두 개: 다음 응답 후보/WAIT와 최근 대상 발언의 speechAct 추정. speechAct는 로그 분석용이며 사람 원문/태그나 플레이어 전략을 덮어쓰지 않는다. 명시 답장, 빈 시작, 비활성 상태는 호출하지 않는다.
- 각 판 모드는 생성 시 고정한다. 비교 기록에 gameId/stateVersion/메시지 ID/입력 SHA-256/기존 선택/JEV 선택/적용 선택/확신도/확률/모델·질문 버전/지연/input_tokens/추정 비용/오류·대체 상태를 보존한다. 비밀 키/프롬프트/모델 오류 원문은 기록하지 않는다. 대국 중 공개 API에는 개별 비교 판단을 노출하지 않는다.
- 선택→Gemini→게시 이전의 기존 버전/중복 요청 검사를 유지한다. Gemini 실패에도 앞서 발생한 JEV 사용량은 남긴다. 낡은 요청의 JEV 비용은 로컬 별도 시도 목록에 저장하고 게시 여부를 구분한다.

자동 검증: 기존 선택 일치, baseline의 0호출, shadow에서 기존 주체 유지, jev에서 선택 변경·WAIT의 생성 생략, 명시 replyTo 보호, 비밀 배정을 바꿔도 입력 일치, 잘못된 JSON/후보/분포/usage 및 401/429/503/시간 초과 대체, 동시 호출·사람 개입 시 낡은 결과 미게시, 실패 때 JEV 사용량 기록, 새 판/복구/설정 검증. 모의 응답으로 API 계약과 상태 경계만 확인하며 모델 품질을 입증하지 않는다.

## 비교와 평가

종료 로그의 routingAttempts는 동일 공개 입력에서 계산한 두 선택을 비교한다. `scripts/compare-routing.mjs`로 총 시도/성공/대체/불일치/WAIT/실제 게시/입력 토큰·비용·지연을 집계한다. 불일치는 개선율이 아니다. shadow는 기존 대화 궤적에서의 비교이고 jev를 적용한 별도 판은 이후 상황이 달라져 단순 승률 차이를 인과 효과로 해석할 수 없다. 과거 로그에는 JEV 판단이 없으므로 이를 복원했다고 표현하지 않는다.

초기 실제 평가 제안은 한국어 사례 30개×선택지 순서 2종×3회, 허용 후보 집합 일치율 90% 이상과 정보/직접 답장/중복 게시 위반 0건이다. 비용·범위·품질 기준은 확정되지 않았으므로 자동 유료 평가를 실행하지 않는다. 사용자 플레이로 발생한 실제 호출은 평가 실험과 구별한다.

공식 근거: https://docs.typesafe.ai/api , https://docs.typesafe.ai/primitives/choice , https://docs.typesafe.ai/models , https://docs.typesafe.ai/confidence , https://docs.typesafe.ai/model-jaggedness/jev-1.13 , https://github.com/typesafe-ai/skills/blob/main/skills/typesafe-ai/SKILL.md . 공식 가격 입력 $0.042/백만 토큰, 출력 무료(2026-10-03 확인). 추정 비용은 실제 응답 input_tokens로 계산한다. 한국어 품질·지연·정답률은 실제 평가 전 미확인이다.
