# 새 사건 뒤 AI 발언 누락 복구

2026-10-06. 사용자 관찰: 시작할 때만 AI가 말하고 이후에는 조용함. 최근 완료 판의 기존 events를 조회한 결과 두 번째·세 번째 팀 제안과 모든 투표/원정 결과에서 정상 JEV 응답이 WAIT였으며 Gemini 생성은 생략됐다. HTTP 오류로 인한 중단이 아니었다.

## 원인과 선택

진행자 입력은 이전 채팅에 초점을 맞추고 새 사건은 간접적인 proposal/quest 필드로 전달했다. 사건의 첫 반응과 이미 끝난 토론을 구분하지 않고 WAIT를 허용했다. WAIT를 받아 SILENCE를 적용하면 pendingDiscussion이 없어지고 수동 진행 정책에는 추가 대화 타이머가 없으므로 그대로 대화가 끝났다.

새 사건을 trigger.event와 최근 공개 사건으로 전달한다. 새 팀·공개 찬반 결과·원정 결과의 첫 응답은 발언자 네 명 중에서 JEV가 선택한다. 다음 발언부터는 WAIT를 다시 허용한다. 사용자 질문은 기존 응답 보장을 유지한다. 모든 플레이어를 강제로 순회하거나 자동 단계 이동을 복원하지 않는다. 연속 세 발언 상한을 유지한다.

Gemini 첫 반응은 CHAT 출력 계약으로 요청하며 구성 이유, 공개 찬반의 차이, 원정 결과가 의심/다음 팀에 주는 영향을 짧게 말하도록 안내한다. 사용자 v3.txt는 수정하지 않고 래퍼에서 요청 조건에 맞게 덧붙인다. SILENCE 등 계약 위반은 기존 두 회 상한 내에서 재시도하며 계속 실패하면 기존 오류 기록과 선택된 참가자의 오류 안내 발언으로 처리한다. 안내는 모델의 전략 분석으로 간주하지 않는다.

## 자동 검증과 통과 기준

- TEAM_DISCUSSION/VOTE_RESULT/QUEST_RESULT의 burst 0 첫 사건에서 Choice 후보에 WAIT가 없어야 한다. 유효 반응 후 WAIT가 복구되어야 한다.
- 채팅이 바뀌지 않아도 새 공개 사건이 입력되어야 하며 다른 참가자의 역할·생각·카드·추측 기록은 입력되지 않아야 한다.
- 잘못된 JEV WAIT/장애는 한 번 호출 후 기존 발언자로 대체한다. Gemini SILENCE 재시도 후 정상 CHAT이면 저장 가능해야 한다. 연속 실패는 두 번에서 멈추고 실제 선택 AI에 귀속된다.
- 사용자 응답, 수동 단계 버튼, 3회 상한, 구판 자동 진행, 비교 두 모드, 역할 추측 정보 경계를 기존 검사와 함께 통과해야 한다.
- 명령: 운영 소스에서 `node --test tests/*.test.mjs`, `node node_modules/typescript/bin/tsc --noEmit --incremental false`, Worker 빌드. 추가 UI/API 확인은 별도 로컬 DB와 모의 응답으로 수행한다.

형식·상태 검증은 실제 전략 품질 평가가 아니다. 유료 모델 평가 범위와 기준은 이번 요청에 지정되지 않아 호출하지 않는다. 실제 발언의 유용성은 새 판에서 확인이 필요하다. 첫 반응이 없던 사건에는 Gemini 호출 한 번이 추가되며 실패 시 기존 제한 내 재시도 비용이 발생한다. 한 판 실제 증가 비용은 미측정이다.
