# JEV 대화 멈춤 원인과 자동 복구

2026-10-06 사용자는 사람 발언에도 AI가 답하지 않고 다음 단계로 가지 않는 경우를 보고했다. 진행 도움에 의존하지 않는 것이 목표이므로 멈춤 원인을 찾아 고치도록 요청했다.

## 확인한 원인

운영 Worker 오류 로그를 먼저 확인하고, 오류가 아닌 정상 판단도 원인일 수 있어 최근 30분의 성공 요청으로 조회를 넓혔다. 사용자 판 `f8263d3c-3a88-492e-b873-5bceccf3242d`의 상태 버전 3/4에서 JEV는 responder=ai1, progress=WAIT, status=OK였고, 8/9에서도 AI 발언자와 WAIT를 함께 선택했다. `progressDecision`은 발언자와 무관하게 progress=WAIT를 SILENCE로 바꿨다. 즉 단계 이동 대기를 응답 중단으로 잘못 해석했다. 같은 판의 버전 46/47에서는 responder=WAIT, progress=WAIT가 반복됐다. 두 번 침묵하면 `conversationDueAt`이 null이 되어 다음 자동 판단이 영구히 없어졌다. 화면도 3번째 원정 팀 토론에 멈춰 있었다. 민감한 Worker 요청 헤더·채팅 원문은 문서에 복사하지 않았다.

추가로 입력 시작 시 클라이언트가 진행 중 요청을 abort했고 실제 취소 요청과 409를 확인했다. Worker가 취소되면 finally의 임대 해제가 끝나지 않을 가능성이 있다. 현재 판의 멈춤을 임대 잔존으로 확정한 것은 아니며 예방적으로 서버 요청을 끝까지 실행하고 상태 버전/클라이언트 epoch로 오래된 응답을 무시하도록 바꿨다.

## 선택한 수정과 검증 기준

- progress WAIT와 responder를 분리한다. 선택된 AI는 답변할 수 있고 단계 전환만 기다린다.
- 사람의 아직 답하지 않은 발언이 있으면 단계 이동보다 답변을 우선한다. responder WAIT면 기존 공개 주소 선택을 사용하고 Gemini 침묵도 한 번 재시도한다. 응답 생성 실패는 기존 오류 기록과 함께 실패 사실을 밝힌 공개 대체 발언으로 남겨 조용히 입력을 버리지 않는다.
- 두 번 대기 후 팀 토론/결과 확인은 자동 복구한다. 필요한 두 AI 발언이 부족하면 JEV를 추가 호출하지 않고 기존 발언자 선택으로 발언을 요청한다. 충분한 팀 토론이나 공개 결과는 엔진의 합법 후보에 따라 투표 예고 또는 CONTINUE로 이어진다. 투표 예고의 6초 유예/취소와 사람 미답변 보호는 유지한다. 사람 리더의 팀 선택·사람 표·임무 카드·암살 입력을 대신 제출하지 않는다.
- 이미 멈춘 conversationVersion=1 판도 같은 수정 코드를 적용받는다. 새 게임 생성이나 저장 데이터 마이그레이션은 필요 없다. 새로고침하면 저장된 상태에서 자동 일정을 다시 계산한다. JEV 화면의 진행 도움을 제거하고 baseline 수동 진행은 유지한다.
- 회귀 통과 기준: AI responder+WAIT는 CHAT, 사람 발언+WAIT/SILENCE는 유효한 답변, 반복 WAIT/네트워크 장애에서도 사람의 필수 게임 입력만 받아 자동 완주, 판별 호출 제한, 비밀 경계·유예·불법 전환·이전 판 호환 유지. 실제 확인은 별도 합성 판의 한 번 팀 토론에서 답변 후 수동 START_VOTE/CONTINUE 없이 VOTE 도달이다.
