# 원탁 중심 화면과 투표 전 토론

## 목표와 범위
팀 초안→토론/수정→투표 시작→공개 결과→결과 토론을 같은 원탁에서 진행한다. 개인 역할은 접어두고 참가자·현재 팀·대화·현재 행동을 가까이 둔다. 원정 결과는 대화 안에 남기고 모달을 제거한다. 기존 화면 및 관련 진행 코드는 `backups/ui-before-roundtable-2026-10-02/`에 복사해 보존한다.

사람 1명 게임의 속도 제어로 사람만 START_VOTE를 할 수 있다. 이는 리더 역할을 바꾸지 않는다. 팀 결정/수정은 현재 리더만 가능하다. AI 리더 팀은 사람의 REQUEST_REVISION을 받아 기존 PROPOSE 요청으로 다시 판단한다. 투표 시작 뒤에는 명단을 바꿀 수 없다. 토론 중 채팅과 기존 제한된 AI 발언을 허용하되 모델 호출을 무한 연쇄하지 않는다. 자유로운 AI 발언자 자기 선택과 전략 품질 개선은 이번 변경 범위 밖이다.

B 충신 리더의 초기 초안은 기존 계산기를 유지한다. 사용자가 명시적으로 재검토를 요청한 경우에는 대화를 읽지 않는 계산기로 재계산하지 않고 모델 PROPOSE로 판단한다. 키가 없거나 모델 실패 시에는 기존 규칙 AI로 대체하며 명단이 그대로일 수도 있다. 정책 버전은 2026-10-02.8이며 기존 .7 A/B 표본과 동일 조건으로 비교하지 않는다.

## 상태와 호환성
PROPOSE 행동은 TEAM_DISCUSSION으로 전환하고 DRAFT 제안을 저장한다. 같은 리더의 재제안은 같은 제안 ID/횟수의 초안을 수정한다. START_VOTE는 그 초안을 VOTING으로 확정하고 pendingDiscussion을 비운 뒤 VOTE로 전환한다. REQUEST_REVISION은 AI 리더만 재제안하도록 예약한다. 기존 저장된 VOTE/결과 상태는 그대로 이어간다. DB 스키마 변경은 없다.

공개 사건은 서버에서 구조화한 공개 텍스트·시각·버전만 저장해 observe에 노출한다. 개별 미공개 표·카드·역할은 사건으로 만들지 않는다. UI는 사건과 메시지를 시간순으로 합치고 replyTo 원문을 인용해 질문/응답을 연결한다. 과거 게임의 사건을 추정해 새로 생성하지 않는다.

## 구현 전 통과 기준
- TEAM_DISCUSSION에서 사람/AI 투표 거부. 자동 AI 진행은 토론 또는 요청된 팀 수정만 수행.
- 리더만 정확한 인원으로 초안 수정 가능. 수정으로 부결 횟수 증가 없음. START_VOTE 후 수정 불가.
- AI 리더 수정 요청, 중복 요청, 투표 개시, 일시정지와 재개, 결과 확인, 5회 부결/종료 경로 검사.
- 공개 사건에 역할표·미공개 표·개별 임무 카드 없음. 전원 투표 후 결과 사건 생성.
- 기존 버전 검사로 오래된 요청을 거부하고 모델 실패 대체 경로를 유지.
- Node 자동 검사, TypeScript, 빌드, 로컬 API 완주/개입 검사, 데스크톱·390px 화면 검증.

실제 모델 품질 평가는 자동 규칙 검사와 구분한다. 이번 유료 평가 호출은 실시하지 않으며 사용자 실제 플레이 후 질문 응답·반론·수정 이유와 선택 연결을 별도 평가한다.
