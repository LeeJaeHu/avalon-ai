# 사용자 프롬프트 V2

작성일: 2026-10-01. 사용자 수정본을 그대로 적용한다. 기존 정책 .4의 프롬프트는 `site/lib/prompts/v1.mjs`에 보존한다.

## 적용

- 원본 `아발론_프롬프트_작성중.txt`를 수정하지 않고 `site/lib/prompts/v2.txt`에 동결한다. `v2.mjs`의 TEMPLATE과 내용이 같은지 자동 검사한다.
- 역할·역할별 목표·공개 상태·본인 정보·이번 요청 자리표시자만 실행 시 치환한다. 요청에는 본인 이름, 필요한 팀 인원과 사용 가능한 플레이어 ID를 담는다.
- 지목할 때 별도 문구는 추가하지 않는다. 이름 기반 발언자 선택과 기존 직접 응답 재시도는 유지하되 재시도에도 같은 V2 본문을 쓴다.
- `thinking` 지시를 그대로 둔다. 반환 JSON을 받으면 허용된 행동 필드만 추출하고 thinking 및 기타 모델 필드를 버린다. 이후 모델 입력, 게임 상태, 화면, 종료 로그에 모델 thinking 값을 전달하지 않는다.
- 정책 `2026-10-01.7`, 프롬프트 `V2`를 신규 게임 설정·사건에 기록한다. A/B 원정팀 계산 정책은 유지한다. B 충신 리더는 기존 계산기를 사용하므로 해당 제안은 V2 모델 생성이 아니다.

## 검사와 한계

- 원문 일치·자리표시자 치환·지목 문구 미추가·V1 보존을 검사한다. 모의 모델 세 판을 종료까지 진행하고 모든 행동 종류, thinking 제거와 후속 입력 경계를 검사한다.
- 기존 규칙·AI·믿음·후보 계산·로그 검사, TypeScript 및 빌드, 로컬 API 종료·사람 끼어들기 검사도 실행한다.
- 모의 모델 통과는 실제 모델 품질 검증이 아니다. 실제 모델 최대 8회 검사 질문에는 별도 답변이 없었으므로 자동 유료 대국을 실행하지 않는다. 배포 후 사용자가 새 게임을 시작해 실제 플레이한다.
- 원문의 JSON 블록은 선택지와 설명이 들어간 출력 안내로 보존했다. 그 블록 자체가 유효한 JSON 예시는 아니므로 모델 형식 오류 가능성은 남는다. 실제 반환 JSON과 행동 합법성은 기존 서버 검증·오류 처리로 확인한다.
- 원문에는 이번 구성에 없는 퍼시벌·모르가나·모드레드·오베론 실수 설명도 있다. 실제 역할 배정은 기존 5인 구성을 유지하며 모델이 이를 혼동하는지는 실제 플레이에서 확인해야 한다.
- 최초 V2 생성 출력 상한은 300토큰이었다. 후속 형식 오류 보완에서 768토큰으로 늘렸고 중계는 최대 1,024토큰까지만 전달한다. thinking을 포함한 출력이 길면 여전히 잘릴 수 있으며 MAX_TOKENS 종료와 JSON 읽기 실패를 함께 관찰하면 OUTPUT_TRUNCATED로 구분한다. 이전 INVALID_JSON의 실제 잘림 여부는 메타데이터가 없어 미확인이다.
- 프롬프트가 바뀐 전후 데이터는 같은 조건의 A/B 표본으로 섞지 않는다. 진행 중 판을 이어가면 게임 생성 버전과 사건 실행 버전이 달라질 수 있으므로 V2 검사는 새 판에서 시작한다.

## 2026-10-01 실제 플레이 오류 보완

- 이름 없는 “말하신/하셨/당신…” 문장은 직전 메시지의 AI(명시 replyTo가 있으면 해당 메시지 작성자)에게 전달한다. 명시 이름을 우선한다. 일반 의미 추론은 아니며 대상이 불명확한 여러 화자 지칭은 남은 한계다.
- 개인 정보에 본인 ID·이름, 요청에 답할 메시지와 작성자 이름·허용 행동·유효 JSON 예시를 넣는다. V2 원문은 유지한다. 특정 지목 상황에 추가 본문을 붙이지 않는다.
- Vertex responseSchema로 요청별 type·선택값·팀 크기·대상을 제한한다. CHAT의 SILENCE 분기가 있으므로 text·speechAct는 스키마에서 선택 필드로 두고 CHAT 반환 시 서버에서 필수·길이·태그를 확인한다.
- 다른 행동 종류, 잘못된 채팅 형식, 본인 이름을 타인 발언자처럼 부르는 일부 표현은 한 번 재시도한다. JSON 읽기 실패도 기존처럼 재시도한다. 지속 오류 시 실제 응답자·요청/반환 종류·완료 사유·문자 수를 내용 없이 기록한다. 예외 코드만으로 장문의 출력 잘림을 추정하지 않는다.
- Google 공식 [출력 스키마 enum 예제](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/samples/generativeaionvertexai-gemini-controlled-generation-response-schema-4?hl=en)를 참고했다. 중계가 responseSchema를 그대로 전달하도록 실제 Cloud Run도 수정했다.
- 자동 검사 34/34와 TypeScript·빌드 통과. 사용자 승인 범위에서 첫 실모델 3회(채팅 2건 HTTP400, 투표 1건 통과), 추가 2회(채팅 2건 통과)를 수행했다. 빈 문자열 enum 제거 후 채팅이 성공했으므로 해당 제약을 원인으로 추정한다. upstream 오류 본문은 보관하지 않았으며 정확한 거부 문구는 미확인이다.
- 투표 입력/출력 2,807/100토큰, 암시적 질문 2,619/123토큰, 자기 인식 2,978/106토큰. 실제 응답 코드·형식·응답자와 자기 혼동 검사를 통과했다. 각 사례 1회이므로 반복 품질·승률 개선·비용 절감으로 해석하지 않는다. 총 실제 생성 요청 5회 중 HTTP400 2회 포함, 추가 유료 대국은 미실시다.

## 500 장애 복구

일시적인 HTTP500/502/503/504·네트워크·시간 초과는 한 번 재시도한다. 모델·출력 검증이 계속 실패하면 채팅은 기존처럼 건너뛰고, PROPOSE/VOTE/CARD/ASSASSINATE는 기본 규칙 행동으로 진행한다. 저장·DB 오류는 이 대체 처리 대상이 아니다. 대체 전 현재 버전을 다시 확인해 일시정지·사람 채팅·새 행동을 덮어쓰지 않는다.

게임 화면에 기본 규칙으로 처리했다는 안내를 보여주고 사건에 `aiMode: fallback`, `reason: MODEL_FAILURE`, 오류 코드와 실행 버전을 저장한다. AI 품질 분석 시 정상 모델 행동과 대체 행동을 구분하며 장애·복구율도 보고한다. 모델 실패를 기본 전략의 성공으로 기록하지 않는다.

재현 명령: `node tests/model-outage-server.mjs`(8798), 로컬 Wrangler 실행에 `--var VERTEX_PROXY_URL:http://127.0.0.1:8798/generate --var VERTEX_PROXY_TOKEN:outage-test-only` 추가, `AVALON_URL=http://127.0.0.1:8799 node tests/api-model-outage.mjs`. 상시 500에서도 종료·대체 투표·오류 기록·복구 안내를 확인한다. 외부 모델 호출은 없다.
