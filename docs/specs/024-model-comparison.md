# Gemini 단독 / JEV + Gemini 비교

2026-10-06. 이후 두 구성을 비교할 수 있도록 구현 요청. 실제 유료 실험은 이번 범위에 포함하지 않는다.

- 새 게임 설정에 두 프리셋과 사용자 설정을 제공한다. Gemini 단독은 baseline/gemini, 혼합은 jev/jev이며 대화는 공통 Gemini다. Gemini 단독의 발언자 선택은 기존 규칙임을 명시한다.
- 프리셋은 NEW에서 서버가 두 모드를 함께 확정한다. 현재 판에는 영향을 주지 않는다. JEV 미연결 시 혼합 모드는 실패하고 현재 판을 보존한다. 기존 API의 개별 모드 설정은 유지한다.
- 새 판은 공통 proposalPolicy A, 프롬프트/모델/진행 규칙을 유지한다. 비교 버전과 구성은 aiConfig 및 종료 로그에 보존한다. 오류 시 대체 행동 기록은 그대로 남긴다.
- 내려받은 종료 로그를 로컬 CLI로 비교한다. 게임 ID 중복은 제외하며 충돌 사본은 거부한다. 완료/재시작/연습/과거 조건 미확인/사용자 구성을 구분한다. 비용 누락은 0으로 간주하지 않는다.
- 조건별 집계는 사용자 역할·플레이어 수·모델/프롬프트/정책·역할 추측 버전 등을 구분한다. 지연은 호출별 관측값이며 사용자 체감 대기나 한 판 시간과 같지 않다. 승률·역할 추측 점수는 게임 전체 품질의 인과 지표가 아니다.

검증 기준: 두 프리셋 매핑/잘못된 입력, 모의 모델 호출 분리, 로그 구분·중복·불완전 사용량·재시작·점수 미제출, 기존 엔진 테스트, TypeScript/빌드, UI 프리셋과 다음 판 적용을 검사한다. 실제 모델 품질 비교와 유료 호출은 미실시로 남긴다.

사용법: 설정에서 AI 비교 모드 선택 → 새 게임 → 종료 후 게임 로그 다운로드. 다른 모드도 반복 후 `node scripts/compare-models.mjs <로그1.json> <로그2.json>` 실행. 출력은 개인정보/대화 원문 없이 집계와 판별 요약을 포함한다. 두 모드를 번갈아 진행하고 역할별 표본수를 함께 확인한다.
