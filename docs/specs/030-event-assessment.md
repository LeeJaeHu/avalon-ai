# 리더의 팀 제안 전·다른 AI의 제안 후 상황 판단

작성일: 2026-10-07. 구현 전 검증 계약.

## 동작과 경계

- 현재 일정은 leader-before-team-v2다. AI 리더는 제안/수정 전에 판단하고 나머지 AI는 TEAM 발표 후 판단한다. 원정 결과 뒤 THINK는 생성하지 않는다. 진행 중 구판은 새 일정으로 이어가며 바뀐 정책 판은 비교에서 제외한다. event-assessment-v1 출력 계약은 유지한다.
- AI 리더의 제안 기회에 본인1회, 발표 후 나머지 AI3회다. 사용자 리더는 발표 후 AI4회다. 채팅이나 JEV 선택보다 먼저 기존 ADVANCE/리스 흐름으로 순차 처리한다. 사람이 추가 채팅·정지·팀 수정으로 상태를 바꾸면 진행 중 결과는 기존 버전 검사로 폐기한다. 새 팀 수정은 이전 큐를 새 사건으로 대체한다.
- 입력은 공개 기록, 본인 역할/합법 지식/본인 카드·행동, 본인 이전 판단만이다. 다른 AI의 판단, 미공개 표/카드, 전체 역할표를 전달하지 않는다.
- 출력은 상황 요약, 본인 진영의 유불리(FAVORABLE/BALANCED/UNFAVORABLE/UNCERTAIN)와 근거, 발언 계획, 다음 행동 계획이다. 유불리는 모델 자기보고이며 보정된 승리 확률이나 실제 JEV 선택 이유가 아니다. 각 텍스트는 1~600자, 발언 계획은 말할 필요가 없으면 그 이유를 기록한다.
- 악끼리 팀을 피하기, 기만, 실패 카드 중복 위험, 불리한 팀에 대한 설득은 상황에 따라 비교한다. 특정 전략을 항상 정답으로 강제하지 않는다. 멀린 은폐와 암살 단계도 고려한다.
- 최신 개인 판단은 본인 JEV(행동/발언 의사)와 Gemini 대화 입력에만 제공한다. 공개 관찰/중립 발언 라우터에는 내용이 없다. 공개 발언 필요성과 화자 선택 정책 자체는 이번 변경 범위에 포함하지 않는다.
- 한 요청당 모델 호출 1회, 자동 재시도 없음. 생성/형식 실패도 사건별 처리 완료로 기록하고 기존 JEV 입력으로 진행한다. 요청 실패가 반복 진행을 막지 않는다. 실제 모델 판만 활성화하며 모델과 추론 수준은 해당 판의 기존 설정을 사용한다.
- THINK는 공개 채팅·사건·대화 횟수·게임 단계를 변경하지 않는다. 진행 중 판단은 다음 단계 이동을 막으며 완료 후 기존 토론으로 돌아간다.

## 자동 검사와 통과 기준

2026-10-07 판단 시점 변경 설계: AI 리더는 PROPOSE에 앞서 본인만 판단한다. 첫 제안·부결 후 리더 교대·다음 원정·팀 재검토마다 한 번 처리하고 같은 제안 기회에서 중복 생성하지 않는다. 팀 발표/수정 후에는 리더를 제외한 AI만 판단한다(사용자 리더면 AI4명). 원정 결과 후 THINK는 제거하고 공개 결과 토론은 유지한다. 개인 JEV/채팅/행동은 이전 판단을 현재 공개 사실로 재검토한다. 새 scheduleVersion으로 조건을 구분하고 진행 중 구판의 결과 후 큐와 제안 후 리더 큐를 정리한다.

구현 전 통과 기준: 리더 선판단→PROPOSE→다른 AI 판단 순서, 사용자 리더4명/AI 리더 나머지3명, 같은 기회 중복 없음, 부결/다음 원정/수정의 리더 재판단, 결과 후 THINK0회와 최종 역할 추측 정상, 무효/실패/오래된 결과 및 비밀 경계 보존을 검사한다. 현재 별도 유료 품질 평가는 미실시하며 전체 Node/TypeScript/로컬 API/Worker 빌드 후 배포한다.

2026-10-07 막판 정체 노출 설정 설계: 새 게임 설정 `endgameExposureAllowed` boolean을 추가한다. UI 이름은 '막판 정체 노출 허용', 기본 OFF이며 다음 새 판부터 고정 적용한다. ON은 즉시 원정/부결 패배가 걸린 막판에 노출을 감수하는 승리 우선 판단을 허용하고 OFF는 막판에도 공개 입장/은폐와 대안을 비교한다. OFF도 일부러 패배하거나 반대를 금지하는 규칙은 아니다. 기존 미기록 판은 기존 위험 판단을 유지하기 위해 ON으로 해석하고 UI는 미기록으로 표시한다. 개인 THINK/CHAT/JEV에 같은 설정을 전달하고 로그·비교 조건에 포함한다. 설정 변경은 추가 모델 호출/동료 조율/역할 맞추기 시점 변경을 만들지 않는다.

설정 구현 전 통과 기준: 기본/ON/OFF/잘못된 타입 검증, 새 판 저장/재조회, 개인 판단·채팅·JEV 입력의 동일 설정 및 ON/OFF 지침 차이, 구판 호환과 타인 비밀 비노출, 비교 조건 분리. 기존 모의 API 흐름에서 NEW·GET을 검사하고 전체 Node/TypeScript/Worker 빌드 후 배포한다. 실제 모델이 지침을 항상 따르는지는 별도 평가 대상이다.

2026-10-07 공개 입장과 행동 연결 후속 설계: 개인 판단의 발언 계획을 실제 발언으로 간주하지 않는다. 개인 JEV 입력에 본인의 현재 팀 제안 이후 공개 발언과 이전 공개 발언을 분리해 전달한다. 멀린/악은 공개 근거 없는 눈에 띄는 행동의 노출 위험과 덜 노출되는 합법 대안을 비교하되 즉시 패배·5번째 부결의 위험을 우선 검토한다. 공개 토론에서 필요한 우려는 투표 전에 표현하며 타인의 질문을 본인의 발언으로 회상하지 않는다. 중립 라우터는 공개 정보만으로 성공 팀 교체 등의 아직 해소되지 않은 쟁점에 발언 기회를 고려한다. 사적 계획을 라우터에 전달하거나 발언/찬성을 강제하지 않는다. 기존 호출 흐름과 후보를 보존한다.

구현 전 통과 기준: 현재 제안 전후 본인 발언 분리, 타인의 비공개 표/판단 비노출, 발표되지 않은 계획을 발언으로 취급하지 않는 지침 전달, 멀린의 2승0패·2패·5회 부결 입력 및 모든 합법 찬반 보존, 성공3회 뒤 실제 다음 단계 전달을 자동 검사한다. 모의 CHAT/JEV 경로에 새 입력이 전달되는지도 확인한다. 실제 행동 은폐 품질은 이 검사로 입증하지 않으며 별도 유료 평가는 이번에 실행하지 않는다.

구현: `public-stance.mjs`의 공통 지침을 개인 상황 판단/Gemini 발언/JEV 행동 선택에 전달한다. TEAM 공개 사건에는 당시 공개 메시지 수 `messageCount`만 추가하며 그 인덱스로 본인 발언의 제안 전후를 나눈다. 기존 메시지는 version이 없어 시각만으로 순서를 추정하면 같은 밀리초에서 오분류될 수 있어 인덱스를 사용했다. 구판의 사건 경계가 없으면 UNAVAILABLE로 표시하고 미분류 본인 발언을 전달한다. 중립 라우터는 비공개 계획 대신 공개된 팀 변경 쟁점만 고려한다. 지침은 선택을 유도하며 강제 발언/투표 대체 로직은 없다. 판단용 추가 호출은 없지만 입력 토큰과 실제 발언 수에 따른 비용/지연 변화는 미측정이다.

## 관측

trace: 공개 사건 ID → AI/THINK/source state version → model_usage → events.THINK의 eventAssessment.status(OK/FAILED/NO_MODEL) → 해당 개인 JEV 입력. JEV selection 및 사용량에는 assessmentEventId/assessmentSourceVersion을 기록해 참조를 연결한다. events에는 검증된 판단/상태를 비공개 종료 로그용으로 기록한다. 오류 코드와 호출 비용·지연은 기존 ai_failures/model_usage에 기록한다. 비교 조건에 assessmentVersion을 추가해 이전 조건과 구분한다.
