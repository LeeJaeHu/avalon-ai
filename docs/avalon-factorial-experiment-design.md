# 아발론 보조정보와 JEV 비교 실험 설계

작성일: 2026-10-04 한국 시간. 설계 제안이며 실험 실행·우위 판정 결과가 아니다. 이번 요청은 보조지표 제공 여부와 JEV 행동 제어 여부를 비교하고, 두 실험을 함께 해도 되는지 판단하는 것이다. 두 요소를 네 조합으로 무작위 배정하면 각각의 효과와 상호작용을 비교할 수 있다. 목표·처치 범위·예산·채택 기준은 사용자 확인 전까지 확정하지 않는다.

## 현재 구조와 이전 논의

- `site/lib/ai.mjs`의 V2 입력에는 `roleClues`와 `evilBelief`가 함께 들어간다. 기존 `proposalPolicy=A/B`는 정보 제공 여부가 아니라 팀 제안 결정 방식을 바꾼다. A는 모델 선택, B는 충신 AI 리더의 초기 제안을 계산기로 선택한다. 재검토 요청은 모델에 맡긴다. 로컬 V3 빌더가 전달되는 경로는 기존 B 계산기 분기를 건너뛰므로 V2/V3를 같은 처리로 간주하면 안 된다.
- `docs/specs/016-jev-discussion-routing.md`: JEV는 발언자·응답 필요를 선택한다. 명시 답장은 코드가 우선하고, WAIT는 Gemini 생성을 생략한다. 전략 목적·팀·투표·카드·암살은 JEV 제어 범위가 아니다. shadow는 기존 선택을 실제 적용하면서 JEV 선택만 함께 기록한다.
- 이전 채팅 「아발론 플레이어 악 확률모형 추가」에서 사용자가 가정 계수의 학습 전후 실험 설계와 개선 지표를 요청한 내용을 확인했다. `docs/specs/005-belief-learning-experiment.md`의 Brier 평가는 확률모형 품질을 다루며 AI에 정보를 주는 효과와 다르다.
- 「논문 3편 정리와 AI 개선안」 및 `docs/avalon-ai-evaluation-and-decision-design.md`에는 원문 기반 모델 판단 / 추론 보조 / 코드 행동 선택의 A/B/C 제안이 있다. `docs/specs/006-team-choice-ab-experiment.md`에는 실제 팀 선택 A/B의 분모·역할·중단·표본 수 한계가 정리돼 있다.
- 자료 구조: 판 상태는 `gameId`별 역할·제안·표·원정·승패, 사건은 판+상태 버전별 행동, 라우팅 시도는 요청별 선택·적용·오류·사용량이다. 한 판에 여러 사건/시도가 있으므로 조인으로 행이 늘어난 것을 독립 표본 증가로 세지 않는다. 실제 데이터의 기간·판 수·누락률·기준값은 이번에 조사하지 않았다.
- 최근 일지에는 로컬 JEV 비교 서버가 Gemini 미설정 연습 모드였던 확인 기록도 있다. 실제 비교 시작 전에 실행 모드를 다시 확인한다. 규칙 연습 판은 모델 실험의 표본에 넣지 않는다.

## 처치를 먼저 고정

보조정보의 최초 제안 범위는 `evilBelief` 제공 여부다. `roleClues`까지 제거한다면 이는 확률만의 효과가 아니라 추론 보조 묶음의 효과다. 팀 계산기 사용은 정보 제공과 별도 처치다. 사용자가 범위를 선택하기 전에는 어느 것도 확정하지 않는다.

정보 미제공 조건에서도 자기 역할·시작에 합법적으로 아는 정보·공개 기록·규칙·합법 행동 목록은 동일하게 보존한다. 미제공은 모델 입력에서 선택한 파생정보를 빼는 것이며, 평가용으로 서버가 계산하는 것까지 금지할 필요는 없다. 파생정보가 다른 요약·프롬프트·evidence 경로로 새지 않는지 검사한다. 원문 이력의 절단, 출력 한도, 온도, 페르소나, 모델·프롬프트 버전은 고정한다. 보조정보의 추가 입력 토큰은 해당 기능의 실제 비용으로 포함한다.

JEV는 현재 구현된 발언 라우팅만 최초 실험 대상으로 제안한다. 전략·행동 목적까지 맡기는 후보는 아직 다른 처치이며, 역할별 목표·비밀정보 경계·새 실패 경로를 정의한 뒤 별도 실험으로 다룬다. 지금 라우팅 결과로 확대 범위의 효과를 주장하지 않는다.

기존 팀 계산기 A/B는 최초 실험에서 A로 고정하는 안을 권한다. 원래 A/B를 동시에 유지하면 요인이 세 개가 되어 완전 비교에는 8조합이 필요하고, B가 모델 판단을 우회해 보조정보 효과가 희석될 수 있다. 기존 실험을 바꾸는 구현은 이번에 하지 않는다.

## 두 요소를 함께 비교하는 방법

| 조건 | 보조정보 | 발언 라우팅 |
| --- | --- | --- |
| C00 | 미제공 | 기존 코드 |
| C10 | 제공 | 기존 코드 |
| C01 | 미제공 | JEV |
| C11 | 제공 | JEV |

새 판 시작 시 네 조건을 원칙적으로 같은 비율로 무작위 배정하고 판 종료까지 유지한다. 모델·프롬프트·규칙·UI·계산기 정책을 고정하고 시간대/세션, 사람 역할, 시작 리더를 사전 조건으로 균형 배정한다. 행동마다 정책을 바꾸면 앞 행동의 영향이 남으므로 서로 독립인 A/B로 취급할 수 없다. 같은 판 안 AI들의 행동은 서로 영향을 주므로 실제 서비스 경험 실험은 판 전체를 하나의 배정 단위로 삼는다.

각 조건의 동일 지표 평균을 Y00,Y10,Y01,Y11이라 할 때:

- 기존 라우팅에서 정보 효과: Y10−Y00. JEV에서 정보 효과: Y11−Y01.
- 정보 미제공에서 JEV 효과: Y01−Y00. 정보 제공에서 JEV 효과: Y11−Y10.
- 균등 배정에서 정보 평균 효과: [(Y10−Y00)+(Y11−Y01)]/2. JEV 평균 효과도 같은 방식으로 계산한다.
- 상호작용: (Y11−Y10)−(Y01−Y00). JEV의 효과가 정보 여부에 따라 달라지는지 본다. 비용·오류처럼 낮을수록 좋은 지표는 방향을 맞춰 해석한다.

상호작용이 중요한 경우 평균 효과만 보고 둘 다 채택하지 않는다. 예를 들어 JEV가 정보 없을 때만 도움을 주면 특정 조합을 선택하는 것이 적절할 수 있다. C00 대 C11만으로는 묶음의 우열만 알 수 있고 개별 원인은 분리할 수 없다. 표본이 작으면 한 요소를 고정한 두 집단 실험을 먼저 할 수 있지만 그 결과는 고정한 조건에서의 효과이며 조합 효과를 보장하지 않는다.

무작위 배정 전 사용자가 JEV 모드를 직접 선택한 과거 판은 탐색 자료다. 모드 선택 이유·시간·숙련도 등이 달라질 수 있어 무작위 A/B의 인과 결과로 합치지 않는다. 버전 변경 전후 판도 분리한다. 명시적으로 JEV를 선택하는 현재 화면은 사용성을 확인하는 기능이며 블라인드 실험 화면은 아니다.

## 측정 목표별 지표 계약

주 지표는 아래 두 목표 중 사용자 우선순위에 맞춰 하나를 사전 선택한다. 임의 가중 합산 점수를 만들지 않는다. 소유자가 채택 판단을 맡으며 기준값·의미 있는 최소 개선폭·허용 악화폭은 현재 미확인이다.

| 지표 | 정의와 자료 | 용도와 한계 |
| --- | --- | --- |
| 플레이 재미 점수 | 정상 종료와 중단 직후 동일 문항 ‘이 판이 재미있었나요?’ 1~7점. 사람-판별 한 응답, 조건별 평균과 차이. 모든 배정 판의 응답 요청 수·응답률 및 중단률도 함께 보고. 미응답을 0점으로 대체하지 않음. | 서비스 경험 목표의 주 지표 후보. 현재 설문 없음. 자연스러움은 별도 진단 문항으로 분리. 승패 만족·역할·플레이 순서 영향을 고려. 한 사람의 반복 자료는 그 사람에게만 적용. |
| 대상 AI 진영의 최종 승률 | 고정 상대 정책을 둔 평가에서 대상 AI 한 자리만 보조정보 처치를 변경. 암살까지 정상 종료된 판 중 대상이 속한 진영이 이긴 판 비율. 충신·멀린·암살자·하수인을 분리하고 사전에 정한 역할 비중으로 표준화. 중단/오류 판은 별도 보고하며 전체 시작 판의 승리 도달률도 확인. | 전략 능력 목표의 주 지표 후보. JEV는 중앙 라우터이므로 전체 라우팅을 함께 바꾸면 다른 AI에게도 효과가 가는 시스템 처치임을 명시해야 함. 개인 AI 능력과 시스템 효과는 별도 실험으로 분리. |
| 맥락에 맞는 응답 비율 | 독립 평가 사례에서 정한 허용 발언자 집합/WAIT, 질문 내용 관련성, 중복 없는 응답을 모두 만족한 기회 / 사전 정의된 전체 응답 기회. 발언이 게시된 경우만 분모로 삼지 않고 WAIT·미응답도 포함. 판 평가에서는 판별 비율 평균, 유효 기회 0인 판은 해당 없음. | JEV 진단 지표. 허용 후보는 복수 가능하며 답해야 하는데 WAIT이면 실패, 조용해도 되는 상황의 WAIT는 통과. 적절한 발언자 선택과 Gemini 답변 내용 점수를 별도로 보존해 원인을 구분. 라벨 평가자 간 불일치도 기록. |
| 충신 리더 전원 선 팀 제안율 | 충신 AI 리더가 악 0명인 합법 팀을 제안한 횟수 / 해당 리더의 모든 합법 제안 횟수. 부결 포함, 판별 비율 평균. 실제 역할표는 사후 채점에만 사용. | 정보 제공의 선택 진단. 정보 획득을 위한 위험 감수도 있어 유일한 정답/주 성과로 쓰지 않음. 멀린·악·사람 제안은 별도 집계. |
| 오류·중단·응답 지연·비용 | 실패/대체 요청 수와 분모, 중단 판/전체 배정 판, 응답 기회 시작→유효 게시까지 지연 p50/p95와 응답 누락 비율, 판당 전체 호출 비용. 실패·재시도·폐기·JEV+Gemini 호출 포함. WAIT는 게시 지연 표본이 아니며 성공 답변의 0ms로 넣지 않음. | 채택 보호 지표. 짧은 판·무응답 증가로 비용/지연이 좋아 보일 수 있어 종료·응답률을 함께 봄. 라우팅 API 지연과 사용자가 체감하는 전체 지연을 구분. |

규칙 위반·관찰 범위를 넘은 입력·미래 사건 사용·낡은 응답 게시는 자동 검사의 필수 통과 대상이다. 비밀을 정체 공개 발언으로 누설하거나 없는 사건을 지어내는 내용 오류는 별도 사람 평가가 필요하다. 규칙 통과만으로 내용 품질을 보장하지 않는다. 심리전의 의도적 거짓말을 무조건 오류로 채점하지 않는다.

**주 지표로 부적합한 후보:** 모든 AI를 함께 바꾼 판의 선 승률을 전체 AI 능력으로 해석하는 것, 발언량, JEV와 코드의 불일치율, JEV confidence, 전체 투표를 독립 표본으로 센 정확도. 선/악 승률은 서로 보완값이고, 많은 말·다른 선택·높은 confidence가 더 좋은 플레이를 의미하지 않는다.

**Brier 점수의 위치:** 같은 공개 기록에서 보조모형 확률 p와 실제 악 여부 y의 (p−y)²를 비교하면 확률 품질을 평가할 수 있다. 같은 모형을 양쪽에 그대로 사용하면서 전달만 끄면 모형의 예측값은 바뀌지 않으므로 Brier는 제공 효과의 주 지표가 아니다. AI 자체의 확률 판단을 비교하려면 양쪽 모두 같은 형식으로 확률을 출력하게 하는 별도 평가 계약이 필요하다.

## 실행을 세 단계로 나누기

1. 자동 검사: 네 배정의 생성·판별 고정·잘못된 설정 거부, 입력 제공/제거, 역할 정보 유지, baseline의 JEV 0회, WAIT와 필수 행동 구분, 명시 답장 우선, 키/HTTP/JSON/시간 초과의 대체와 기록, 동시 요청/사람 개입으로 낡은 결과 미게시를 반복 가능한 기존 Node 테스트 흐름으로 확인한다. 실패하면 수정 후 해당 검사를 재실행하고 실제 평가로 넘어가지 않는다. 현재 정보 미제공 스위치와 네 조건 자동 배정은 미구현이며 이번 설계에서 검사를 실행하지 않았다.
2. 같은 상태 평가: 개발 자료와 분리한 한국어 사례를 유형별 준비한다. 직접 질문·단순 이름 언급·간접 반박·여러 답변 가능·이미 답한 질문·정당한 침묵·첫 원정/실패 이후/5번째 제안을 포함한다. 각 상태에서 네 조건에 동일한 허용 관찰을 공급하고 실행 순서를 무작위화하며 모델 반복 횟수를 고정한다. 최초 기회의 발언자·WAIT를 먼저 평가하고 실제 Gemini 내용/후속 판단은 별도 평가한다. 같은 상태의 반복 출력을 독립 새 사례로 세지 않는다. 상태·원본 판 단위로 자료를 분리하고 불확실성을 계산한다.
3. 전체 판 평가: 서비스 경험은 네 조건 전체 AI에 적용한 판을 무작위 배정하고 설문·응답·진행·비용을 비교한다. 전략 검증은 대상 한 자리의 정보 처치와 고정 상대를 먼저 비교하고, JEV는 별도 시스템 라우팅 평가를 한다. 동일 역할 배정·시작 리더·상대 정책의 조건 묶음을 만들되 서로 달라진 상태에 같은 행동 원문을 강제하지 않는다. 게임 시드는 외부 모델 출력 재현을 보장하지 않는다. 조건별 반복과 무작위 실행 순서가 필요하다.

shadow는 같은 공개 입력에서 두 선택의 차이를 찾아 사례를 만드는 데 유용하다. 실제 적용 후 대화·게임 결과가 달라지는 효과, 채택 후 비용 절감, 승률 효과를 직접 추정하지는 못한다. shadow는 추가 JEV 호출의 지연·비용도 발생한다.

## 분석과 채택 규칙

- 네 조건의 표본 수·역할·시작 리더·모드·버전·누락률을 먼저 점검한다. 예상 배정 비율 불일치나 특정 조건의 로그 누락이 크면 원인을 해결하기 전 우위 판정을 보류한다.
- 게임 경험 지표는 판/세션/사용자 의존성을 반영한다. 같은 사람의 반복 판은 독립 사용자 수를 늘리지 않는다. 단일 사용자 평가에서는 세션별 균형 무작위 순서와 학습/피로 영향을 기록하고 개인 내 비교로 표현한다. 같은 상황을 네 번 사람에게 재연하면 답을 기억하는 효과가 생기므로 온라인 블라인드와 같은 입력 오프라인 평가를 구분한다.
- 오류·JEV 대체가 난 판도 원래 배정된 조건에 포함하는 분석을 주 분석으로 한다. 성공적으로 JEV가 적용된 판만 고르면 잘 작동한 조건을 사후 선택한다. 실제 적용 횟수·대체율은 보조 분석에 사용한다.
- 판별 지표를 먼저 만들고 95% 구간과 효과 크기·분모를 함께 보고한다. 짝지은 시나리오는 묶음별 차이, 실제 반복 플레이는 사용자/세션 상관을 반영한다. 관련 사건 수를 독립 판 수로 취급하지 않는다.
- 주 지표, 정보/JEV 효과 중 어떤 검정을 확증할지, 상호작용의 탐색/확증 여부, 비교 횟수에 따른 오류 통제 방법을 사전에 정한다. 모든 조합을 여러 지표로 뒤져 유리한 결과만 채택하지 않는다. 후보 선택 후 새 보류 자료에서 선택 조합 대 기준선의 별도 확증을 하는 방법도 가능하다.
- 확정할 규칙의 형태는 ‘의미 있는 최소 개선폭을 충족하는 효과와 불확실성 근거 + 사전 지정한 보호 지표 악화 한도 충족’이다. 비용 목표라면 품질의 비열등성 허용폭을 먼저 정하고 그 범위를 지키면서 전체 비용/지연 감소를 본다. 유의하지 않다는 사실만으로 품질이 같다고 결론 내리지 않는다.
- 신뢰구간이 넓으면 결론은 우위 미확인이다. 당장 필요한 선택은 더 단순하고 비용이 낮은 조건을 잠정 유지할 수 있지만 통계적 동등성 입증과 구분한다. 명백한 규칙/정보 경계 실패는 해당 실행을 중단하고 원인·재현 근거를 남긴다.

## 표본 수와 운영 기록

현재 네 조건의 분산·기준값·상관·예산이 없어 확정 판 수를 제시하지 않는다. 동일 상태 사례는 대화 품질 파일럿, 소수 판은 계측·분산 파일럿으로 쓰고 통계적 승률 증거로 표현하지 않는다. 파일럿 이후 주 지표·최소 개선폭·검정력·중단률·반복 사용자 상관·다중 비교를 반영해 필요 표본 수와 종료 시점을 정한다. 네 조건으로 나눠도 평균 주효과는 두 조건씩 합쳐 비교할 수 있지만 상호작용·개별 조합 차이는 더 많은 자료가 필요하다. 기존 Spec 006의 두 집단 승률 표본 예시를 네 조건에 그대로 대입하지 않는다. 중간에 유의해 보인다는 이유로 임의 종료하지 않는다.

trace는 실험 ID→판 ID→요청/상태 버전→라우팅→생성→게시/폐기를 연결한다. log는 배정·오류·대체·중단 사건을 남기고 metric은 위 판별 성과·비용·지연을 집계한다. 최소 기록은 처치 배정, 버전·모델 설정, 시작 조건, 실제 적용/대체 상태, 분모가 되는 모든 기회, 종료/중단 이유, 설문/평가 라벨과 평가자, 전체 호출 사용량이다. 키·민감 원문은 기록하지 않는다.

Sites의 폐기 호출은 종료 JSON 밖 서버 로그에 남는 기존 제한이 있다. 비용 비교 전에 요청/시도 기록까지 모을 수 있는지 확인하거나 결과를 관측 가능한 범위의 하한으로 표시한다. 사건 로그만으로 전체 비용 절감을 단정하지 않는다. 현재 수집된 판의 완전성과 평가 집계 구현은 미확인이다.

## 2026-10-04 보완 수치로 비교하는 역할 수행 지표

사용자는 객관적인 수치 개선을 원하며, 멀린 암살 성공률 하락을 정체 은폐 개선의 예로 제시했다. 동시에 여러 원인의 혼합, 충신의 정보 획득을 위한 악 포함 팀 선택, 선·악 AI의 상반된 승리 목표 때문에 단일 팀 순도나 전체 승률 판정이 어렵다고 지적했다. 대기시간·오류율은 상대적으로 기준 설정이 쉽다고 판단했다. 이는 아래 지표 검토의 기준이며 제안한 개별 지표를 채택했다는 의미는 아니다.

수치화 가능성과 원인 해석 가능성은 구분한다. 자동 계산 지표는 규칙·정답 역할·시간으로 채점하고, 의미 평가 지표는 사전 라벨과 평가자에 의존한다. 전략에 유일한 정답이 없는 사례에서는 행동 자체를 단순 오답으로 만들지 않는다. 다음 모든 숫자 예시는 설명용이며 실측·확정 목표가 아니다.

### 멀린은 세 지표를 함께 보고 고정 공격자로 확인

대상 멀린이 AI인 시작 판 N, 선이 세 원정을 성공해 암살 단계에 도달한 판 R, 멀린 암살 적중 판 H를 센다. 암살 미완료·중단은 따로 보존하고 성공한 것으로 채점하지 않는다. 완전한 종료 기록에서는:

- 원정 단계 통과율 = R/N. 이 지표는 팀 전체의 성과이며 멀린 개인의 인과 효과로 바로 해석하지 않는다.
- 조건부 암살 회피율 = (R−H)/R. 사용자가 제시한 암살 성공률 H/R의 보완값이다.
- 최종 선 승리 도달률 = (R−H)/N. 암살 회피만 높이고 선의 원정 진행을 망치는 조건을 구별한다.

예: A에서 R/N=80%, H/R=90%이면 최종 선 승리는 8%. B에서 R/N=20%, H/R=60%이면 최종 선 승리는 역시 8%. 암살률만 보면 좋아졌지만 멀린의 전체 역할 수행 개선 근거는 없다. 이는 완전 종료·각 비율이 위 식을 따르는 가상 예다. 중단 자료가 있으면 정상 종료 승률과 전체 시작 판 도달률을 분리한다.

암살자가 달라지면 멀린의 은폐와 공격자의 추론 능력이 섞인다. 개인 멀린 후보를 평가할 때 다른 자리 정책, 특히 암살자의 모델·프롬프트·관찰 범위·설정을 고정한다. 별도로 고정된 평가 암살자에게 A/B의 공개 기록을 보여주고 실제 멀린 적중률을 채점한다. 여러 사전 고정 공격자를 사용할 때는 공격자별 수치도 보고한다. 이 평가는 지정 공격자에 대한 노출이지 사람에게 보편적으로 통하는 은폐 수준은 아니다.

일부 발언의 노출 효과를 분리하려면 동일 공개 상태에서 생성한 A/B 멀린 발언을 각각 붙여 같은 평가 암살자에게 식별하게 하는 짝지은 사례를 만들 수 있다. 역할 정답은 채점에만 제공한다. 발언자 자신이 멀린이라고 표시하거나 파일명·입력 메타데이터로 답을 새게 하지 않는다. 발언 전/후 실제 멀린 적중률 차이를 측정하되 상태·발언 길이·이름/좌석 구성·공격자 설정·반복을 고정한다. 암살자 판단은 원래 게임으로 되돌리지 않는다. 확률 출력의 상승폭도 참고 가능하지만 공격자 자기 보고 확률의 보정은 별도 검증 대상이다.

암살 단계에 도달한 판만 고르면 처치에 의해 구성 자체가 달라지는 선택 문제가 남는다. 도달률 동시 보고와 고정 상태 평가로 해석을 보완하되 원정 도달 판이 완전히 동일 모집단이 되었다고 주장하지 않는다. JEV는 발언 기회·다른 AI 발언도 바꾸는 시스템 처치이므로 그 실험의 암살률 차이는 멀린 개인 문장 능력만의 효과가 아니다.

### 충신은 행동의 정답 대신 추론의 정답을 먼저 측정

주 후보는 **AI 자체 판단의 Brier 점수**다. 충신에게 허용된 공개 상태와 시작 정보를 제공한 뒤 자신을 제외한 네 명 각각의 악 확률 p를 평가 전용 응답으로 받아 실제 악 여부 y와 비교한다. 악 포함 팀 선택 여부와 무관하게 평균 (p−y)²를 계산하며 낮을수록 좋다. 멀린·악처럼 이미 악을 아는 역할은 이 충신 지표에 합치지 않는다. 양 조건 모두 같은 네 명·같은 공개 체크포인트·같은 질문과 출력 형식을 쓴다. 판 안 체크포인트를 평균해 판당 점수 하나로 만든 뒤 판별 평균을 비교한다.

이때 `evilPosterior()`를 서버에서 계산한 점수는 제공 여부에 따라 바뀌지 않아 제공 효과를 채점할 수 없다. 반드시 두 조건의 **AI가 내린 판단**을 받아야 한다. 현재 운영 행동 응답에 이 확률 출력은 없어 별도 평가 경로가 필요하다. 평가 질문이 사고를 바꾸거나 정답을 다음 결정에 알려주는 일을 막기 위해 원본 상태를 복제한 오프라인 평가에서만 실행하고 결과를 게임 입력에 되돌리지 않는다. 이는 평가 질문 아래의 추론 품질이며 실제 행동 중 내적 신념을 직접 읽었다고 주장하지 않는다.

새 정보 활용 능력은 같은 사건 전·후의 Brier 차이 `정보 활용량 = Brier_이전 − Brier_이후`로 참고 비교한다. 동일한 공개 사건을 양쪽에 주며 원정 실패·투표 공개 등의 종류별로 분리한다. 예를 들어 실패 카드 한 장이 나온 본인 포함 2인 팀은 충신 관점에서 동행자가 악으로 확정되므로, 확정된 역할 관계에 대한 판단의 오류도 자동 채점할 수 있다. 성공 원정의 악 포함 가능성을 0으로 단정하는 실패와 구분한다. 모든 개별 사건이 반드시 Brier를 낮춰야 한다고 요구하지 않으며 사례 묶음의 평균·분포·악화 사례를 보고한다.

정답이 논리적으로 확정되는 사례에서는 **확정 정보 해석 정답률 = 필요한 역할 관계를 모두 올바르게 답한 사례/전체 해당 사례**를 별도로 센다. 이는 추론 응답의 정답률이고 ‘확정 악이 있는 팀을 제안했으니 틀렸다’는 행동 라벨이 아니다. 추론을 맞게 했어도 전략적으로 위험 팀을 선택할 수 있다.

정보 획득 전략의 선택 가치까지 평가하려면 같은 시작 상태에서 후보 행동 이후를 고정 상대 정책으로 반복 실행해 대상 진영의 최종 승리 확률을 비교해야 한다. 승패 가치 추정의 불확실성·모델 호출비용이 크므로 후속 검증으로 둔다. ‘새 정보가 생긴 양’ 또는 ‘확률 분포가 더 확신해진 양’만으로 전략적 이득을 인정하지 않는다. 잘못된 확신도 증가할 수 있고, 정보 획득이 원정 패배 비용보다 가치 있는지는 별개다.

### JEV는 발언자 선택과 답변 내용을 분리

| 수치 후보 | 계산 | 주의점 |
| --- | --- | --- |
| 발언자/WAIT 적합률 | 선택이 사전에 지정한 허용 후보 집합에 속한 사례 / 전체 사례 | 정답 후보 복수 허용. 한국어 사례의 사전 라벨 필요. 직접 지목 질문과 비지목/간접 질문은 별도 보고. 명시 답장은 코드 우선이라 전체에 섞으면 JEV 기여가 과장될 수 있음. |
| 필요한 응답 누락률 | 답이 필요하다고 지정한 기회에서 WAIT·실패·미게시로 유효 답이 없는 기회 / 전체 답변 필요 기회 | 답변 관찰 창은 응답 완료 또는 다음 사람 행동/단계 전환까지 등 사전 고정. 경쟁 요청으로 취소된 경우도 원인별 보존. |
| 불필요한 발언률 | 침묵이 적합하다고 지정한 기회에 발언을 게시한 기회 / 전체 침묵 적합 기회 | 무응답만 늘려 수치를 좋게 만들지 못하도록 위 누락률과 짝지음. |
| 질문 내용 충족률 | 사전 지정한 답변 요건을 만족한 기회 / 전체 답변 필요 기회 | 질문에 답해야 할 기회를 분모로 삼아 미응답을 숨기지 않음. 발언자 선택 성공과 Gemini 내용 성공을 별도로 기록. 사람/모델 라벨 평가에 의존하며 숫자라는 이유로 완전 객관성을 주장하지 않음. |

의미 라벨은 정책 결과를 보기 전에 작성하고 허용 이유를 남긴다. 일부 표본은 두 평가자가 독립 채점해 일치율과 불일치 사유를 보고한다. 평가자 모델을 사용한다면 모델·프롬프트 버전을 고정하고 사람 정답 표본과의 일치율을 확인한다. 모델 평가는 정답 보증이 아니다. 현재 이 평가 데이터/집계는 미구현이다.

### 운영 지표는 분모와 관측 구간을 고정

- 원시 모델 오류율 = 형식/값/연결 오류 시도 / 전체 실제 모델 호출 시도. 재시도 성공으로 최초 오류를 지우지 않는다. 정상 WAIT는 오류가 아니다.
- 최종 대체율 = 오류 때문에 기존 규칙·기본 행동으로 대체한 요청 / 전체 대상 요청. 원시 오류율과 구분한다.
- 응답 지연 p50/p95 = 동일 유형의 응답 기회 시작부터 유효 게시까지. 실패·누락 비율을 함께 보고하며 WAIT를 0ms 성공 답변으로 넣지 않는다. CHAT/PROPOSE/VOTE 등을 나눠 요청 구성 변화의 영향을 확인한다.
- 비용 = 배정 판당 모든 JEV+Gemini 호출 비용과 사전 정의한 응답 기회당 비용. 실패·재시도·폐기도 포함하며 판 종료율/유효 응답률을 함께 보고한다. 오류 응답에서 usage가 없는 경우 0비용으로 간주하지 않는다. 실제 과금 자료가 없으면 추정식·미측정 범위를 명시한다.

최근 별도 작업에서 운영 JEV 선택이 배포되고 Gemini/JEV 합성 연결 smoke가 실시된 사실을 작업일지에서 추가 확인했다. 이는 기존 설계 작성 당시 이후의 상태이며 본 지표에 대한 품질·승률 평가 결과는 아니다. 운영 모드 수동 선택 자료는 여전히 무작위 실험 결과와 구분한다.

### 첫 비교에 추천하는 구성과 판정

보조정보는 충신 추론 Brier와 확정 정보 정답률, JEV는 라우팅 적합률과 필요한 응답 누락률을 우선 직접 진단한다. 역할 수행 전체 검증에는 고정 상대의 멀린 원정 통과/암살 회피/최종 승리 도달률을 함께 사용한다. 이들이 서로 다른 목표를 측정하므로 하나의 총점으로 임의 합산하지 않는다. 상대를 고정한 대상 한 자리의 역할별 승률은 여전히 유효한 최종 성과 지표이며 일반적인 선·악 기준 승률을 알아야만 비교 가능한 것은 아니다.

보고 형식은 `A 분자/분모(비율), B 분자/분모(비율), 차이(%p 또는 점수), 95% 구간, 모델/버전/상대/사례 구성`으로 고정한다. 예를 들어 암살률 90%→60%라도 9/10→6/10과 90/100→60/100은 증거 강도가 다르다. 판·원본 상태·반복 세션 상관을 반영하고 지표/역할별 표본 수를 보고한다. 의미 있는 최소 개선폭과 보호 지표 허용 악화폭은 아직 미확정이며 파일럿과 사용자 판단으로 정한다. 기준이 정해지기 전에는 효과 추정과 한계를 보고할 수 있으나 최종 채택 성공으로 표현하지 않는다.

검토 상태: 정의·분모·정보 경계·자동/의미 채점 구분은 설계 완료. 실제 기준값·평가 라벨 품질·표본 분산·추론 출력 수집·집계 구현은 미확인/미구현. 평가 실행·개선 수치 측정은 미실시다.

### 수치 지표의 연구 참고

- AvalonBench §5.2는 원정 승리, 암살 승리, 암살 조건부 정확도, 충신의 역할 추론 정확도를 분리한다. 해당 게임의 5번째 제안 처리 등 규칙은 현재 구현과 달라 논문 수치를 합격선으로 옮기지 않는다. https://arxiv.org/html/2310.05036v3

AI 자체 Brier·동일 상태 발언 노출 검사·JEV 적합률을 현재 프로젝트에 적용하는 계약은 Codex 제안이며 위 논문의 실측 결과를 이 프로젝트 성과로 사용하지 않는다.

## 2026-10-06 보완 개선 순서와 JEV 레이블

권장 순서는 평가 기준선 확보 → 충신의 추론/행동 연결 개선 → JEV 라우팅 개선 → 멀린 은폐와 협력 평가 → 후보 조합 전체 검증이다. 개발·사례 준비는 함께 진행할 수 있지만 원인을 확인하는 평가 구간에서는 다른 구성요소 버전을 고정한다. 충신 단계가 끝난 뒤 JEV를 비교한 결과는 개선된 충신 아래에서의 JEV 효과이며, 최초 기준선과 단계별 상승폭을 독립적인 기여로 합산하지 않는다. 단계마다 채택 후보·비교 기준·평가 자료를 버전으로 보존한다. 여러 구성요소를 동시에 바꾸면 그 묶음의 효과만 주장하거나 사전 설계한 요인 실험으로 분리한다.

충신 단계에서는 프롬프트 변경과 입력 지표 추가를 한 번에 바꾸지 않는 안을 우선 제안한다. 동일 평가 상태에서 추론 Brier/확정 정보 정답률을 먼저 확인하고 선택적 후속 행동 평가를 연결한다. 추론 정답률만 좋아졌다고 팀 선택/전략 개선까지 완료로 보지 않는다. 자동으로 확정할 수 없는 행동의 정답을 임의 강제하지 않는다.

JEV의 의미적 선택 적합률에는 기준 레이블이 필요하지만 사용자가 모든 판을 직접 채점할 필요는 없다. 명시 replyTo 대상 보호·정보 경계·후보 형식은 자동 검사하며 현재 명시 답장은 코드가 우선하므로 이를 JEV 모델 품질 점수와 분리한다. 간접 질문·복수 응답 가능·이미 답한 질문·침묵 적합 같은 의미 사례는 사례당 공개 맥락/응답 필요 여부/허용 발언자 집합/WAIT 허용 여부/짧은 이유를 사람이 검토하는 안을 제안한다. 초기 유형별 사례를 Codex가 초안 작성하고 사용자는 애매한 기준과 표본을 검토할 수 있다. Codex/평가 모델 레이블은 가설이며 독립 정답으로 간주하지 않는다.

레이블 작성 때 JEV/기존 코드의 결과와 실제 비밀 역할은 숨기고 해당 시점의 공개 맥락만 보여준다. 결과를 본 뒤 답을 맞춰 바꾸지 않는다. 비밀 역할을 아는 사용자라면 종료 판 전부보다 역할표를 가린 사례 묶음을 검토하는 편이 적절하다. 기준이 바뀌면 레이블 버전을 변경하고 기존/신규 출력을 모두 같은 새 기준으로 재채점한다. 개발 사례와 보류 평가 사례를 분리하고 사람 검토 없는 자동 점수는 대리 평가로 표현한다. 평가 인터페이스 구현은 이번 범위에서 하지 않는다.

사용자는 멀린의 원정 통과 기여에 충신 호응도 필요하며 충신 프롬프트나 입력 보조정보 개선이 필요할 수 있다고 지적했다. 이를 설계 가설로 반영한다. 멀린 단독 평가에서는 충신·악·라우팅을 고정하고 멀린 후보만 변경한다. 협력 평가에서는 충신 기본/개선 × 멀린 기본/개선의 네 조합을 비교하되 JEV를 고정해 상호작용을 확인한다. 첫 단계부터 이 실험까지 한꺼번에 확증할 필요는 없으며 실제 표본·비용에 따라 후속 검증으로 둔다.

충신 협력은 멀린 의견에 무조건 찬성하는 비율로 채점하지 않는다. 충신은 멀린 정체를 모르고 악의 설득에도 노출되기 때문이다. 같은 공개 상황에서 타당한 근거를 포함한 제안과 근거 없는 제안을 구분하는지, 팀/찬반 선택과 후속 진영 성과가 어떻게 달라지는지 평가한다. 발언자 실제 역할을 기준으로 ‘멀린을 믿으면 정답’이라는 레이블을 주지 않는다. 전체 원정 통과율은 협력 결과이고 멀린 개인 공로와 구분한다.

이 순서는 Codex 권고이며 사용자는 순차/동시 진행 여부를 질문했을 뿐 아직 최종 선택하지 않았다. 새 프롬프트·입력·JEV 설정 변경, 실제 모델 평가, 개선 수치 측정은 이번 보완에서 미실시다.

## 2026-10-06 보완 JEV를 먼저 평가하는 진행 권고

사용자는 JEV→충신→멀린→동시 순서와 처음부터 동시 개선하는 대안을 제시했다. Codex는 JEV→충신→멀린→조합 검증을 권고한다. 현재 JEV는 발언자/WAIT 선택이라는 좁은 범위여서 의미 레이블 기준을 마련한 뒤 선택 적합률·필요 응답 누락률·불필요 발언률·지연·비용으로 먼저 비교하기 적절하다. 평가 동안 플레이어 프롬프트·보조정보·팀 선택 정책을 고정한다. JEV에서 문제가 발견돼도 플레이어 프롬프트까지 함께 고쳐 원인을 섞지 않는다.

그다음 JEV 후보 버전을 고정하고 충신의 추론과 행동 연결을 비교하며, 충신 후보까지 고정한 뒤 멀린의 암살 회피·원정 통과·최종 선 성과를 평가한다. 마지막 동시는 새 변경을 한꺼번에 만드는 단계가 아니라 이미 만든 후보 조합의 상호작용을 검증하는 단계다. 충신×멀린 네 조합에서는 JEV를 고정하고, 최종 후보 묶음과 최초 기준선의 전체 성과도 비교한다. JEV까지 포함한 개별 상호작용을 모두 분리하려면 세 요인의 8조합이 필요하므로 표본·비용 확인 후 별도 범위로 정한다.

처음부터 동시 개선도 가능하나 여러 요소를 함께 바꾼 결과만 비교하면 후보 묶음의 효과만 알 수 있다. 사용자 최종 선택은 아직 미확정이며 이번 보완은 권고 기록이다. 실제 평가·코드 변경은 하지 않는다.

## 2026-10-06 사용자 판단 보완 JEV 도입을 전제로 역할 AI 개선

사용자는 기존 코드 중심 진행을 JEV로 바꾸면 더 자유로운 대화와 진행이 가능하다고 보아 JEV를 도입한 뒤 충신·멀린을 개선하려 했다고 밝혔다. 따라서 JEV 채택 여부를 발표 전 첫 품질 비교의 의사결정으로 잡았던 Codex 권고는 사용자 목표와 맞지 않았다. JEV 도입은 사용자 방향으로 기록하고 자유로운 대화·진행 효과는 기대/가설로 구분하며 실측 개선으로 쓰지 않는다.

수정 권고는 JEV 기반 진행의 기준 버전을 먼저 고정하고, 10월 8일 발표 전 충신 추론 개선을 주 평가 범위로 삼는 것이다. 동일 공개 상태·동일 역할 정보에서 기존 충신과 후보 충신을 비교하며 확정 정보 해석 정답률과 평가 전용 AI 확률의 Brier를 측정한다. 프롬프트 변경과 보조정보 추가는 원인을 분리하거나 묶음 효과로 명시한다. 현재 평가 전용 출력·사례·집계는 준비가 필요하고 실제 개선 여부는 미확인이다. 멀린은 고정 공격자 아래 발언 노출/암살 식별의 소규모 탐색 평가를 선택적으로 준비하며 전체 원정·암살 회피·선 승률 확증은 후속 범위로 둔다. 남은 시간·실행 비용에 따라 충신 한 영역의 재현 가능한 결과를 우선한다.

현재 구현된 JEV는 발언자/WAIT 선택이고 단계 진행 제어·제한된 AI 연쇄 토론까지 포함하는 확장과는 다르다. 이번 사용자 발언만으로 그 확장 범위·종료/사람 개입 조건·자동 호출 상한까지 확정하지 않는다. 진행 구조가 바뀌면 역할 평가의 기준 버전도 고정하거나 다시 평가해야 한다. JEV 규칙·정보 경계·오류 대체의 검증은 도입 전제에서도 유지하지만 기존 코드 대비 통계적 우위를 채택의 선행 조건으로 삼지 않는다.

## 2026-10-07 최신 구조에서 사용자 역할 추측과 비용 비교 검토

사용자는 다른 세션에서 게임이 바뀌었다고 알리고, 입력 지표 제공/미제공의 비교, 종료 전 사용자의 역할 맞추기 정답률, JEV 혼합/Gemini 구성 비용을 평가하려 한다고 밝혔다. 역할 추측은 프롬프트 등 개선의 효과를 보기 위해 추가했고 역할별 승률을 역할 정답률에 통합할지 질문했다. 높은/낮은 정답률 중 어느 방향을 개선으로 볼지는 이 항목 작성 시 미확정이다.

### 확인한 최신 구현

- `docs/specs/022-jev-actions-and-role-guess.md`, `site/lib/action-selection.mjs`: JEV가 개인 관점의 팀/투표/악 카드/암살 행동을 선택한다. Gemini는 V3 대화와 자기보고 생각을 생성하고, 엔진은 합법성/상태 전이를 검증한다. 이전의 발언자/WAIT만 JEV라는 설명은 현재 범위에 맞지 않는다.
- `docs/specs/026-natural-discussion-routing.md`: 발언 필요성 TALK/WAIT와 발언자를 분리했다. 최신 운영은 수동 단계 진행이며 JEV가 전부 자동 전환하는 것으로 설명하지 않는다.
- `site/lib/comparison.mjs`: Gemini 단독 프리셋은 기존 코드 발언자+Gemini 행동, 혼합은 JEV 발언 제어+JEV 행동이다. 대화는 둘 다 Gemini다. 이는 시스템 묶음 비교이며 Gemini가 발언 제어까지 전부 대신하는 대조군이 아니다.
- 로컬과 보존된 운영 소스의 `ai.mjs`/`action-selection.mjs`는 `roleClues`와 `evilBelief`를 전달한다. 새 판 API에는 이 제공 여부 스위치나 버전 필드가 없다. 따라서 현재 확인한 구현만으로 지표 ON/OFF 실험이 실행됐다고 볼 수 없다. 실제 운영 DB의 로그 내용은 이번에 읽지 않았다.
- `role-guess.mjs`: 세 번째 성공 또는 실패 원정 결과 뒤, 암살·정체 공개 전 AI4명의 세부 역할을 한 번 제출한다. 점수/정체는 종료 전 응답·모델에서 숨긴다. 역할 수 제약·자기 역할을 사용하고 사용자 역할/시작 정보/원정 수/AI 설정도 저장한다. 5회 부결·재시작에는 이 추측이 없다.
- `usage.mjs`/`game-log.mjs`: 사용량은 호출별 별도 DB 기록으로 저장하고 종료 JSON의 modelUsage에 포함한다. Gemini와 JEV 모두 기존 가격 버전의 추정 비용을 계산한다. 가격표의 현재 정확성과 실제 청구액은 이번에 확인하지 않았다. 비용 누락 호출은 unknownCalls로 표시한다.
- 비교기는 판 ID 중복·미완료·재시작·연습·과거/사용자 모드를 구분하며 조건별 요약과 전체 요약을 만든다. 완료 판 비용 평균은 비용이 전부 알려진 판만 포함한다. 오류/누락/중단이 조건마다 다르면 제외된 판도 별도 보고해야 한다.

### 지표를 합치지 않는 이유

로그에 승률·추측·비용을 함께 기록하는 것은 적절하다. 단일 점수로 합치는 것은 권하지 않는다. 승패는 진영 목표 달성이고 사용자 역할 정답률은 사람의 역할 식별 결과다. 사람의 악 식별 정답률이 높아지면 사람에게 유리한 정보가 늘었을 수 있지만 악 AI의 은폐는 나빠졌을 수 있다. 인간의 멀린 적중은 자신의 역할에 따라 시작 지식·선 편의 추론·악 편의 은폐 실패를 다르게 반영한다. 충신도 일부러 악처럼 보여 멀린을 보호할 수 있어 실제 충신의 식별률 상승을 무조건 성능 개선으로 보지 않는다.

역할별 승률과 역할별 사람 식별률은 별도 열로 나란히 보고 상충 관계를 해석한다. 원칙적으로 AI의 추론 향상 주장에는 AI 자체의 평가용 확률/역할 판단을 채점해야 하며 사람 역할 추측만으로 대체할 수 없다. 정체 은폐 개선 주장에는 고정 관찰자/공격자·동일 초기 조건 아래의 식별률과 역할 목표 성과를 함께 본다. 서로 다른 목표에 임의 가중치를 주어 합산하면 채택 이유가 감춰질 수 있다.

### 역할 추측의 측정 계약 보완 제안

- 기존 네 명 exact role 정답률은 계속 원자료로 보존한다. 시작 정보에 따라 난이도가 달라 인간의 시작 역할별로 나눠 보고 같은 사용자의 반복 학습·피로와 플레이 순서를 기록한다. 한 사용자 결과는 그 사용자 범위다.
- `exact role`과 `선/악 진영` 정답률을 분리한다. 악임을 맞혔지만 암살자/하수인을 바꿨다면 진영 정답, 세부 역할 오답이다. 공개 대화에서 두 세부 역할을 구별할 단서가 적을 수도 있다.
- 시작부터 아는 정답은 과제별로 구분해 제외한 미지 항목 정답률을 추가한다. 멀린이 아는 악의 진영과 악이 아는 동료 정보를 그대로 추론 성공으로 세지 않는다. 진영을 안다고 세부 역할까지 아는 것은 아니므로 네 역할 정답률에서 해당 플레이어 전체를 일괄 제외하지 않는다. 평가 분모0이면 해당 없음.
- 사람을 충신으로 제한한 자료는 주 비교 후보다. 그렇지 않으면 충신·멀린·악의 자료를 합쳐 단일 평균의 변화만 보고 채택하지 않는다. 현재4개 답은 판/사람의 공동 판단이며 4개의 독립 실험 표본이 아니다. 판별 점수와 표본수/불확실성을 보고한다.
- 멀린 실제 플레이어 적중률, 실제 악의 진영 식별률, 세부 역할별 식별률을 별도로 보고한다. 특히 멀린 은폐는 정답률 하락이 유리할 수 있지만 역할 목표 성과를 함께 봐야 한다. 추측 레이블의 방향은 사용자 목적 확인 전 확정하지 않는다.
- 현재 추측 시점은 원정 승패가 이미 확정된 직후다. 어느 진영이 원정에서 이겼는지 아는 정보가 추측에 반영되며, 암살 이전 검사는 암살 행동의 효과를 관찰하지 못한다. 같은 시점의 사후 경험 지표로는 쓸 수 있지만 초기/중간 추론과 같지 않다. 세 성공/세 실패, 3~5원정, 5회 부결·중단·미제출의 건수도 보고한다. 이 사후 조건으로 나눠 본 결과를 무작위 배정의 전체 인과 효과로 대체하지 않는다.
- 역할 분포를 강제하는 현재 UI는 답의 독립성이 없다. 무작위 기준을 쓸 때도 자기 역할·시작 정보·분포 제약을 지키는 기준선이 필요하며 단순한 25%를 보편 기준으로 적용하지 않는다.

### 비용과 역할 성과 비교 설계

발표 전에는 별도 비교로 작게 나누는 안을 권한다.

1. 보조정보 효과: JEV/Gemini 구성·프롬프트를 고정하고 특정 입력만 ON/OFF로 바꾼다. 자기 역할·합법 시작 정보·공개 기록은 유지한다. Gemini 대화 입력과 JEV 개인 행동 입력 등 모든 간접 전달 경로를 점검하고 제공 종류/버전·대상 역할·판 배정을 기록한다. 어디까지 제거할지에 따라 처치 정의가 달라진다.
2. 프롬프트 효과: 보조정보와 모델 구성을 고정하고 기존/후보 프롬프트만 바꾼다. 승률과 사람 식별률을 둘 다 저장하되 목적을 따로 해석한다. 프롬프트와 보조정보를 묶어 바꾸면 묶음 효과만 주장한다.
3. 비용 비교: 같은 보조정보·프롬프트·규칙에서 두 시스템 구성을 비교한다. 판당 비용, 사용한 호출 수, 행동 종류별 호출당 비용/토큰과 응답 성공·중단·오류를 함께 보고한다. 더 빨리 패배하거나 대화가 줄어 비용이 낮아진 상황과 같은 일을 더 싸게 한 상황을 구분한다. 실제 Gemini/JEV 가격 버전과 usage 누락 범위를 명시한다.

같은 상황의 비용을 더 직접 비교하려면 공개/개인 허용 관찰을 복제해 양쪽 판단을 별도로 실행할 수 있다. 실제 적용하는 선택은 하나만이고 다른 것은 shadow 측정이다. 같은 판의 양쪽 선택을 기록해도 양쪽 승패·후속 인간 추측 결과를 동시에 얻을 수는 없다. 현재 프리셋 로그는 적용한 모드의 호출을 기록하며 동일 모든 개인 행동에서 두 모델을 모두 실행하는 실험은 아니다. shadow가 있더라도 적용하지 않은 정책의 최종 승률을 재구성했다고 표현하지 않는다. 평가 shadow 비용과 실제 서비스 비용도 분리한다.

두/세 요소를 동시에 확증할 필요가 있다면 각각 두 수준인 보조정보×모델 구성은4조합, 여기에 프롬프트까지 포함하면8조합이다. 현재처럼 사용자가 선택한 구성별 판은 탐색 비교 자료이며 무작위 배정 자료와 다르다. 소수 판으로 조합을 늘리는 대신 목표 하나를 정하고 기준 버전을 고정하는 것이 발표 전 권고다. 같은 로그에 여러 지표를 기록하는 것은 문제없으나 독립 처치 배정/비교 조건이 없으면 원인 분리는 안 된다.

### 결론과 미확정 사항

현 구현은 조건·사용량·역할 추측을 함께 보존하는 탐색 관측 기반으로 적절하다. 보조정보 ON/OFF와 프롬프트의 인과 효과, 역할별 전략 우위 확증에는 추가 조건 고정·배정·채점 계약이 필요하다. 승률과 사람 역할 정답률은 통합 점수가 아니라 별도 결과로 유지한다. 제거할 지표, 적용 대상, 사람 추측의 원하는 개선 방향, 비용/반복/표본은 미확정이다. 실제 DB 로그·성과·비용 절감·모델 품질은 이번 검토에서 측정하지 않았다. 코드 수정·테스트·모델 호출·배포는 하지 않았다.

## 2026-10-07 사용자 목적 확정과 측정 구현

사용자는 인간이 역할을 구분하지 못하는 것을 AI의 역할 수행으로 보기 위해 추측을 추가했다고 명시했다. 진영/세부 역할 점수 분리, 사용자 시작 역할별 분리, 5회 부결판의 추측을 요청했다. 실험 순서는 모델 변경 비교→역할 확률 입력 유무에 따른 행동 비교→프롬프트 개선의 승률/사용자 식별 비교를 제안했다. 앞 항목의 방향 미확정은 이 발언으로 해소됐으며 아래 순서는 Codex의 권고다. 전체적인 전략 성공까지 낮은 식별률 하나로 증명되지는 않는다.

### 데이터 이해와 측정 계약

확인한 경로는 `site/lib/role-guess.mjs`(1판의 추측4개), `game-log.mjs`(판 ID별 종료 상태/사건/호출), `comparison.mjs`(중복 제거 후 판별 비교)와 `scripts/compare-models.mjs`(JSON 집계 CLI)다. 실제 운영 표본/기간/기준 수치는 아직 미확인이다. 각 AI 답은 같은 판의 연결된 판단이므로 독립 표본4개로 세지 않는다. 모델 사용량은 판에 여러 호출이 대응하며 비교기는 판별 비용을 먼저 합산한다.

| 지표 | 분자 / 분모 | 용도와 방향 | 적합성 |
|---|---|---|---|
| 세부 역할 정답률 `guessAccuracy` | 정확한 역할 추측 수 / 제출 AI 수 | 사람 식별 난이도; 낮아지면 은폐 가설 지지 | 조건부 적합: 시작 지식, 사용자 숙련, 공개 단서 부족 영향 |
| 진영 정답률 `factionGuessAccuracy` | GOOD/EVIL 정답 수 / 진영 채점 가능 AI 수 | 선악 구분 난이도; 세부 역할 혼동과 분리 | 조건부 적합: 멀린·악 사용자의 시작 지식 포함 |
| 선 승률 `goodWinRate` | GOOD 승리 판 / 유효 완료 판 | 은폐 변화와 전략 성과를 함께 확인 | 조건부 적합: 참가자/구성 고정 필요; 모든 AI에 공통 최대화 목표 아님 |
| 판당 비용 `meanCostUsd` | 비용이 모두 알려진 판의 합계 / 해당 판수 | 구성별 비용 비교 | 조건부 적합: 추정 단가, 호출량/원정 길이 차이, 중단 비용 별도 |

추측은 종료 직전 3성공/3실패/5회 부결에서 한 번 제출하고 종료 뒤 공개한다. 통계는 같은 실험 버전의 실제 모델 완료 판으로 제한하며 연습·재시작·미완료·구성 미확인 판은 제외 수를 보존한다. 추측 미제출/진영 재계산 불가를 0점으로 취급하지 않는다. 집계는 판 ID 중복 제거, 제출 답의 합계 정답률과 제출 판수를 제공한다. 사용자 자신은 제외한다. 시작 역할별 `byHumanRole`과 정확한 조건별 `byConditions`를 먼저 보며 종료 경로별 `byCheckpoint`는 설명용이다. 목표/유의한 개선 폭은 실제 기준 자료가 없어 정하지 않았다. 시작부터 아는 항목을 제외하는 추가 지표는 아직 구현하지 않았다.

### 권고 실험 순서

1. **모델/시스템 구성 비교**: Gemini 단독 vs JEV+Gemini. 프롬프트·확률 입력·게임 규칙·가격 버전을 고정한다. 판당 비용/호출량/오류·대체율을 중심으로 보고 승률과 식별률도 기록한다. 두 프리셋은 발언 제어와 행동 제공자가 함께 바뀌므로 결과는 구성의 효과로 표현한다. 순수한 행동 모델 효과를 원하면 라우팅을 같은 것으로 고정해야 한다.
2. **역할 확률 입력 ON/OFF**: 채택/기준 모델 구성을 고정하고 확률 지표만 바꾼다. 자신의 역할·허용 시작 지식·공개 기록은 유지한다. 동일한 관찰 상태에서 팀·투표·카드·암살의 선택 변화율을 비교하는 고정 사례 평가와 실제 판 결과를 구분한다. 변화율은 영향 유무이며 좋은 방향의 증거는 아니다. 현재 ON/OFF 스위치는 아직 없으므로 다음 구현이 필요하다. Gemini/JEV 두 입력 경로와 생각/기억의 간접 전달까지 범위를 정한다.
3. **프롬프트 기존/개선 비교**: 모델/입력 설정을 고정하고 프롬프트만 바꾼다. 승률과 사용자 식별률을 별도 열로 보고, 식별률 하락과 승률 악화를 함께 관찰하면 전략 실패 가능성을 점검한다. 같은 사용자/시작 역할 안에서 양 조건을 비슷한 횟수로 배정하고 실행 순서를 무작위화해 학습/피로와 변경 효과의 혼동을 줄인다. 단계가 바뀔 때는 이전 단계의 옛 로그 전체를 그대로 새 대조군으로 쓰지 말고 고정된 기준 구성을 다시 함께 실행한다.

한 판 안에 여러 결과 지표를 함께 저장해도 된다. 개발을 병행하더라도 평가 판에서는 변경 축 하나와 다른 버전 고정을 지킨다. 위 순서는 짧은 일정에서 원인을 설명하기 위한 제안이며 상호작용까지 검증하는 설계는 아니다. 표본이 적으면 탐색 결과와 판수로 발표하고 확정 개선으로 주장하지 않는다. 확증 분석의 오차/신뢰구간은 판 단위로 계산해야 한다. 통제 가능한 차이를 묶고 순서를 무작위화하는 근거: [NIST randomized block designs](https://www.itl.nist.gov/div898/handbook/pri/section3/pri332.htm).

## 2026-10-07 주 비교 축 변경: Gemini 모델 비용과 역할 수행

사용자는 배포판에서 실험하므로 변경을 배포하도록 요청했고, JEV 혼합의 비용·품질이 더 좋을 것이라는 예상 때문에 Gemini 3.5 Flash-Lite와 상위 Gemini의 비용/역할 수행 비교로 첫 단계를 바꾸려 했다. 우위는 사용자 가설이고 실제 측정 결과는 아직 없다. 비교 후보 3.5 Flash는 Codex가 동일한 세대의 상위 비용 모델로 선택했다.

새 순서는 **JEV 구성을 고정한 Lite/Flash 모델 비교 → 확률 입력 ON/OFF → 프롬프트 개선**이다. 첫 실험은 Gemini 대화·인간 발언 분류 모델을 함께 바꾸고 JEV 발언/개인 행동 선택, 프롬프트, 입력 확률, 원정 규칙, 출력 설정을 고정한다. JEV가 행동을 계속 선택하므로 Gemini 자체의 독립 행동 능력에 대한 비교와는 구분한다. 게임 종료 로그의 `modelComparisonVersion=gemini-tier-v1`로 시작 역할과 다른 조건을 맞춘 새 판만 비교한다. 같은 판 네 답을 독립4표본으로 보지 않는다.

비용은 두 모델의 각각 다른 단가와 실제 응답/추론/캐시 토큰을 사용해 합산한다. 공식 Global Standard 입력/출력/캐시 USD/백만 토큰은 Lite .30/2.50/.03, Flash 1.50/9.00/.15다(2026-10-07 확인, [Google 가격표](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing)). 같은 토큰 수의 상대 단가는 실제 판 비용 비율을 보장하지 않는다. 로그 수집에도 사용량 변경 revision을 추가해 늦은 비용 확정을 놓치지 않게 했다.

판당 비용 증가분과 진영/세부 식별률 변화(퍼센트포인트), 시작 역할별 승률, 오류/대체와 호출 수를 별도 열로 비교한다. 식별률 하락과 승률 악화가 동시에 나타나면 무조건 은폐 개선으로 채택하지 않는다. 실제 표본을 보기 전 개선 수치/가중 총점/채택 임계값은 만들지 않는다. 세부 구현/배포 및 검증은 `docs/specs/027-gemini-tier-comparison.md`와 작업일지에 연결한다.
