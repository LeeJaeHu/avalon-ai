# 아발론 임무 카드 선택 소규모 탐색 — 2026-09-29

상태: 합성 상황 단발 실험. 실제 게임·사람 플레이·전략 승률 평가는 아니다.

## 목적과 조건

악 AI가 매번 실패 카드를 내지 않고 점수와 노출 위험을 구별하는지, 악 AI 두 명이 같은 원정팀일 때 선택을 맞출 수 있는지 살폈다. 로컬 `.env`에 이미 설정된 API 키를 사용했으며 키와 응답 원문 전체는 저장하지 않았다. 현재 마피아 코드와 같은 모델 `gemini-3.5-flash-lite`, JSON 응답 모드, `temperature: 0.8`, `maxOutputTokens: 300`으로 호출했다. 합성 상황 4개와 같은 팀 악 2명의 독립 선택 2쌍, 총 **8회 호출**이다. 각 입력은 한 번씩만 실행했다. 프롬프트는 기존 아발론 Spec의 간단한 악 역할·임무 카드 지침을 축약한 탐색용 문장이며, 배포된 마피아 프롬프트나 구현된 아발론 에이전트의 결과가 아니다.

## 관찰한 출력

| 상황 | 악 AI 출력 | 판단할 수 있는 범위 |
| --- | --- | --- |
| 첫 임무, 악 두 명이 2명 팀에 포함 | `SUCCESS` | 두 실패 카드의 노출 위험을 언급했다. 상대도 성공할지는 알 수 없다. |
| 다섯째 임무, 선 2·악 2, 자신만 악인 팀 | `FAIL` | 실패 1장으로 즉시 악 승리인 상황을 구별했다. |
| 셋째 임무, 선 2·악 0, 자신만 악인 팀 | `FAIL` | 선의 세 번째 성공을 막는 선택을 했다. |
| 둘째 임무, 악 두 명이 3명 팀에 포함 | `FAIL` | 다른 악의 선택을 보지 못하므로 동시 실패 위험이 남는다. |
| 같은 둘째 임무: 암살자·하수인 독립 호출 | 각각 `FAIL`, `FAIL` | 이 한 쌍에서는 실패 카드 2장이 나왔다. |
| 같은 둘째 임무: 짝수 임무에는 ID가 앞선 악이 실패 담당이라는 공통 비공개 원칙 제공 | 암살자 `FAIL`, 하수인 `SUCCESS` | 이 한 쌍에서는 실패 카드 1장이 나왔다. |

앞의 네 호출은 입력 토큰 합계 743개, 출력 토큰 합계 217개이며 각각 916~1,266ms(로컬 호출 시작부터 응답 파싱까지)였다. 뒤의 네 호출은 입력 666개, 출력 39개였다. 전체 8회의 입력·출력 합계는 각각 **1,409개·256개**다. 출처는 실행 시 터미널에 출력한 `usageMetadata`와 호출별 선택값이다. 모델 응답이 모두 파싱됐고 HTTP 오류는 없었다.

## 해석과 다음 검사

이 모델은 네 단발 상황에서 즉시 승리와 초반 노출 위험을 구별했다. **티 나지 않게 이긴다거나 안정적으로 전략을 수행한다는 결론은 낼 수 없다.** 특히 공동 원칙이 없을 때 두 악의 동시 실패를 한 쌍에서 관찰했다. 이는 모델 지능만의 문제가 아니라, 비공개 동시 행동을 하는 두 에이전트가 서로의 선택을 볼 수 없는 구조적 문제다. 공동 원칙도 한 쌍만 시험했고, 사람 악 플레이어가 팀에 있는 경우와 여러 임무에 걸친 균형은 미확인이다.

후속 구현에서는 같은 역할·점수·팀 이력의 입력을 여러 번 반복하고, 두 AI의 합성 결과와 실제 한 판 흐름을 함께 측정한다. 평가 항목은 즉시 승리 기회 누락, 실패 카드 2장 노출, 모두 성공해 놓친 실패 기회, 금지된 정보 사용, 완주율, 호출·토큰·지연이다. 공동 원칙을 쓸 경우 사람 악 플레이어가 선택권을 유지하면서 어떤 정보를 받는지도 먼저 정한다.
